## 一、今日算法题：访问所有节点的最短路径（LC 847）

### 题目

给出一张无向连通图 `graph`，`graph[i]` 是与节点 `i` 相邻的节点列表。返回**访问所有节点**所需的最短路径长度。可以从任意节点开始、在任意节点结束，节点可以重复访问。

```
输入: graph = [[1,2,3],[0],[0],[0]]
输出: 4
解释: 一个最短路径是 [1,0,2,0,3]，长度 4。
```

**约束**：`n == graph.length`，`1 <= n <= 12`，无自环，无重边，图连通。

### 为什么今天选这道题（主题同构）

Day 131 防守量了「可达集」，Day 129 攻击找了「最短路径」，今天把两者焊在一起——**覆盖率引导模糊测试（coverage-guided fuzzing）的状态搜索骨架**：

| 算法概念 | 红队 / 模糊测试对应 |
|---|---|
| 节点 | 程序状态 / 模型响应类别 |
| `mask` = 已访问集合 | **coverage bitmap**：哪些边 / 分支已经触发过 |
| 状态 = `(node, mask)` | fuzzer 的种子 = `(当前输入, 已覆盖路径集合)` |
| 访问所有节点 | coverage 最大化 = 探索完备 |
| 最短路径长度 | **最小变异代价达到目标 coverage** |
| `n ≤ 12 → n·2ⁿ` 状态 | coverage 空间爆炸的工程现实——bitmask 是压缩表达 |

AFL / LibFuzzer 的全部本质：维护一张"哪些状态见过"的 bitmap，**任何带来新 coverage 的输入都进种子队列**——和本题 BFS 里"mask 出现新 1 位就入队新状态"一模一样。红队自动化平台就是把这个原理搬到 LLM 上：变异 prompt = 走边，新 refusal 类别 / 新内部状态 = 新节点入队。

### 思路：状态 = `(节点, mask)`，分层 BFS

```python
from typing import List
from collections import deque

class Solution:
    def shortestPathLength(self, graph: List[List[int]]) -> int:
        n = len(graph)
        if n == 1:
            return 0
        FULL = (1 << n) - 1

        # 起点任选 → 所有 (i, 1<<i) 作为第 0 层同时入队
        queue = deque((i, 1 << i) for i in range(n))
        seen = set(queue)          # 入队即标记，老三样纪律
        steps = 0

        while queue:
            for _ in range(len(queue)):        # 一次处理一整层
                node, mask = queue.popleft()
                for nei in graph[node]:
                    nm = mask | (1 << nei)     # 访问是累积的：用 |，不是 ^
                    if nm == FULL:
                        return steps + 1
                    if (nei, nm) not in seen:
                        seen.add((nei, nm))
                        queue.append((nei, nm))
            steps += 1
        return -1   # 题目保证连通，到不了这
```

**复杂度**：状态总数 = 节点数 × mask 数 = `n · 2ⁿ`，每个状态扩展 `deg` 条边 → **O(n² · 2ⁿ)** 时间，O(n · 2ⁿ) 空间。n=12 时约 4.9 万个状态，毫无压力。

**易错点**：
1. **起点任选** → 所有节点作为初始状态**同层**入队（0 步时已经访问自己）。"从每个起点分别 BFS 取 min" 是 n 倍的纯浪费。
2. **入队即标记**——`(nei, nm)` 在入队时进 `seen`，同一状态被多条路径到达只处理一次。
3. mask 合并用按位或 `|`：访问是单调累积的，用异或 `^` 会把已访问位打掉，直接 WA。
4. 判 `FULL` 的时机放在**扩展邻居时**而不是出队时——省一层队列操作。

### 正确性为什么显然

分层 BFS 的标准不变量：第 k 层恰好包含"路径长度 = k 可达"的全部状态。第一次扩展到 `FULL` 时返回 `steps + 1`，即首次到达全覆盖的路径长度——BFS 按层扩张保证最先到达的一定最短。

### 连环问（面试官的十八般武艺）

**Q1：n = 50 怎么办？状态爆炸。**
诚实回答 + 给工程出路：
- `n·2ⁿ` 指数爆炸，50 就是 `50·2⁵⁰`，精确 BFS 必死；
- 退而求其次：**把"全覆盖"改成"coverage 最大化"**——这正是 fuzzing 的现实！AFL 用 64KB bitmap 哈希桶做近似（允许碰撞 = 允许漏报），**拿精确性换工程可用性**；
- 或上启发式：A*（h = 未访问节点数，可采纳）、beam search（每层只保留 top-k 状态 = fuzzing 的**能量调度 energy schedule**）；
- 面试金句："很多算法题以为自己是精确覆盖问题，工程里它只需要是个够好的探索策略——这是 coverage-guided 对 exhaustive 的根本替代。"

**Q2：和 TSP / 哈密顿路径什么关系？**
哈密顿路径要求每个节点**恰好**访问一次（NP-complete），本题允许重复访问——这个松弛把问题拉回了"状态数指数、但 n 小时可精确解"的区间。工程话术："很多真实问题以为自己是 TSP，其实是本题这种'允许重访的 coverage 问题'——**这个松弛决定了可解性**。"

**Q3：怎么还原具体路径？**
parent 哈希表记录 `(nei, nm) ← (node, mask)`，找到 `FULL` 后沿指针回溯。fuzzer 语境里这叫**变异谱系（seed genealogy）**：每个高危输入都能回溯它的变异祖先链，归因时知道它是从哪个种子、经过哪几步变异来的。

**Q4：能双向 BFS 吗？**
mask 维**不可逆**——"还剩哪些没访问"不是对称状态，反向搜索没有自然的起点定义。重要的工程直觉：**状态含历史（mask / visited set）的搜索难以双向化**。红队侧同理：从攻击目标反推（goal-backward）只在状态可逆时成立，对抗攻击通常只能前向搜索 + 目标判定（这正是 GCG 只能贪心爬、不能倒着走的原因）。

**Q5：并行化怎么做？**
- 第一层 n 个初始状态天然独立（sharding by start node）；
- 或按 mask 分片：不同 worker 负责不同的位域子空间，定期 merge 各自的"已见状态"表（和 Day 104 Gossip 的反熵同步异曲同工）；
- fuzzer 对应物：AFL 多核 forkserver + corpus 周期性同步 coverage bitmap。

**Q6：边带权重（变异代价不同）呢？**
BFS → Dijkstra（状态图边权非负）。红队版：不同变异算子代价不同——字符替换便宜、语义改写贵、GCG 一轮前向要 GPU 时间更贵。**期望成本最低的攻击路径 = 状态图上的 Dijkstra**（Day 129 单词接龙带权版的同款 callback）。

### 工程映射一句话

> **本题 = coverage-guided fuzzing 的状态搜索骨架：种子 = (输入, coverage mask)、新 coverage = 新状态入队、最短路径 = 最小变异成本。AFL 的工程智慧——bitmap 压缩、能量调度、种子去重——全是这张状态图上的剪枝与近似。红队自动化平台就是把这个骨架架在 LLM 上。**

## 二、面试技巧：红队自动化平台设计

### 总纲：从"手测 prompt"到工业化攻击流水线

Day 129 给了攻击面地图、Day 130 给了检测器经济学、Day 131 给了沙箱施工。今天回答最后一个问题：**这些攻击怎么被规模化地生产出来**。手工试几句 prompt 不是红队，是抽奖。工业级红队 = **模糊测试方法论在 LLM 上的整体迁移**——面试官听到"我们把 AFL 的思路搬到 LLM 红队"，这一题就赢了一半。

### 1. 红队流水线五段（平台架构图，背下来）

```
① 变异生成        ② 沙箱执行        ③ 判定分级        ④ 归因分析        ⑤ 回流增强
 Mutation          Execution         Judge             Triage           Feedback
 (语料库+算子)     (Day 131 沙箱)    (拒绝≠失败)       (最小化+聚类)    (回归集+训练)
```

**① 变异生成（Mutation Engine）**
- **语料库三层**：已知越狱样本（DAN / JailbreakChat 公开语料）+ 对抗样本（GCG/AutoDAN 产物）+ **正常任务样本**（对照组，防 over-refusal 的假安全——Day 128 双指标要求）；
- **变异算子四级**（按代价从便宜到贵排）：
  - **字符级**：leet 替换、零宽字符、同形异义 Unicode（正是 Day 130 归一化层的对抗面）；
  - **词级**：同义词替换、语序打乱、多语言混排（低资源语言越狱是公开薄弱点）；
  - **语义级**：Crescendo 多轮渐进——每次只推进一小步，单轮都在安全线内，多轮累积破防；
  - **梯度级**：**GCG**——对目标 loss 做贪心坐标下降（今天的题在连续空间的版本，下面单列一节）；
- **关键工程决策：覆盖引导**——用"是否触发新 refusal 类别 / 新工具调用路径"做 bitmap 近似，优先变异 coverage 高的种子（= 今天的算法题）。

**② 沙箱执行（Execution）**
- Day 131 的 L4 施工直接复用：攻击样本要在**无网络、无凭证、只读**沙箱里跑——红队自己也绝不能成为 ambient authority 的污染源（让攻击样本摸到真凭证 = 帮它完成目标）；
- 批量 + 并行：microVM 池，每 episode 重置（环境可重置性 = Day 131 veRL 连接的同款要求）；
- 记录**完整轨迹**（trajectory），不是只记最终回复——归因分析要用。

**③ 判定分级（Judge）——最容易踩坑的一关**
- **拒绝 ≠ 攻击成功**：模型拒绝也可能是"识别出攻击所以拒绝"。正确判据是**有害任务是否被完成**（HarmBench 式行为判定），不是 keyword 匹配"我说不"就算赢；
- **判定两层漏斗**（复用 Day 120 验证器成本谱）：全量跑规则匹配 + 分类器（Llama Guard 档），边界样本升级 LLM judge——10⁷ 级变异量不可能全量上 judge；
- **双指标护栏**（Day 130 AgentDojo callback 落地）：ASR 上升的同时**正常任务完成率不掉**。只优化 ASR 会把模型逼成全拒答的假安全——Day 128 Goodhart 定律的同构重演。

**④ 归因分析（Triage）**
- **最小化（minimization）**：把触发成功的长样本删减到最小触发核——**delta debugging / ddmin**，和编译器 bug 复现最小化是同一个算法；
- **聚类去重**：按 embedding 或响应签名聚类。10 万个"成功样本"可能只对应 20 个独立漏洞——**修 20 个洞 ≠ 修 10 万条样本**；
- 人工定级：确认可用的漏洞 → 写报告 → 进黄金回归集。

**⑤ 回流增强（Feedback Loop）——紫队飞轮**
- 成功样本进**黄金回归集**：每次模型 / prompt / 护栏变更全量回归（Day 128 回归门禁复用）；
- 成功样本进**训练集**，两个方向：(a) SFT / DPO 的负样本（目标是拒绝 / 安全完成，样本进 rejected 侧）；(b) **GRPO 的对抗 rollout**（攻击成功轨迹 = 最难的负梯度样本，Day 130 veRL 连接的正式落地）；
- **防过拟合**：回归集轮换 held-out（Day 128 污染三板斧），否则模型学会"背下这 10 万条越狱"而非"学会拒绝这一类越狱"。

### 2. GCG 算法骨架（今天的题在连续 / 离散混合空间的版本）

GCG（Zou et al. 2023.10，《Universal and Transferable Adversarial Attacks on Aligned Language Models》）是 LLM 红队的分水岭：第一次让攻击**自动化、可迁移**——同一个对抗 suffix 能批量打穿多个模型。

```
算法骨架（能默写这个，面试官眼睛一亮）：
1. 目标：对禁止问题诱导肯定回答 → 构造 loss = −log P("Sure, here is" | 有害问题 + suffix)
2. 坐标：suffix 中每个 token 位置就是一个"坐标"
3. 每轮迭代：
   a. 对每个位置 i，用梯度 ∇_{e_{s_i}} loss 在 embedding 空间找 top-k 候选替换 token
      （one-hot 输入的梯度 = 替换方向的近似排序依据）
   b. 枚举"位置 × 候选"的 batch（几百~几千条），前向传播评估真实 loss
      —— embedding 近似 ≠ 真实离散 loss，必须前向校验
   c. 取 loss 下降最大的那条替换 → 固定 → 进入下一轮
4. 终止：目标串出现（攻击成功）或步数预算耗尽
```

**面试要点四条**：
- 本质 = **贪心坐标下降**：一次只改一个坐标、选当前最优、立即固定——和今天的题"逐位点亮 mask"是同一个搜索纪律；
- "**梯度提议 + 前向校验**"是连续松弛 → 离散投影的标准范式，说得出这句 ≈ 读过论文；
- **通用性来自多模型联合 loss**：对 M 个开源模型加权求和，找到的 suffix 同时压 M 个模型——单模型 suffix 容易过拟合到特定模型的怪癖上；
- **局限必说**：suffix 长、不可读、需要白盒梯度（闭源 API 不可用）。闭源场景靠**黑盒迁移**：开源模型上造 suffix，直接搬去攻击闭源模型，成功率依然可观——这正是标题里 "universal and transferable" 的另一半含义。

### 3. 从 GCG 到家族树（30 秒版本）

| 方法 | 机制 | 黑盒/白盒 | 一句话定位 |
|---|---|---|---|
| PAIR | LLM 当攻击者，多轮对话 + 历史反馈迭代 | 黑盒 | 用模型攻模型，攻击者与被攻击者同族时成功率最高（"做自己最懂自己的弱点"） |
| TAP | PAIR + Tree-of-Thoughts 分支探索 | 黑盒 | 把越狱当推理树搜索（Day 117 MCTS 的红队版） |
| **GCG** | 梯度贪心坐标下降 | 白盒 | 自动化 + 可迁移的开山之作 |
| AutoDAN | 遗传算法进化**可读**越狱 | 白盒/灰盒 | 解决 GCG 不可读：fitness = 攻击成功 − 可读性惩罚 |
| Crescendo | 多轮渐进累积 | 黑盒 | 单轮都在安全线内，多轮累积破防（实测打穿企业级助手的高危范式） |

**选型判据**：有白盒梯度 → GCG / AutoDAN；纯黑盒 API → PAIR / TAP / Crescendo；要可读可传播的 PoC → AutoDAN；模拟真实多轮场景 → Crescendo。

### 4. 连环问速答

**Q1：红队平台怎么衡量有效性？**
"三轴报表（Day 129 callback 正式落地）：① ASR 分攻击类别 × 分难度，不只看平均值；② **正常任务完成率护栏**——双指标缺一不可，全拒答的假安全不算赢；③ 漏洞修复周期——从发现到修复进回归集的时间。**红队的价值不在打出多少样本，在于闭环多快**。"

**Q2：红队系统和评估系统（Day 128）什么关系？**
"同一条流水线的两个读法：批量回放 + 自动打分 = 评估；针对性构造 + 主动进攻 = 红队。共享 trajectory store、共享 judge 栈，只差一个'生成器'模块。**eval 给你尺子，red team 主动去找尺子量不到的地方**——AgentDojo / AgentHarm 这类基准就是评测集和红队语料的合体产物。"

**Q3：对抗样本进训练，模型为什么不会反而学会越狱？**
"方向感问题：成功攻击样本对防御方是**负样本**——目标输出是拒绝 / 安全完成，样本进 DPO 的 rejected 侧或 SFT 的安全改写侧，同时按 Day 128 的做法 held-out 轮换。真正危险的是不加过滤地把'攻击成功对话'原样 SFT——那是让模型把越狱模板背下来。"

**Q4：闭源模型怎么做红队？**
"三层打法：① 开源白盒代理（Llama / Qwen 系）用 GCG 批量生产候选 suffix；② 迁移测试闭源 API（universal suffix 的本来用途）；③ 纯黑盒迭代（PAIR / TAP）针对闭源特有行为微调。合规线提前说：授权范围内测试，生产数据脱敏——这句主动讲是加分项。"

**Q5：人类红队 vs 自动化平台的关系？**
"自动化管**广度和回归**——每秒千条变异、每次发版全量回归；人类管**深度和新颖性**——新型攻击范式（比如刚出现的间接注入多轮链）只能靠人 + LLM 辅助头脑风暴发现，自动化只能变异已知模式。经验比例：已知面 90% 自动化 + 10% 人工；新范式靠紫队飞轮把人发现的模式固化成新的变异算子，完成沉淀。"

**Q6：veRL 里红队数据怎么用？（呼应 Week 17，向量化收尾）**
"两条路：① **对抗 reward**：rollout 时混入红队种子语料，reward = 任务成功 − λ·安全违规，约束用 CPO / Lagrangian 硬预算而非裸惩罚（Day 130 结论——裸惩罚会被 Goodhart）；② **失败轨迹利用**：攻击成功轨迹 = 组内 reward 最低的样本，GRPO 组基线自动给它最大梯度（Day 112）——**红队平台每打穿一次，训练侧就白得一个高质量难例**。红队不是成本中心，是训练数据的矿山。"
