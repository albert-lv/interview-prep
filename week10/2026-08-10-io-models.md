## 一、今日算法题：实现一个基于 epoll 的 Reactor TCP 服务器

### 题目描述

设计并实现一个支持**高并发长连接**的 TCP Echo 服务器，要求：
1. 单进程单线程模型，能同时处理 **10000+** 并发连接
2. 使用 Linux `epoll` 实现 IO 多路复用
3. 支持新连接接入、数据读取、数据回写三种事件
4. 使用**边缘触发（ET）+ 非阻塞 IO**，要求处理完整数据

### 核心思路：Reactor 模式

```
┌─────────────────────────────────────────────────────┐
│                  Reactor 事件循环                    │
│                                                     │
│   1. epoll_wait() 阻塞等待就绪事件                   │
│   2. 遍历就绪 fd 列表，分发到对应 handler            │
│   3. handler 处理完毕后，重新注册监听事件            │
│   4. 回到步骤 1                                      │
└─────────────────────────────────────────────────────┘
```

**为什么选择 epoll + ET + 非阻塞？**
- `select/poll`：每次调用都要拷贝 fd 集合到内核，O(n) 遍历，连接数 > 1000 后性能暴跌
- `epoll`：fd 常驻内核红黑树，就绪事件通过回调加入就绪链表，epoll_wait 直接返回链表，O(1) + O(就绪数)
- **ET（边缘触发）**：只在状态变化时通知一次（如空→有数据），倒逼程序员一次性读光数据，减少 epoll 调用次数
- **非阻塞 IO**：ET 模式下必须搭配非阻塞，否则 `read` 阻塞会导致整个事件循环卡死

### 代码实现（C 语言）

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/epoll.h>
#include <sys/socket.h>
#include <netinet/in.h>

#define MAX_EVENTS 1024
#define BUF_SIZE 4096
#define PORT 8080

// 设置 fd 为非阻塞
int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags < 0) return -1;
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

// 添加 fd 到 epoll 监听
void add_epoll(int epfd, int fd, uint32_t events) {
    struct epoll_event ev;
    ev.events = events;
    ev.data.fd = fd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);
}

// 修改 fd 监听事件
void mod_epoll(int epfd, int fd, uint32_t events) {
    struct epoll_event ev;
    ev.events = events;
    ev.data.fd = fd;
    epoll_ctl(epfd, EPOLL_CTL_MOD, fd, &ev);
}

// 创建监听 socket
int create_listen_socket(int port) {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd < 0) {
        perror("socket");
        exit(1);
    }
    
    int reuse = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse));
    
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = INADDR_ANY;
    addr.sin_port = htons(port);
    
    if (bind(listen_fd, (struct sockaddr *)&addr, sizeof(addr)) < 0) {
        perror("bind");
        exit(1);
    }
    
    if (listen(listen_fd, 128) < 0) {
        perror("listen");
        exit(1);
    }
    
    return listen_fd;
}

// 接受新连接
void accept_connections(int epfd, int listen_fd) {
    while (1) {
        struct sockaddr_in client_addr;
        socklen_t addr_len = sizeof(client_addr);
        int conn_fd = accept(listen_fd, (struct sockaddr *)&client_addr, &addr_len);
        
        if (conn_fd < 0) {
            // EAGAIN / EWOULDBLOCK: 没有更多连接了（ET 模式下需要这样）
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                break;
            }
            perror("accept");
            break;
        }
        
        set_nonblocking(conn_fd);
        // ET 模式监听可读 | 对端关闭 | 错误
        add_epoll(epfd, conn_fd, EPOLLIN | EPOLLET);
        printf("New connection: fd=%d\n", conn_fd);
    }
}

// 处理客户端数据（ET 模式：必须一次性读完）
void handle_client_data(int epfd, int fd) {
    char buf[BUF_SIZE];
    
    // ET 模式：循环读到 EAGAIN 才算读完
    while (1) {
        ssize_t n = read(fd, buf, sizeof(buf));
        
        if (n > 0) {
            // Echo 回写（实际工程应该用 epoll 监听可写事件再写）
            write(fd, buf, n);
        } else if (n == 0) {
            // 对端关闭连接
            printf("Client closed: fd=%d\n", fd);
            epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
            close(fd);
            break;
        } else { // n < 0
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                // 数据读完了，等待下一次 epoll 通知
                break;
            } else if (errno == EINTR) {
                continue; // 被信号中断，重试
            } else {
                perror("read");
                epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
                close(fd);
                break;
            }
        }
    }
}

int main() {
    int listen_fd = create_listen_socket(PORT);
    set_nonblocking(listen_fd);
    
    int epfd = epoll_create1(0);
    if (epfd < 0) {
        perror("epoll_create1");
        exit(1);
    }
    
    // 监听新连接（LT 模式也可，ET 模式要 accept 到 EAGAIN）
    add_epoll(epfd, listen_fd, EPOLLIN | EPOLLET);
    
    struct epoll_event events[MAX_EVENTS];
    printf("Server listening on port %d (epoll ET mode)\n", PORT);
    
    while (1) {
        int nfds = epoll_wait(epfd, events, MAX_EVENTS, -1);
        
        for (int i = 0; i < nfds; i++) {
            int fd = events[i].data.fd;
            uint32_t ev = events[i].events;
            
            // 错误处理
            if (ev & (EPOLLERR | EPOLLHUP)) {
                printf("Error on fd=%d, closing\n", fd);
                epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
                close(fd);
                continue;
            }
            
            if (fd == listen_fd) {
                // 新连接事件
                accept_connections(epfd, listen_fd);
            } else if (ev & EPOLLIN) {
                // 可读事件
                handle_client_data(epfd, fd);
            }
        }
    }
    
    close(epfd);
    close(listen_fd);
    return 0;
}
```

### 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 事件注册 | O(1) | epoll_ctl 操作红黑树，单次 O(log n)，但 fd 变动不频繁 |
| 等待事件 | O(就绪数) | epoll_wait 直接返回就绪链表，与总连接数无关 |
| 处理事件 | O(数据量) | 读写本身的复杂度 |
| 空间复杂度 | O(连接数) | 内核红黑树存储所有 fd，用户空间维护 events 数组 |

**对比 select/poll**：
- `select`: 每次调用 O(n) 遍历所有 fd，fd 集合大小限制 1024
- `poll`: 也是 O(n) 遍历，但无数量限制
- `epoll`: O(1) + O(就绪数)，**百万级连接**依然稳定

### 易错点

1. **ET 模式不读光数据**：只读一次，剩下的数据不会触发新事件，永久丢失
2. **阻塞 fd + ET**：read 阻塞 → 整个 Reactor 线程卡住，所有连接挂死
3. **accept 不循环**：ET 模式下多个连接同时到达，只 accept 一次会漏掉
4. **忽略 EINTR**：信号中断后必须重试，否则可能丢事件

## 二、面试技巧：IO 模型高频考点

### 2.1 五种 IO 模型对比

Unix 网络编程定义的五种 IO 模型，是面试必考：

| IO 模型 | 阻塞阶段 | 特点 | 代表 |
|---------|---------|------|------|
| **阻塞 IO** | 发起 → 数据就绪 → 数据拷贝 | 全程阻塞，一个连接一个线程 | 传统 BIO |
| **非阻塞 IO** | 无（轮询） | 立即返回 EAGAIN，CPU 空转 | 极少直接用 |
| **IO 多路复用** | epoll_wait 阻塞 | 一个线程监控多个 fd，谁就绪处理谁 | select/poll/**epoll** |
| **信号驱动 IO** | 无 | 数据就绪时内核发 SIGIO | 几乎不用 |
| **异步 IO** | 全程无阻塞 | 内核拷贝完数据后通知应用 | Windows IOCP、Linux AIO |

**关键记忆口诀**：
> 阻塞 IO：傻等  
> 非阻塞 IO：轮询（忙等）  
> IO 多路复用：等人来叫我  
> 信号驱动 IO：到了打电话  
> 异步 IO：送上门

### 2.2 epoll 为什么比 select/poll 快？

这是面试最高频的问题，回答要有层次：

**第一层次（数据结构）**：
> select/poll 每次调用都要把 fd 集合从用户空间拷贝到内核空间，epoll 通过 `epoll_ctl` 把 fd 注册到内核红黑树，一次注册终身有效，后续 `epoll_wait` 零拷贝。

**第二层次（就绪检测）**：
> select/poll 每次都要遍历所有 fd 检查是否就绪，O(n)。epoll 在内核中为每个 fd 注册回调函数，数据就绪时通过回调把 fd 加入就绪链表，`epoll_wait` 直接返回这个链表，O(就绪数)。

**第三层次（fd 数量限制）**：
> select 受 `FD_SETSIZE` 限制（默认 1024），poll 和 epoll 理论上只受系统内存限制。

**完整回答模板**：

```
1. 调用方式：epoll 通过 epoll_ctl 一次性注册 fd 到内核红黑树，
   后续 epoll_wait 无需重复拷贝 fd 集合；select/poll 每次都要全量拷贝。

2. 就绪检测：select/poll 每次 O(n) 遍历所有 fd；
   epoll 基于回调机制，数据就绪时自动加入就绪链表，epoll_wait 直接返回，O(1) + O(就绪数)。

3. fd 限制：select 有 1024 限制；epoll 无硬性限制，百万级连接也能高效处理。

4. 触发模式：epoll 支持 LT（水平触发）和 ET（边缘触发），
   ET 模式减少 epoll 调用次数，进一步提升高并发性能。
```

### 2.3 LT vs ET 怎么选？

| 特性 | LT（水平触发） | ET（边缘触发） |
|------|--------------|--------------|
| 通知次数 | 只要 fd 还有数据，每次 epoll_wait 都通知 | 只在状态变化时通知一次 |
| 编程难度 | 简单，不读光也没关系 | 困难，必须一次性处理完，必须非阻塞 |
| 性能 | 略低（可能重复通知） | 更高（减少 epoll 调用） |
| 适用场景 | 通用场景，可靠性优先 | 高并发、追求极致性能（如 Nginx） |

**推荐**：
- 新手/可靠性优先 → LT
- 追求极致性能 + 能处理好边界 → ET（Nginx 默认 ET）

### 2.4 Reactor vs Proactor

| 维度 | Reactor | Proactor |
|------|---------|----------|
| 模式 | "准备好通知我" | "做完告诉我" |
| 数据读写 | 应用自己 read/write | 内核负责读写，应用只处理业务 |
| 实现复杂度 | 中等（需处理非阻塞边界） | 简单（但依赖内核 AIO 成熟度） |
| 跨平台 | Linux/Unix 成熟 | Windows IOCP 成熟，Linux AIO 鸡肋 |
| 代表 | Redis、Nginx、Netty | Windows 高性能服务器 |

**Redis 的单线程 Reactor**：
> Redis 使用单线程 epoll 事件循环，所有命令串行执行，避免了锁竞争和上下文切换。为什么单线程还这么快？
> 1. 纯内存操作，瓶颈不在 CPU
> 2. IO 多路复用处理网络事件，没有线程切换开销
> 3. 避免锁竞争和复杂同步

### 2.5 高频面试题速答

**Q: 10k 并发连接怎么设计服务器？**
> 核心：IO 多路复用 + 事件驱动。
> 1. 监听端口，set_nonblocking + epoll ET
> 2. 单线程 Reactor 处理 accept/read/write 事件
> 3. 业务计算若耗时，扔给线程池异步处理，完成后通过 eventfd/pipe 通知主线程回写
> 4. 配合连接池、零拷贝（sendfile）、定时器（时间轮）管理空闲连接

**Q: 为什么 Redis 是单线程的，却能处理 10k QPS？**
> 1. Redis 命令都在内存中执行，纳秒/微秒级，没有磁盘 IO
> 2. 单线程避免了锁、线程切换、缓存失效的开销
> 3. 网络 IO 用 epoll 多路复用，阻塞只在 epoll_wait
> 4. 6.0+ 引入多线程 IO，但命令执行仍是单线程，网络读写多线程化进一步提升吞吐量

**Q: epoll 内核数据结构是什么？**
> 1. **红黑树（rb_tree）**：存储所有注册的 fd，key 是 fd，支持 O(log n) 的增删查
> 2. **就绪链表（rdllist）**：数据就绪时通过回调把 fd 节点加入链表，epoll_wait 直接遍历返回
> 3. **等待队列**：epoll_wait 的进程挂在此队列，有事件时唤醒

```
┌──────────────────────────────────────────────────┐
│  epoll 三板斧                                    │
│  epoll_create → 创建 epoll 实例                   │
│  epoll_ctl    → 注册/修改/删除 fd（红黑树）        │
│  epoll_wait   → 阻塞等待就绪事件（就绪链表）        │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  IO 模型演进路线                                 │
│  BIO (阻塞) → 多线程 BIO → NIO (poll/select)    │
│       → epoll Reactor → AIO Proactor             │
│  面试重点在中间三个：多线程 BIO、epoll、Reactor   │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  ET 模式 checklist                               │
│  ✓ fd 必须设为非阻塞                             │
│  ✓ read/write 循环到 EAGAIN                      │
│  ✓ accept 循环到 EAGAIN                          │
│  ✓ 处理 EPOLLERR | EPOLLHUP                      │

└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  为什么 epoll 快？                               │

└──────────────────────────────────────────────────┘
```
