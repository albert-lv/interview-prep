## 一、今日算法题：蓄水池抽样（LC 398 随机数索引 / LC 382 链表随机节点）——无限流上的无偏均匀采样

### 题目

给定一个可能**无限长**的数据流，设计一个算法从中**均匀**抽取 k 个样本（每个元素被选中的概率恰好相等）。你只能：

- 按流式顺序看一遍每个元素（不能回溯、不能随机访问）；
- 使用 O(k) 额外空间（流可能无限大，不能全存下来）；
- 在**任意时刻**被问到，都能立刻交出当前 k 个样本。

LC 398 版本：`int[] nums` 很大（内存放不下或流式到达），`pick(target)` 要返回 target 出现下标的**均匀随机**一个。LC 382 版本：单链表，`getRandom()` 返回一个随机节点的值——链表连长度都要现场数，是 k=1 的水塘特例。

### 工程重述：agent 轨迹无限流的「无偏抽检器」

这个题在本系列里不是孤立的，它是三条线的交汇点：

- **Day 138 奖励服务**：高 reward 轨迹送 1~5% L3 复核——轨迹是无限流式到达的，「抽 1%」必须是**无偏**的，否则你只抽到流开头那批（hacker 换策略你就瞎了）；
- **Day 142 推理网关**：10 万并发 agent 请求，全量记录 tracing 存不起，线上采样 1% 进可观测系统——采样器本身要在请求路径上，O(1) 内存；
- **Day 136 异步 pipeline**：rollout 轨迹流式进有界队列，质量审计要从队列里实时抽样，**等流结束再采 = 事后诸葛亮**。

共同约束：流无限、不能存、要实时、必须无偏。这就是蓄水池抽款的全部卖点。

### 算法 R（水塘抽样）：三行代码，一个归纳证明

```
reservoir = 流的前 k 个元素            # 先把池子灌满
for i = k+1, k+2, ... 每个新元素 x:
    j = random(1, i)                   # 在 [1, i] 里均匀取一个
    if j <= k:
        reservoir[j] = x               # 以 k/i 的概率替换池中某个位置
```

**正确性（面试必考，归纳证明背下来）**：第 i 个元素最终留在池中的概率 = k/i。

- **进入概率**：第 i 个元素被选中替换的概率是 k/i；
- **留存概率**：它一旦进入，之后第 t 步（t > i）被换出的概率 = (k/t) × (1/k) = 1/t，即每一步存活的概率是 (t-1)/t；
- 于是 P(第 i 个元素最终在池里) = (k/i) × i/(i+1) × (i+1)/(i+2) × ... × (n-1)/n = **k/n**。
- 对任意 i 成立 ⇒ 每个元素等概率 k/n ⇒ **均匀、无偏**。

**复杂度**：时间 O(n)（每个元素一次随机数）、空间 O(k)、**单次遍历**。

**为什么朴素做法不行（连环问第一弹）**：
- 「先遍历数总数 n，再第二遍 rand 抽」——流式场景**没有第二遍**（数据已经过去），且 n 未知；
- 「rand() % n」——n 不知道；
- 「每元素以 k/n 概率收下」——n 不知道，且概率随 n 变化需要全局协调；
- 「哈希分桶」——可以（hash(x) % m < k 收下），是**确定性采样**，适合「同一个请求永远采/永远不采」（tracing 粘性采样正是这么干的！），但**无法保证任意时刻恰好 k 个**、也不适合「池子大小动态调整」。面试把两个方案并排放 = 格局打开：水塘 = 无偏 + 恰好 k 个；哈希 = 确定性 + 粘性，工程上 tracing 用后者，审计抽检用前者。

### 进阶阶梯（面试官的 follow-up 弹药库）

1. **「时间不够 O(n)，10⁹ 元素流怎么办？」→ Algorithm L（Li, 1994）**：不逐元素掷骰子，而是**用几何分布直接算出「下一次入选发生在第几个元素」**，大步跳跃。总随机数次数降到 O(k·log(n/k))，期望复杂度 O(k(1+log(n/k)))，IO 场景下是数量级优化。**核心思想：入选间隔服从指数分布，先采样间隔再跳。**
2. **「元素有权重要按权重采」→ A-Res / A-Chao（Efraimidis-Spirakis）**：给每个元素算钥匙 `key = rand()^(1/w_i)`，流式维护**钥匙最大的 k 个**（小根堆），等价于按权重无偏采样。权重版水塘 = LC 528（按权重随机选择）的流式版——再进阶是 **Alias Method**（离线 O(n) 建表、O(1) 查询），加权采样工程终态。工程映射：轨迹按「reward 方差」加权抽（方差高 = 信息量大，Day 138 SNR 视角）、按「token 成本」加权抽（审计预算恒定，贵的少抽）。
3. **「k=1 的特例」→ LC 382**：链表随机节点，池子退化成单个变量，每个节点以 1/i 概率替换当前答案。 reservoir 的 hello world。
4. **「分布式：N 个分片各自流水」→ 分层合并**：每个分片跑自己的水塘（容量 k），分片流量不等时**不能直接合并池子**（长流分片被欠采）。标准答案：**按分片流量比例做 PPS（按规模比例概率）抽样合并**，或每分片水塘容量 ∝ 其流量份额；等流量分片才允许「合并后重采 k 个」。把「分层 ≠ 均匀」这个坑主动说出来 = 面试官点头时刻。
5. **「要 top-k 频繁项不是均匀采样」→ 算法家族对偶**：均匀采样保「无偏估计任意聚合」，但 top-k 频繁项要用 **Count-Min Sketch / Space-Saving**（频率 sketch，O(ε⁻¹log δ⁻¹) 空间）。**先分清题目要「代表性」还是「极端性」**：审计要代表性 → 水塘；找 reward hacking 苗头要极端性 → sketch 抓头部。两者经常级联：sketch 粗筛可疑流量 → 水塘从可疑流里精抽。
6. **「样本的置信区间呢？」→ 水塘样本当 bootstrap 源**：池里 k 个样本可重采样估均值方差；但注意**不放回抽样的有限总体修正**（fpc）：样本均值的标准误 = s/√k × √(1−k/n)。面试说出 fpc = 统计功底露一手。
7. **「元素会删除」→ 经典水塘不支持**；带删除的均匀采样是研究问题（日历抽样/两级采样），工程兜底 = 逻辑删除标记 + 定期重建池子。
8. **「采样率动态调」→ 粘性哈希 + 水位**：tracing 场景经典做法（OpenTelemetry 的 tail-sampling 前身），按错误率上调采样率——**采样率本身成为控制回路的一部分**，呼应 Day 140「混沌四纪律」里的 stop condition 思想。

### 代码

```python
import random

class ReservoirSampler:
    """无限流上的无偏均匀采样器：任何时刻 get() 都交出当前 k 个均匀样本。"""
    def __init__(self, k: int):
        self.k = k
        self.seen = 0
        self.pool = []

    def add(self, x) -> None:
        self.seen += 1
        i = self.seen
        if i <= self.k:                       # 前 k 个：直接灌满
            self.pool.append(x)
        else:
            j = random.randint(1, i)          # 以 k/i 概率替换
            if j <= self.k:
                self.pool[j - 1] = x

    def get(self):
        return list(self.pool)                # 恰好 k 个（seen >= k 时），各自概率 k/seen

# LC 398 应用：target 出现下标均匀抽取
class Solution:
    def __init__(self, nums):
        self.nums = nums
    def pick(self, target):
        count, ans = 0, -1
        for i, v in enumerate(self.nums):     # 水塘 k=1
            if v == target:
                count += 1
                if random.randint(1, count) == 1:   # 1/count 概率替换
                    ans = i
        return ans
```

**复杂度**：`add` O(1)、`get` O(k)；总时间 O(n)、总空间 O(k)。**正确性不依赖流的分布、不依赖 n、不依赖到达节奏**——这是对「无限流无偏采样」的**唯一** O(k) 空间单遍解（经典结论）。

## 二、面试技巧：Test-Time Scaling 工程实战——什么时候买智能、买什么、花多少

### 1. 先立框架：三条 Scaling 轴

Raschka 在 10/21 的《State of LLMs 2026》播客里把话说得很白：**inference scaling 就是不改权重、纯在用时多花算力**。花法只有三种：

| 轴 | 买什么 | 代表技术 | 成本模型 |
|---|---|---|---|
| **并行宽度** | 多个独立样本 + 聚合 | Self-Consistency / Best-of-N / 加权投票 | n × 单发成本 |
| **串行深度** | 更长的推理过程 | 长 CoT、反思、ToT/GoT 搜索、元推理 | token 数 × 单 token 成本 |
| **单次速度** | 同样的采样更便宜 | 投机解码、Highspeed 版、线性注意力硬件 | 固定常数因子 |

**Kimi K3.1 Pro 的发布（10/24）把三条轴同时演了**：底座后训练把「愿意想多久」的能力训进去（深度轴）、API 侧可以并行采样（宽度轴）、Highspeed 版 2~3× 速度（速度轴）、Cerebras 上用 69 层线性注意力重造经济学（架构定汇率）。**面试被问「怎么提升模型能力」，先反问预算花在哪个轴上——这句话本身就是答案的一半。**

### 2. 采样家族谱系（宽度轴全家桶）

- **Self-Consistency（Wang et al. 2022）**：temperature 采样 k 条 → 提取最终答案 → **多数投票**。MATH 上单次 54% → k=5 约 65% → k=20 约 72%。代价：成本线性。
- **Best-of-N**：不投票，用 verifier / PRM 打分取最高。Cobbe / Lightman 一脉。
- **加权/排序投票**：Ranked-Voting SC（用候选排序而非仅 top 答案）、**Pairwise-Guided Logit Adjustment（arXiv 2610.18583，10/13 新发）**——两两比较引导的聚合，比裸 SC 更抗候选分布偏移。
- **Universal SC**：开放任务没有可抽取的「最终答案」时，用 LLM 当聚合器判断语义一致性。
- **Verifier 引导**：GenRM / GenPRM（把验证本身变成生成任务，7B 在 ProcessBench 上打赢 72B）。
- **Agent 轨迹聚合（arXiv 2602.18998《Evaluating Test-Time Scaling of General LLM Agents》）**：在 general agent 任务上**多数投票直接失效**（轨迹没有唯一 final answer，Pass@K 涨但 Majority 不涨甚至跌），替代方案是 **Self-Choice / Pairwise / 外部 judge**——**聚合器的选择必须由输出结构决定，这是 2026 年的标准答案。**

### 3. 今天的重头戏：投票的失效边界（把三篇论文变成一张表）

这是面试官最新鲜的弹药，也是你反超背八股的人的机会：

| 场景 | 证据 | 失效机理 |
|---|---|---|
| 模型太强 | Gemini 2.5 Pro MATH-500 98%→99.6%，花 15× 算力（arXiv 2511.00751） | 路径高度冗余，无方差可降；聚合器反而引入伪错误（Flash-Lite >15 条 **准确率下降**） |
| 模型太弱 | GPQA Diamond 上投票让 Qwen2.5-7B 在 56.6% 问题上**更差**（arXiv 2608.11403） | 高方差、无主导答案 → 投票 ≈ 随机抽签，还系统性偏向「最像训练分布」的错误答案 |
| judge 系统性偏差 | RUVERBENCH：3~5 票后饱和，再多票无效 | 投票只消**采样噪声**（方差），消不掉**系统性偏差**（bias）——位置偏/冗长偏投 100 票照样在 |

**统一理论一句话（bias-variance 分解）**：多数投票是**方差绞肉机**——它把独立采样噪声磨平，对共享偏差无能为力。而**同一家族模型的多条采样路径，偏差是共享的**（同样的训练分布、同样的盲区），所以：

- **投票起作用的窗口 = 模型「够强以至于单发有戏」且「没强到路径冗余」的中间地带**；
- 想突破这个窗口，要么引入**异构性**（跨家族投票、PoLL 评审团——小模型评审团以 7× 更低成本打赢单大 judge，因为不同家族不共享盲区；这正是 Day 138 L3 判据「跨家族 2~3 个 frontier 模型多数决」的论文级依据），要么引入**外部信号**（verifier、执行反馈、PRM）。

### 4. 预算经济学：几条经验法则上秤

- **「3~5 票原则」**：RUVERBENCH + 多篇 2026 复现共同指向：自洽性收益在 **3~5 条路径内结算 80% 以上**。线上默认 k=4 或 5，超过必须 justify。
- **「Blend-ASC 动态分配」（NeurIPS）**：按当前一致性分布决定下一条还采不采，平均省 6.8× 样本、无超参。**流式早停的工程形态**：先并发 3 条 → 全一致即停 → 分歧大再追加 2 条 → 仍分歧升级 verifier 或人工。
- **「生成 vs 验证的天平」（When To Solve, When to Verify）**：常规难度分布上 SC 性价比高于 GenRM（8× 算力才能追平）；**难题占比高时**（竞赛数学、形式化证明）验证侧相对收益可达 30%。**先估任务的难度分布，再决定预算往生成还是验证倾斜。**
- **成本公式要写全**：k 路采样的真实成本 = k × 单发成本 × **(1 − 前缀复用率)**。同 prompt 组内采样共享前缀 prefill（Day 142 prefix caching 红利在这里精准兑现），n 路并行的边际成本往往只有 decode 部分；**但 KV cache 要 ×n**（Day 143 的账直接搬过来），长上下文高并发采样是显存杀手。**Cerebras 的线性注意力账本（10/25）说明架构正在改写这个公式的常数项。**
- **错误成本不对称才买**：医疗/金融/法律场景错误代价 ≫ 采样成本，k=8~16 合理；普通对话场景 15× 成本换 1.6% 是负 ROI——**采样预算应该跟着错误代价走，不是跟着能力上限走。**

### 5. 工程清单（落地 checklist）

1. **答案规范化先于投票（canonicalization）**：「1/2」vs「0.5」vs「2^{-1}」不规范化，投票就是统计垃圾。规范化器自己也是攻击面（Day 130 感知归一化思想同源）。
2. **temperature 分层**：投票路径用 0.5~0.8 要多样性；最终展示路径用 greedy 或低温保质量。
3. **置信度 = 票分布**：9/10 一致是高置信，5/10 一致要挂「低置信」标并触发二轮。置信度本身进日志、进告警（低置信率飙升 = 模型或流量异常的第一信号）。
4. **审计留痕**：保留全部 k 条轨迹 + 票分布 + 聚合器版本号（reward_version 三元组铁律同款，Day 138）。
5. **聚合器也是组件**：USC 的 judge、pairwise 的比较器都要版本化、要 golden set 回归（Day 138 判据 CI 同款）。
6. **超时与降级**：采样聚合必须带 deadline，超时按「已有票的多数」出结果并标记 degraded——**测试时扩展永远不能拿尾延迟换准确率**（TPOT p99 是硬约束，Day 142）。

### 6. 模拟面试五连

- **Q1：Self-Consistency 和 Best-of-N 怎么选？** 有可抽取答案、无可靠 verifier → SC；有强 verifier/执行反馈 → BoN（代码任务直接跑测试选过测的，verifier 免费）；开放任务 → USC/LLM 聚合。聚合器选择由**输出结构**和**可用信号**决定。
- **Q2：为什么跨家族投票比同家族多采样强？** bias-variance：同家族路径共享训练偏差，投 100 票只是同一个盲点的 100 次复印；跨家族引入独立偏差源，方差和偏差同时被压制。PoLL 数据：小模型异构评审团 7× 更便宜还更准。回收 Day 138 L3 设计。
- **Q3：面试官问「k 取多少」，满分回答？** 「先分任务难度分布和错误代价：常规任务 3~5 条（RUVERBENCH 收益饱和点）；难题占比高时配 verifier 而非无脑加 k；强模型上警惕负收益（arXiv 2511.00751：15 条路径后 Flash-Lite 准确率反降）；生产上用 Blend-ASC 式动态早停把 k 从超参变成控制回路。」
- **Q4：10 万 QPS 的网关要加采样聚合，架构怎么落？** 网关层拦截 → 按错误代价路由（高代价请求进采样池）→ 组内同 prompt 并行 n 路（prefix 共享，KV ×n 要过容量校核，Day 142 预算预检题直接复用）→ 流式早停调度 → canonicalize → 聚合 → 置信度落审计日志。超时降级路径必备。
- **Q5：怎么用今天的蓄水池抽样？** 采样聚合的生产效果需要无偏审计：从请求流里水塘抽 k 条做人工/强模型复核，无偏 → 误差率估计可信；按 reward 方差加权（A-Res）→ 审计预算花在信息量最大的请求上；分层 → 按租户/按路由档位分层抽，保证每层都有样本。**采样器 + 聚合器 + 审计器，三位一体的 test-time scaling 才配叫工程。**

### 今日金句

> **多数投票是一台方差绞肉机：它把采样噪声磨平，却对系统性偏差无能为力——同一家族模型投出的多数，只是同一个盲点的 k 次复印。投票的收益在第三到第五条路径就结算完毕，后面的采样只是在给冗余充值。而 2026 年的工程答案不是不投票，是「分层买」：3~5 票打底，异构破偏差，verifier 攻难题，早停防浪费——测试时计算不是超参数，是一门预算学。**
