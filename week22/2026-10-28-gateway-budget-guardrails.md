## 一、今日算法题：最近的请求次数（LC 933）+ 设计 Rate Limiter（令牌桶 / 漏桶）

### 题目

**LC 933 最近的请求次数**：实现一个计数器类 `RecentCounter`，每次调用 `ping(t)`（t 单调递增，单位毫秒）返回**过去 3000 毫秒内的请求数**（含 t 自身）。

工程版本（面试真正在考的）：**为 LLM 网关设计一个限流器**——每个租户/API key 限制 `R` 次/秒（或 `T` token/分钟），超额请求**快速失败**而不是排队拖死网关。

### 为什么今天讲它（配额三轴的算法底座）

Day 142 预告过的「配额三轴」——**限流（rate）× 配额（quota）× 并发槽（slot）**——第一轴的算法本体就是今天的题：

- rate 轴 = 「每秒/每分允许多少」→ 滑动窗口 / 令牌桶 / 漏桶（今天的题）；
- quota 轴 = 「本月/本周期总量多少」→ 一个计数器 + 周期翻转（算法平凡，难在语义，见面试部分 429 vs 402）；
- slot 轴 = 「同时能有多少个在飞」→ 信号量（semaphore）。

三轴缺一，就有逃逸路径：只有 rate 没有 quota → 匀速打满整月账单（Skynet 的 10 万步最喜欢这种环境）；只有 quota 没有 rate → 月初一秒打爆下游；只有 rate+quota 没有 slot → 10 万个并发各占一点额度，把 KV 池（Day 143）挤到抢占换出。

### 思路：五种限流算法一张表

| 算法 | 内存 | 单操作复杂度 | 平滑性 | 允许突发 | 典型用途 |
|---|---|---|---|---|---|
| 固定窗口计数器 | O(1) | O(1) | 差（窗口边界 2× 突刺） | 窗口级突发 | 粗粒度、可容忍突刺 |
| 滑动窗口日志 | O(W) | O(log W)+淘汰 | 好（精确） | 无 | 小规模精确限流 |
| 滑动窗口计数器 | O(数窗) | O(1) | 较好（加权近似） | 部分 | **网关最常用** |
| **令牌桶** | O(1) | O(1) | 好 | **桶容量内自由突发** | **API 网关标准答案** |
| 漏桶 | O(1) | O(1) | 最好（恒定速率出） | 无（排队或丢弃） | 下游保护、出口整形 |

**LC 933 最简正解 = 滑动窗口日志**：队列存时间戳，`ping(t)` 时把 `< t-3000` 的队首全部弹出，返回队列长度。

```go
type RecentCounter struct{ q []int }

func Constructor() RecentCounter { return RecentCounter{} }

func (c *RecentCounter) Ping(t int) int {
    c.q = append(c.q, t)                       // t 单调递增 → 直接入队
    for c.q[0] < t-3000 {                      // 弹掉窗口外的
        c.q = c.q[1:]
    }
    return len(c.q)                            // 窗口内请求数
}
```

**边界坑两个**：窗口是**闭区间** `[t-3000, t]`（所以弹出的条件是 `< t-3000` 而非 `<=`）；单调递增的前提让队列头部一定是窗口外最老的——如果 t 不单调，要先排序或换结构。

### 令牌桶（Token Bucket）——面试标准答案

每个 key 一个桶：容量 `B`（桶大小 = 允许的最大突发），以恒定速率 `R` 往里放令牌；一个请求要**先取走 1 个令牌**（token 维度就取走 `n_tokens` 个），取到才放行，取不到立刻拒绝。

```go
type Bucket struct {
    tokens     float64   // 当前令牌数
    lastRefill time.Time // 上次结算时刻
}

type Limiter struct {
    mu      sync.Mutex
    buckets map[string]*Bucket
    rate    float64       // 令牌/秒
    burst   float64       // 桶容量
}

func (l *Limiter) Allow(key string, cost float64) bool {
    l.mu.Lock()
    defer l.mu.Unlock()
    b, ok := l.buckets[key]
    if !ok {
        b = &Bucket{tokens: l.burst, lastRefill: time.Now()}
        l.buckets[key] = b
    }
    // 惰性结算：不放后台 goroutine，请求来时按 elapsed 补发令牌
    elapsed := time.Since(b.lastRefill).Seconds()
    b.tokens = math.Min(l.burst, b.tokens+elapsed*l.rate)
    b.lastRefill = time.Now()
    if b.tokens >= cost {
        b.tokens -= cost
        return true
    }
    return false                                  // 快速失败：不排队
}
```

- **复杂度**：O(1) 时间、O(租户数) 空间；无后台定时器（惰性结算）→ 无惊群、无空转。
- **为什么惰性结算是关键工程细节**：每 key 一个 ticker goroutine = N 万个空转协程；惰性结算把「补令牌」摊销到请求路径上，和 Day 143 懒标记线段树「先记账，谁需要谁结账」是同一个哲学。
- **漏桶（Leaky Bucket）对偶**：桶底以恒定速率漏水（处理），请求进来加水，水满即拒。输出**恒定平滑**（整形 egress），但不允许突发——适合保护脆弱的下游（老数据库、限价的第三方 API），不适合交互式流量（突发=用户同时提问被无故拒绝）。

### 高频连环问

**Q1：固定窗口和滑动窗口差在哪？** 固定窗口在窗口边界允许 2× 流量突刺（59s 和 60s 两个窗口各打满 R → 1 秒内 2R）。滑动窗口计数器用「本窗口计数 × 权重 + 上窗口计数 × (1-权重)」近似，O(1)、误差有界；滑动窗口日志精确但 O(窗口内请求数)。**网关选滑动窗口计数器；强一致小额支付选日志版——误差方向要说清楚（近似版可能略放行）**。

**Q2：10 万个租户、单机存不下？** 分片 + 一致性哈希（Day 145！）把 key 路由到 N 个计数分片；更工程化的答案：**限流从精确走向允许超发**——Redis `INCR`+`EXPIRE` 做固定/滑动窗口（一个 key 两次往返 O(1)），本地进程内缓存 + 异步批量同步 Redis（最终一致，超发率 ∝ 同步间隔）。**先问业务能接受多严格的限流，再选存储——这句反问加分。**

**Q3：限流器自己成了单点/热点怎么办？** ①本地令牌桶 + 定期从中心「批量领 token」（边缘自治，断网也活着，超发=未用额度）；②分层限流：边缘本地粗限（防突发）→ 中心精限（防总额）——**和缓存三级表（Day 145 L1/L2/L3）同构：越近请求越糙，越中心越准**。

**Q4：令牌桶的 burst 怎么定？** = 业务允许的瞬时并发体验（交互式：R×2~5 秒；批处理：burst=1 平滑执行）。**burst 是产品参数不是算法参数**——和 Day 144 采样 k 值同理：先问错误代价/体验预算，再定数字。

**Q5：被限流了客户端该收到什么？** 429 + `Retry-After`（rate 轴，稍后能成）vs 402/403 + 充值指引（quota 轴，这周期没救了）——这正是面试部分第二节「429 vs 402 语义」的引子。**限流算法的返回值要带上「拒绝语义」供上游决策：可重试（等一秒）还是不可重试（去付费）。**

### 工程映射：LLM 网关的多维限流

真实 LLM 网关（Kong/Envoy/自研）对每个 key 同时跑**三个桶**：

```
per-key:   RPM 桶（请求/分）‖ TPM 桶（token/分）‖ 并发 slot 信号量（在飞请求数）
per-model: 每模型再叠一层（保护稀缺的大模型配额）
per-cost:  每请求按价目表折算 $ 进「成本桶」（$/天）——Terra 的 1/20 缓存价意味着成本桶必须区分缓存命中/未命中
```

任一轴超了都快速失败，拒绝信息带轴标识（`rate_limited` / `quota_exhausted` / `slot_busy`）——**三个轴的拒绝语义不同，客户端的处理路径就不同。**

## 二、面试技巧：网关预算护栏

### 1. 配额三轴框架（先说这张表，再展开任何一轴）

| 轴 | 回答的问题 | 单位 | 超了怎么办 | 状态码语义 |
|---|---|---|---|---|
| **Rate 限流** | 太快了没？ | req/s · token/s | 等下一窗口，**可重试** | **429** + Retry-After |
| **Quota 配额** | 这个月花完了没？ | token/月 · $/月 | 充值/升档/申请临时额度，**不可重试** | **402**（或 403 + 计费码） |
| **Slot 并发** | 同时在飞的是不是太多？ | 并发请求数 | 排队 or 拒，**看 SLO** | 429（排队）/ 503（拒） |

**缺轴逃逸三连（面试官最爱追问）**：只有 rate → 匀速蚂蚁搬家吃光月配额（Skynet 型攻击的合法外衣）；只有 quota → 月初一秒打穿下游 + KV 池抢占（Day 143 num_preemptions 告警）；没有 slot → 慢请求堆积，TPOT p99 恶化（Day 142 组合题②同款）——**slot 轴本质是把 Day 143 的 KV 池容量翻译成网关语言**。

### 2. 429 vs 402：两种「不够」是两种生意

- **429 Too Many Requests**（rate 轴）：「你来得太急，**稍后**再来」→ 客户端该**指数退避 + jitter 重试**；响应必须带 `Retry-After`（或 rate limit 三件套 `X-RateLimit-*`）。
- **402 Payment Required**（quota 轴）：「你**这个月**的钱花完了」→ 重试没有意义（这个周期内），客户端该降级到便宜模型/提示用户充值/走审批申请临时额度。
- **402 的恢复路径是组织流程，不是 sleep**——这是两个状态码最本质的区别。面试加分句：**「429 是时间维度的问题，402 是会计维度的问题；把配额耗尽报成 429，客户端会退避重试白烧你 10 倍的无效请求。」**
- **工程细节**：quota 耗尽不该硬断（体验事故），标配**三级降级路径**（见下）；Header 里要带 `X-Quota-Remaining` 和预计重置时间，让客户端有数据做「预算感知调度」——**好的护栏不是墙，是仪表。**

### 3. 预算耗尽与降级路径（Graceful Degradation Ladder）

配额见底时按梯子往下走，每一级都写明「牺牲什么、保住什么」：

1. **L0 无损**：自动切到缓存档/便宜档——Terra 的缓存输入 $0.05 就是官方给你留的降级位：命中缓存的请求成本只有未命中的 1/20，**先砍缓存未命中率（Day 145 六军规 recanonicalization），等于免费扩容 20 倍**；
2. **L1 降质**：切小模型（RouteLLM 路由阈值临时收紧，Day 145）/关 test-time 采样（k 从 5 降到 1，Day 144）/缩短上下文窗口——**主动降质永远好过被动熔断**，因为节奏在你手里；
3. **L2 降级服务**：非关键功能（深度研究/长文档总结）排队到下个周期，核心问答保供——按业务优先级排序，不是 FIFO；
4. **L3 硬熔断 + 人工**：单 agent 成本斜率突增 10×（失控循环）→ 熔断转人工审批（Day 141 混合题④）。

**铁律（Day 145 可靠性五连同款）：护栏是省钱路径，省钱路径可以挂，不能拖死主路径——配额服务挂了默认放行 + 异步补记，绝不能同步阻塞所有请求。**

### 4. 成本异常 = 行为异常检测（今日最值钱的一节）

Day 141 金句「成本异常 = 行为异常，烧钱斜率突变是 agent 失控循环的第一个信号」——本周 Symantec 用 Skynet 的官方防护建议给这句话盖了章（「监控异常推理用量与 API 费用——这往往是访问权限已被盗用的第一个信号」）。工程落地四件套：

- **基线**：每 key/agent/功能三个维度算 P50/P99 的「token/请求」「$/小时」基线（滑动 7 天，分工作日/周末）——没有基线，"异常"不存在；
- **检测**：斜率突变（1 小时窗口 $ 环比 > 10×）‖ 绝对阈值（单请求 token 超历史 p99 的 5 倍）‖ 结构突变（缓存命中率从 90% 掉到 20%——按 Terra/K3.1 的价目表，命中率跳水 = 成本瞬间 20×，**缓存命中率是最便宜的 IDS**）；
- **处置**：熔断（key 降权/冻结）→ 通知 → **审计日志回溯该 key 最近 24h 全部请求**（Skynet 场景：烧你钱的人在干嘛，比谁在烧更重要）；
- **与身份联动**：成本异常自动触发密钥轮换建议（呼应 360 Netlab 周报：AI 令牌已和传统凭据同列窃取目标）——**成本告警也是安全告警，网关也是 SOC 传感器。**

### 5. 热点案例串讲三则

- **案例 A（定价篇）：Terra 的 1/20 价如何改写完护栏配置**——K3.1 缓存 1/10 价（Day 145）→ Terra 1/20 价（10/27），一周翻倍。如果你把「缓存折扣」写死在成本桶代码里，价目表一变全错。正确答案：**折扣率、各轴阈值、降级梯子的切换点，全部是配置/规则引擎数据，跟随价目表版本发布**——「价目表是数据，不是代码」，和 Day 138 reward_version 版本化同构。
- **案例 B（财报篇）：Anthropic S-1 的 80% 说明了什么**——$130.64 亿按用量计费收入意味着：**护栏这门「内部工具」，在前沿实验室那里就是营收本身**。面试官问「为什么预算护栏值得一个团队做」，把这份招股书拍出来：消费计费 = 计量 + 限额 + 账单三件套，你的网关护栏和 Anthropic 的收银台是同构系统——**做护栏不是成本中心，是在给自己的商业化铺路**。
- **案例 C（安全篇）：Skynet 的 10 万步 vs 你的三轴配额**——Skynet 专门猎杀「未设认证 + 无用量监控」的端点，蜜罐 12.7 万次探测说明扫描是持续背景噪音。**如果你的网关只有 rate 轴：攻击者以合法速率匀速搬空你的余额（LLMjacking 的理想形态）；加上 quota 轴：每月封顶损失可计算（风险评估能报价了）；再加上成本异常检测：密钥泄露当天就被烧钱斜率暴露。**三轴 + 异常检测 = 从「会被搬空」到「损失有上限且能发现」的差距。

### 6. 模拟面试速答五连

**Q1：设计一个支撑 10 万企业客户的 LLM 网关预算护栏。**
「三轴配额模型（rate/quota/slot 独立配置，缺轴有逃逸路径）→ 存储用 Redis 集群按 key 哈希分片，桶用滑动窗口计数器近似 O(1) → 配额判定走本地缓存 + 异步批量同步（超发率可控），slot 用信号量，KV 容量联动 Day 143 的池水位 → 拒绝语义三分类：429+Retry-After / 402+重置时间 / 503 → 降级梯子 L0-L3 配置化 → 成本异常检测（基线+斜率+命中率突变）接 SOC → 全部指标进监控：拒绝率、超发率、命中率、每 key  burn rate。**护栏本身高可用：配额服务挂了放行+补记，不阻塞主链路。**」

**Q2：429 和 402 到底怎么分？**
「时间维度 vs 会计维度：429 说『等会儿』，客户端退避重试；402 说『这周期没了』，重试无意义，该走升级/降级。报错了会发生什么：402 报成 429 → 客户端疯狂重试放大损失；429 报成 402 → 用户被误引导去付费，体验事故。Header 带 Retry-After / X-Quota-Remaining，把信息给全。」

**Q3：限流算法选哪个？**
「先反问流量形状：要突发的交互式（API 标准产品）→ 令牌桶（burst 内自由、可配）；要保护脆下游（老库/贵第三方）→ 漏桶（恒定出）；要强一致小额场景 → 滑动日志；10 万 key 规模 → 滑窗计数器 + Redis，接受有界超发并监控超发率。**没有免费午餐：精确度、内存、突发能力三选二。**」

**Q4：怎么防 Skynet 这类「我的密钥被别人拿去烧」？**
「防：认证全覆盖（连 health/model-list 路径都要，Symantec 点名）、密钥窄 scope + 定期轮换、网关前置不裸奔。检：**成本异常检测四件套（基线/斜率/结构/身份联动）——官方说烧钱的异常往往是最早信号**。治：熔断 key → 审计 24h 请求 → 自动轮换。答出『命中率从 90% 掉到 20% 按 1/20 折价表等于成本瞬间 20 倍』这句，面试官知道你是真懂价目表的。」

**Q5：配额服务自己挂了怎么办？**
「三条：①fail-open + 异步补记（护栏不挡主链路）②边缘本地桶自治（缓存一份配额，断网续命，超发有界）③配额服务自己也要配额（防配置错误把 Redis 打爆——混沌注入项：把配额存储延迟注高，验证网关降级路径）。」
