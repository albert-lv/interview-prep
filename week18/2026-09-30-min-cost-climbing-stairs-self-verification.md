## 1) 今日算法题

### 爬楼梯的最少成本（Min Cost Climbing Stairs）

**题意**：给你一个整数数组 `cost`，其中 `cost[i]` 是**踏上**第 `i` 级台阶必须支付的费用（你可以免费站在第 0 级或第 1 级上开始）。每次你可以选择爬 **1 级或 2 级**。求到达**楼顶**（第 `n` 级，`n = len(cost)`，楼顶本身无费用）所需支付的**最小花费**。

```
输入: cost = [10, 15, 20]
输出: 15
解释: 从第 1 级（费用 15）起步，直接爬 2 级到顶，总花费 15。
      若从第 0 级起步：10 + min(15, 20) = 25，更贵。

输入: cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]
输出: 6
解释: 走 0→2→3→4→6→7→9，费用 1+1+1+1+1+1 = 6。
```

**关键约束**：`2 <= cost.length <= 1000`，`0 <= cost[i] <= 999`。简单题，但它是 Day 1 爬楼梯的"对偶回归"——118 天后回到起点，答案会不一样。

### 思路：与 Day 1 对偶——同一个状态机，换个聚合函数

Day 1 的爬楼梯数的是**路径条数**（聚合 = 加法），本题求的是**路径的最小代价**（聚合 = 取 min）。状态定义一模一样：**`f(i)` = 到第 i 级为止的最小花费**，且都只依赖前两项——重叠子结构是同一块，换了个聚合方式。

**转移方程**：

```
f(i) = cost[i] + min(f(i-1), f(i-2))     // 最后一步从 i-1 或 i-2 跨上来
f(0) = cost[0], f(1) = cost[1]           // 起步免费"站上"，但踏上要付费
答案  = min(f(n-1), f(n-2))               // 最后一步爬 1 级或 2 级上顶，登顶免费
```

三个易错点，全是面试钩点：
1. **起步免费、踏上付费**：从 0/1 级开始不收 cost[0]/cost[1] 吗？——错。题意是"可以免费站在上面起步"，但你站上去的那一步要付费。所以初值直接是 `cost[0]`、`cost[1]`，不是 0。
2. **答案是 min(末两项)**：楼顶没有费用，最后一步不花钱，别返回 `f(n-1)` 单值。
3. **为什么不能局部贪心**："每步走便宜的"反例 `cost = [1, 100, 1, 1, ...]`——踏上便宜的第 0 级，下一步被迫付 100；直接站上第 1 级（100）反而... 本题最优是绕过所有 100。贪心只看下一步，DP 看整条路。这是"贪心 vs DP"的标准面试对。

**空间优化**：`f(i)` 只依赖前两项 → 滚动两个变量，O(1) 空间，和斐波那契同构。Day 1 是"你其实一直在写斐波那契"，今天加个 cost 依然成立。

> 🧬 **和今日主题的连接**：本题的暴力解法是枚举全部 O(2ⁿ) 条爬法取最小（每级一个二选一，像不像 Self-Consistency 采样 N 条路径再投票？）。DP 利用**重叠子结构**把指数级路径折叠成线性状态——每条子路径的最优值被复用而不是重采。**test-time compute 的采样/投票只在"状态不可压缩"（开放生成）时才出场；能精确 DP 的问题，别投票。**反过来也成立：LLM 之所以需要投票，正是因为开放生成的状态空间压不动。

### 代码

**Go（滚动变量 O(1) 空间，面试标准答案）：**

```go
func minCostClimbingStairs(cost []int) int {
    a, b := cost[0], cost[1] // f(0), f(1)：起步站上免费，但踏上要付费
    for i := 2; i < len(cost); i++ {
        a, b = b, cost[i]+min(a, b) // f(i) = cost[i] + min(前两步)
    }
    return min(a, b) // 最后一步从 n-1 或 n-2 免费登顶
}
```

**Python（带完整 DP 数组版，先写对再压缩）：**

```python
def minCostClimbingStairs(cost: list[int]) -> int:
    n = len(cost)
    dp = [0] * n
    dp[0], dp[1] = cost[0], cost[1]        # 踏上第 0/1 级的费用
    for i in range(2, n):
        dp[i] = cost[i] + min(dp[i-1], dp[i-2])
    return min(dp[n-1], dp[n-2])           # 登顶那一步不花钱
```

**Follow-up：最多爬 k 级（滑动窗口最小值版）：**

```python
def minCostClimbingStairsK(cost: list[int], k: int) -> int:
    # f(i) = cost[i] + min(f(i-k) ... f(i-1))，维护窗口最小值 → 单调队列 O(n)
    from collections import deque
    n = len(cost)
    dq = deque()                            # 存下标，对应 dp 值单调递增
    dp = [0] * n
    for i in range(n):
        while dq and dq[0] < i - k:         # 滑出窗口的踢掉
            dq.popleft()
        dp[i] = cost[i] + (dp[dq[0]] if dq else 0)  # 窗口最小值
        while dq and dp[dq[-1]] >= dp[i]:   # 保持单调
            dq.pop()
        dq.append(i)
    return min(dp[-k:])                     # 最后 k 级任选一个登顶
```

> 💡 **k 级版精髓**：`dp[i]` 依赖前 k 个状态的最小值——"窗口最小值"是单调队列的招牌场景（和 Day 66 滑动窗口最大值对偶：那题取 max 用递减队列，这题取 min 用递增队列）。k=2 时退化为本题；k→n 时退化为"全局历史 min"，O(n)。

**复杂度**：
- 时间：`O(n)`（k 级版 `O(n)` 单调队列均摊）；空间：`O(1)`（滚动）/ `O(n)`（数组版）。

### 面试官连环问

> **Q1：为什么不能"每步走当前便宜的那级"贪心？**
>
> 反例 `cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1]`：踏上便宜的第 0 级（1），下一步被迫面对 100；而站上第 1 级直接跨过。贪心只看**下一步**的局部代价，DP 的 `min(f(i-1), f(i-2))` 看的是**到这一步为止的全程代价**——"局部便宜可能买来了全局最贵的后续"，这是所有贪心 vs DP 之争的通用判词。

> **Q2：初值为什么不是 f(0)=0？**
>
> 题意是"可免费**站在** 0/1 级起步，但**踏上**要付费"。所以 `f(0)=cost[0]`、`f(1)=cost[1]`。经典坑：写成 0 会让"从第 0 级起步"变成零成本穿越。

> **Q3：状态定义换一下——"爬到第 i 级"而不是"踏上第 i 级"，方程怎么写？**
>
> `g(i) = min(g(i-1) + cost[i-1], g(i-2) + cost[i-2])`，`g(0)=g(1)=0`，答案 `g(n)`。两种定义都对，区别只在"费用记在哪一头"。面试时主动写出两种定义，展示你对建模自由度有意识——状态机定义没有标准答案，只有一致性。

> **Q4：cost 里出现负数，DP 还成立吗？**
>
> 成立。转移图是 DAG（只从低索引向高索引走，无环），DAG 上的最短路 = DP，与权值正负无关。真正的陷阱是语义：若题目改成"每级**停留**还倒贴钱、可无限停留"，那才出现负环，问题变质。考的是**识别最优子结构何时被破坏**。

> **Q5：扩展到"有一次免费跳（跳过任意一级不付费）"技能？**
>
> 状态加维度：`f0(i)` = 到第 i 级且技能没用，`f1(i)` = 技能已用。转移时多一条 `f1(i) = min(f1(i-1), f1(i-2), f0(i-1), f0(i-2))`（本次跨步免费 = 从 f0 跳过来不加 cost[i] 的... 细节按"跳"的定义调整）。四变量 → 六变量，和 Day 108 股票问题"第 k 笔"的状态机扩展**同一套手法**——DP 状态维度的扩展口诀：**多一种人生经历，加一维状态**。

> **Q6：cost 是数据流（一个个到来，无法存全数组）怎么办？**
>
> 本题天然在线：`f(i)` 只依赖前两项，流式维护 `a, b` 两个变量，每个新 cost O(1) 更新、实时输出当前最优——**滚动数组的 DP 都是数据流友好的**，这是和"必须看全数组才能排序"的贪心题的本质区别。

> 💬 **收尾一句话**：爬楼梯教会我们的从来不只是爬楼梯——118 天前它教我们"重叠子结构可以计数"，今天它教我们"同一个状态机换个聚合函数就能求最优，而**当结构允许精确解时，一切采样和投票都是在向近似交税**"。

## 2) 面试技巧：自我验证与反思（Self-Consistency / Self-Refine / 验证者悖论）

### 先把今天的主角放回光谱

Day 115 立过 test-time 策略的三类框架，本周一直在填格子：

| 策略 | 机制 | 外部依赖 | 今天的主角 |
|---|---|---|---|
| 并行采样 | Best-of-N / **Self-Consistency** 投票 | 无（纯内生） | ✅ |
| 顺序修订 | **Self-Refine / Critique-Revise / CoVe** | 可无可有 | ✅ |
| 树搜索 | ToT / MCTS / rStar（昨天） | verifier / value model | — |

前两格的特殊性：**零训练、零外部模型、纯 prompt 工程**——成本只有 token。但它们也共享同一个软肋，这就是今天的核心概念。

### Self-Consistency：多数投票的统计本质

> 📄 Wang et al., Google, 2022：《Self-Consistency Improves Chain of Thought Reasoning in Language Models》

**机制**：不用贪心解码，temperature 采样 N 条独立 CoT 路径，对**最终答案**做多数投票。GSM8K 上把 PaLM-540B 的 greedy CoT 从 56.5% 拉到 74.4%。

**为什么有效**：推理任务有一个好性质——**多条路径收敛同一答案**。数学题的"算出 42"可以从不同解法殊途同归；单条路径的采样误差在投票中被抵消。

**隐藏假设（必背）**：独立性。投票统计的全部合法性建立在"各路径错误互不相关"上。一旦错误是**系统性的**（知识缺陷、训练分布偏见），N 条路径会**一致地错**，投票只是把一个错误重复 N 次。这和 Day 117 Best-of-N 的"共享早期错误"是同一个坑。

**适用边界**：
- ✅ 答案空间有限、可精确比对（数学、逻辑、选择题式推理）——"多数答案"有定义；
- ❌ 开放生成（写邮件、写故事）——没有"多数段落"可投；
- ⚠️ 错误相关性高的问题（模型系统性偏见），增益远低于理论值。

**成本与改进**：
- 成本 = N × 单次推理（N 常见 8~40）；
- Day 115 的通过率公式 `1 − (1−p)^N` 在此正式上岗：独立假设下 N=8 能把 p=0.5 拉到 ~99.8%；但相关错误存在时增益**提前饱和**；
- **加权投票**：用 verifier 分数给路径加权（Fu et al. 的 inference scaling 系列），弱模型多采样 + 加权比强模型少采样更划算；
- **Early-Stopping SC**（Cheeseman et al., 2024）：不等采满——答案分布一旦稳定到统计置信（对比截断二项分布），提前停，实测省 ~40% 采样且精度不掉。**compute-optimal 思想（Day 115）在投票环节的落点**。

### Self-Refine / Critique-Revise：顺序修订循环

> 📄 Madaan et al., CMU + AI2, 2023：《Self-Refine: Iterative Refinement with Self-Feedback》

**机制**：生成 → 自我批评（critique）→ 修订（refine）→ 再批评，循环 1~4 轮。全程同一个模型，不训练、不挂外部反馈。Madaan 原文在对话回应、代码可读性、受限生成上报告了稳定提升。

**然后是一盆冷水（必背，面试杀手锏）**：

> 📄 Kamoi et al., 2024（TACL）：《When Can LLMs Actually Correct Their Own Mistakes?》

系统复盘 self-correction 文献后发现：**intrinsic self-correction（无外部反馈的纯自我修订）经常让成绩变差**。代表作数字：GSM8K 上 GPT-4 标准 CoT 约 95%，加上"请自我检查并修订"的 intrinsic 循环后掉到 82.9%——模型把自己对的改错的比例，高于改对的比例。机制：自评"**看起来对**"和"**真的对**"相关性很弱，修订方向不可靠。

**什么时候真有用（路由表）**：
- ✅ 回路里有**外部信号**：编译器报错、单测红灯、RM 打分、规则校验——批评有了锚点，修订有的放矢；
- ✅ 任务有**明确质量标准可分解**（"这段代码可读性差"可被模型自身部分评估）；
- ⚠️ 纯内生 + 精确答案任务：小心，实证常掉点；
- 💡 实操折中：让修订**带证据**（"指出第几步的哪个等式不成立"比"请检查一遍"有效得多）。

### 验证者悖论（今天的核心概念）

把前两节的隐忧说透，就是**验证者悖论（Verifier Paradox）**，三段式陈述：

1. **能力循环**：如果模型强到能可靠验出这个错误，为什么生成时会犯它？生成与验证共享同一套权重、同一个先验——出错的那一刻，往往也是"看不出错"的那一刻。
2. **独立性崩塌**：自评错误与生成错误**相关而非独立**——这直接击穿 Self-Consistency 的独立性假设（模型倾向认为"自己刚写的"是对的，self-preference bias：实证研究发现 LLM 评审系统性地偏爱自己的生成）。
3. **Goodhart 陷阱**：一旦自评分数进入训练信号（self-rewarding），优化压力会教模型"**看起来对**"而非"**对**"——验证器成了被狩猎的对象。

**两条工程出路 + 一条黑客路线**：

| 出路 | 做法 | 本周对应 |
|---|---|---|
| ① 外包给外部验证器 | 规则 / 代码执行 / PRM——验证与生成解耦，悖论直接消失 | Day 115 成本谱、Day 116 PRM |
| ② 把怀疑心训进权重 | RL 训练后自我检验行为**自发涌现**——R1 论文明确观测到模型学会"回头检查、推翻自己"，o1 长 CoT 里的自我纠正是内化搜索的副产品 | Day 115/117 内化路线 |
| ③ 换个实例互证 | 不让模型验自己，让**另一个实例**（或另一角色）提问互答——rStar 判别式互证 | Day 117 |

> 💡 ②的微妙之处值得单独说：悖论陈述的是**基座模型的内生意愿不可靠**，而 RL 后涌现的自检验恰恰说明"生成-验证"可以被训练**解耦**——能力仍是同一套权重，但行为分布里长出了"停下来复查"的动作。这是"悖论不是死局"的最强证据。

### Reflexion：把批评存进记忆（verbal RL）

> 📄 Shinn et al., 2023：《Reflexion: Language Agents with Verbal Reinforcement Learning》

**机制**：agent 失败后，用语言生成一段**文字反思**（"我刚才错在把 X 当成了 Y，下次应该先检查 Z"），存入情景记忆；下一次 trial 把历史反思拼进 prompt。循环 trial → reflect → retry。

- 为什么叫 verbal RL：trial-and-error 的循环结构是 RL 的，但"梯度"是文字——**语言化的经验更新**，零参数更新；
- 战绩：多步 agent 任务（ALFWorld、HotPotQA）上显著提升，HumanEval 报告 91% 档的 pass@1（GPT-4 配置）；
- 适用：**多轮交互、错误可诊断的任务**（agent 工具调用、交互式编程）；单轮一次性问答场景意义有限——没有"下一次 trial"就没有记忆价值。

### CoVe（Chain-of-Verification）：能直接抄的防幻觉实操

> 📄 Dhuliawala et al., Meta, 2023：《Chain-of-Verification Reduces Hallucination in LLMs》

**四步流水线**：
1. **起草**：正常生成初版回答（可能含幻觉）；
2. **出考题**：让模型针对回答里的**事实性声明**生成验证问题（"某电影的导演是谁？"）；
3. **独立作答**：关键设计——**不看初版回答**，独立回答每个验证问题（防止被自己的初稿锚定）；
4. **比对修订**：验证答案与初稿不一致处，修订输出。

实测事实性提升 20 个点档。**第 3 步的"独立作答"是全案精髓**：验证的独立性假设是被设计出来的，不是祈祷出来的——这正是对"验证者悖论"的工程回应。

### Self-Rewarding：把悖论工业化（高收益高风险的走钢丝）

> 📄 Yuan et al., Meta, 2024：《Self-Rewarding Language Models》

**机制闭环**：模型给自己的多个生成打 LLM-as-Judge 分 → 构造成对偏好（高分 vs 低分）→ DPO 迭代训练 → 模型变强，评审也"变强" → 再迭代。Week 17 的 DPO 引擎在这里复用（Day 111 伏笔回收）。

**收益**：三轮迭代在 AlpacaEval / MT-Bench 持续上涨，一度是"摆脱人工标注"的诱人路线。

**风险（与 GRPO 的对照是关键）**：
- 数学/代码：**能外包验证器就外包**（Day 112 GRPO 的可验证奖励原则）——精确、抗 hack；
- 开放任务：没有外部验证器，self-rewarding 是唯一选择，但自评偏差会被**训练放大**：每轮迭代都把"自己偏爱什么"固化一点，最终**分布坍缩**（输出越来越像模型自己的审美，多样性死亡）——reward hacking 的标准剧本；
- 所以工业界共识收敛为：**self-rewarding 可以起步，但长期天花板需要外部信号**（RLAIF 引入更强裁判、或混入人工/规则锚点）。

### 工程连环问速答模板

> **Q1：Self-Consistency 为什么有效？统计本质是什么？**
>
> 推理任务多条独立路径收敛同一答案，采样误差在多数投票中互相抵消。隐藏假设是**错误独立性**——系统性错误（知识缺陷、分布偏见）会一致地错，投票无效。适用前提：答案空间有限且可精确比对。

> **Q2：Self-Consistency 的通过率怎么估算？**
>
> 独立假设下 `pass@N投票 ≈ 1 − (1−p)^N`，p 是单路径正确率，对数增长——所以 N=4~16 之后收益骤降（Day 115 原话）。相关错误存在时增益提前饱和，且要付 N× 推理成本。改进：加权投票（verifier 分数加权）、Early-Stopping（分布稳定即停，省 ~40%）。

> **Q3：Self-Refine 什么时候有用、什么时候有害？**
>
> 引用 Kamoi et al. 2024：intrinsic self-correction（无外部反馈）在精确答案任务上常掉点（GSM8K 上 GPT-4 从 ~95% 掉到 82.9%）；有外部信号（编译器/单测/RM）时稳定有效。实操：让批评带证据——"指出第几步哪个等式错了"远好于"请检查一遍"。

> **Q4：什么是验证者悖论？怎么反驳它？**
>
> 三句：① 能验出错误为何还犯（生成与验证共享权重）；② 自评错误与生成错误相关，独立性假设崩塌（self-preference bias）；③ 自评进训练信号会被 Goodhart。反驳：外部验证器解耦（悖论消失于数学/代码）、RL 让自检验行为涌现（R1 实证：训练后模型学会回头检查——悖论描述的是基座意愿，不是训练后能力）、互证换实例（rStar）。

> **Q5：CoVe 怎么做？关键设计是什么？**
>
> 起草 → 生成验证问题 → **独立作答**（不看初稿，防锚定）→ 比对修订。精髓是把投票/验证的独立性假设**用流程设计出来**而不是祈祷出来。

> **Q6：Reflexion 和 Self-Refine 什么关系？**
>
> Self-Refine 是单轮内的"批评-修订"循环（同一份输出反复打磨）；Reflexion 是**跨轮**的"试错-反思-记忆"循环（把文字反思存下来指导下一次尝试，verbal RL）。前者改稿子，后者攒经验；Reflexion 的价值随 trial 次数累积，适合 agent 多步任务。

> **Q7：Self-Rewarding 和 GRPO 怎么选？**
>
> 能验证的（数学/代码/规则可判）→ GRPO + 外部奖励，别用自评；不能验证的（开放生成）→ 才考虑 self-rewarding（LLM-as-Judge 造偏好对 + DPO 迭代），但必须警惕分布坍缩，混入外部锚点。一句话：**验证能外包就外包，不能外包的用 RL 把怀疑心训进权重，最后才轮到自评**。

> 💬 **收尾金句**："验证者悖论不是劝退书，是路由表——能外包给规则与执行的验证，绝不外包给模型自己；验证外包不掉的，用 RL 把怀疑心训进权重；实在要自己验自己的，至少换一个实例来问。**怀疑自己是能力，但前提是你先被训练成会怀疑。**"
