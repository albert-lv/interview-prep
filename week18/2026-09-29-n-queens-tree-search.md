## 1) 今日算法题

### N 皇后（N-Queens）

**题意**：将 `n` 个皇后放在 `n × n` 的棋盘上，使得任意两个皇后**不在同一行、同一列、同一条对角线上**。返回**所有**可行的摆放方案（每种方案用 `Q` 和 `.` 表示棋盘布局）。

```
输入: n = 4
输出: [[".Q..","...Q","Q...","..Q."],
       ["..Q.","Q...","...Q",".Q.."]]
解释: 4 皇后恰有 2 种解，两种互为镜像。
```

**关键约束**：`1 <= n <= 9`。约束小，但面试考察点是**问题建模**和**剪枝设计**，不是 AC。

### 思路：按行决策 + 三向冲突检查 = 把约束变成廉价评估函数

N 皇后最容易走弯路的写法是：枚举每个格子放/不放（`O(2^(n²))`，搜索树直接爆炸）。正确建模是：

> **一行必有且仅有一个皇后**（这是约束本身，不是推论）。所以搜索树的每一层就是"第 row 行放哪一列"，决策变量从 n² 个格子压缩成 n 行的各一次列选择，搜索空间从 `2^(n²)` 砍到 `n!`。

**回溯框架（三件套）**：

1. **逐行放置**：第 `row` 行逐列尝试，合法性检查通过才进入下一行递归。
2. **三向冲突 = 三个 O(1) 评估函数**：
   - 列冲突：`cols[col]` 是否已占用；
   - 主对角线（↘）：`row - col` 是恒定值，键范围 `-(n-1) ~ n-1`，整体偏移 `+n-1` 做数组下标；
   - 副对角线（↙）：`row + col` 恒定，键范围 `0 ~ 2n-2`。
   三个布尔数组（或一个 set）进背包，进入子树**前**检查——非法分支在 O(1) 内被剪掉。
3. **路径记录 + 退出撤销**：`cols[row] = c` 记录选择，递归返回后不撤销（下一行会覆盖）但需把三个冲突标记复位——回溯的呼吸，和数独的 `&^=` 撤销同款直觉。

> 🧬 **和今日主题的连接**：三个冲突检查就是这套搜索的**价值评估函数**——廉价（O(1)）、精确（零误判）、前置（扩展前先剪）。树搜索的效率公式就藏在这道题里：**总成本 ≈ 节点数 × 每节点评估成本**，评估越便宜越准，树越小。ToT/MCTS 的一切工程优化（value model、PRM、互证）本质上都是在造更好的"对角线检查"。

### 代码

**Go（回溯 + 三个布尔数组，面试标准答案）：**

```go
func solveNQueens(n int) [][]string {
    cols := make([]bool, n)        // 列占用
    diag1 := make([]bool, 2*n-1)   // 主对角线 r-c+n-1
    diag2 := make([]bool, 2*n-1)   // 副对角线 r+c
    queens := make([]int, n)       // queens[r] = 第 r 行皇后所在列
    var res [][]string

    var backtrack func(row int)
    backtrack = func(row int) {
        if row == n { // 所有行放置完毕 —— 收集一个完整方案
            board := make([]string, n)
            for r := 0; r < n; r++ {
                line := make([]byte, n)
                for c := 0; c < n; c++ {
                    if queens[r] == c {
                        line[c] = 'Q'
                    } else {
                        line[c] = '.'
                    }
                }
                board[r] = string(line)
            }
            res = append(res, board)
            return
        }
        for c := 0; c < n; c++ {
            // 三向冲突 = O(1) 廉价评估，先剪枝后扩展
            if cols[c] || diag1[row-c+n-1] || diag2[row+c] {
                continue
            }
            queens[row] = c // 进入：标记路径
            cols[c], diag1[row-c+n-1], diag2[row+c] = true, true, true
            backtrack(row + 1)
            cols[c], diag1[row-c+n-1], diag2[row+c] = false, false, false // 退出：撤销
        }
    }
    backtrack(0)
    return res
}
```

**Python（位运算版，Follow-up N 皇后 II 的直接复用）：**

```python
def solveNQueens(n: int) -> list[list[str]]:
    res = []
    queens = [-1] * n
    full = (1 << n) - 1                 # n 个 1，低位代表可放的列

    def bt(row: int, cols: int, diag1: int, diag2: int):
        if row == n:
            res.append(["." * c + "Q" + "." * (n - 1 - c) for c in queens])
            return
        avail = full & ~(cols | diag1 | diag2)   # 当前行所有合法列（O(1) 三向评估）
        while avail:
            lowbit = avail & (-avail)            # 取最低位的合法列
            avail &= avail - 1                   # 移除该候选
            queens[row] = lowbit.bit_length() - 1
            # 进入：位图传参天然"进标记"（新掩码），返回后参数弹栈天然"退撤销"
            # diag1 << 1 / diag2 >> 1：对角线冲突随下一行平移
            bt(row + 1, cols | lowbit,
               (diag1 | lowbit) << 1, (diag2 | lowbit) >> 1)

    bt(0, 0, 0, 0)
    return res
```

> 💡 **位运算版精髓**：`diag1 << 1`、`diag2 >> 1` 把对角线冲突"平移"到下一行——对角线天然带行位移，位运算把坐标换算变成了移位操作；递归参数传新掩码，进标记/退撤销由函数栈天然完成，连回溯撤销代码都省了。N 皇后 II（只求方案数）用它三行核心代码，竞赛级解法。

**复杂度**：
- 时间：`O(N!)` 上界（第 row 行最多 `n - row` 个合法选择，`n × (n-1) × … × 1`），剪枝后实际远小于此；`n = 9` 时方案数 352 种，回溯秒过。
- 空间：`O(N)` 递归栈 + `O(N²)` 输出。

### 面试官连环问

> **Q1：为什么不枚举格子放/不放？**
>
> 一行必有且仅有一个皇后，这是约束本身。按行枚举把决策变量从 n² 压到每行一个列选择，搜索空间从 `2^(n²)` 变 `n!`——**问题建模决定搜索树形状**，这是所有搜索题的第一课。

> **Q2：对角线冲突怎么 O(1) 判断？**
>
> 主对角线 `r - c` 恒定、副对角线 `r + c` 恒定，两个键进哈希集合或布尔数组。位运算版用 `<<1 >>1` 平移，连数组下标换算都省了。

> **Q3：N 皇后 II 只求个数，还能更快吗？**
>
> 位运算状态压缩版：`avail = full & ~(cols|diag1|diag2)`，lowbit 枚举合法列，三行核心代码。极限优化可用对称性剪枝（第一行只搜左半边，结果 ×2），N=15 也能秒出。

> **Q4：能不能并行化？**
>
> 第一层按列切分：第 0 行放第 c 列的搜索子树彼此独立，开 n 个 goroutine/线程各算各的，最后归并。回溯的层间独立性是天然的并行入口。

> **Q5：和数独的回溯有什么区别？**（Day 115 送过分）
>
> 数独是"空洞填充"，决策位置不固定，需要 MRV 选最少候选的空格；N 皇后是"逐行强制决策"，每层决策变量固定，分支因子天然递减，不需要启发式选点。

> **Q6：推广一下——n 皇后解的数量增长多快？**
>
> 超指数级增长（n=8 是 92，n=9 是 352，n=14 是 365596），没有已知闭式公式。N > 20 的现实解法用 SAT/SMT 求解器或局部搜索（min-conflicts 算法，几乎线性时间），不是回溯。

> 💬 **收尾一句话**：N 皇后教的不是回溯，是"**先把约束翻译成廉价评估函数，再让搜索树长在评估函数的肩膀上**"——这就是今天 ToT/MCTS/rStar 的全部工程哲学。

## 2) 面试技巧：推理树搜索三件套（ToT / MCTS / rStar）

### 为什么 CoT 不够？—— 从贪心解码到搜索

先把 Week 18 的大图景收拢成一句话：

| 范式 | 决策结构 | 中途纠偏 | 代表 |
|---|---|---|---|
| CoT | 单链贪心 | ❌ 一步错步步错 | 标准 prompting |
| Best-of-N / Self-Consistency | 并行采 N 条完整链，事后投票 | ❌ 只能事后挑，不能中途救 | Day 115 |
| Self-Refine / Critique-Revise | 顺序修订，迭代改稿 | ⚠️ 能改但无分支探索 | Day 118 预告 |
| **树搜索（今天）** | 每步多候选 + 评估 + 回溯 | ✅ 推理中途可分叉可回头 | ToT / MCTS / rStar |

CoT 的失败模式是 **error compounding**：第 3 步算错，后面 12 步全是在错误地基上盖楼。Best-of-N 的失败模式是**无法中途纠偏**——N 条链共享同一个早期错误时，投票只是"一致地错"。树搜索把"回答生成"重构为"状态空间搜索"：每个中间推理状态是节点，每个候选下一步是边，评估函数（PRM！Day 116）是 value——于是搜索算法的全部家当（剪枝、启发式、回溯）都能用上。

### ToT：Tree of Thoughts（2023.05，Yao et al.）

> 📄 《Tree of Thoughts: Deliberate Problem Solving with Large Language Models》

**核心思想**：CoT 把"思考"退化成一句话接一句话的序列生成；ToT 把思考升级成**树**——允许模型在每个推理节点生成多个候选思路、评估它们、选择最有希望的分支深入，并**回溯**。

**四个标准操作（面试要会默写）**：

1. **分解（Decompose）**：把问题切成中间"思路单元"（thought）——一步算术、一段论证、一个草稿段落。粒度是关键设计参数：太细评估噪声大，太粗等于没分解。
2. **生成（Generate）**：对每个节点，让 LLM 采样 `k` 个候选下一步（k 通常 3~5）。
3. **评估（Evaluate）**：对每个候选中间态打分——LLM 自评（"这个思路 1-10 分"）、多数投票、或调用独立 verifier / PRM。**评估器是 ToT 的命门**：垃圾评估 = 垃圾剪枝 = 更贵的错误。
4. **搜索（Search）**：BFS（层扩展 + beam 保留 top-k 节点）或 DFS（深搜到底，失败回溯换兄弟分支）。

**经典战绩**：24 点游戏（每步"用两个数凑出一个中间结果"是天然 thought 单元）、创意写作（段落级分支 + 全局规划）、迷你填字游戏。

**三大局限（面试加分项）**：
- 评估器可被 hack：LLM 自评"感觉良好"和"真的正确"相关性有限；
- 开销爆炸：每节点 k 个候选 × 每候选一次评估，token 成本是 CoT 的 10~50 倍；
- 框架脆弱：分解方式和评估提示词高度任务相关，换一个任务要重新调prompting。

### MCTS：蒙特卡洛树搜索 + LLM 化改造

> 🎯 经典 MCTS 出身 AlphaGo，LLM 推理时代被重新激活：它不是新算法，是**给 ToT 装上统计直觉**。

**经典四步循环（必须默写）**：

```
1. Selection（选择）：从根出发，用 UCB1 反复选最优子节点，直到到达可扩展叶子
      UCB1(s,a) = Q(s,a) + c · √( ln N(s) / N(s,a) )
      └ Q：平均回报（利用）   └ 访问次数少的加分（探索）
2. Expansion（扩展）：给该叶子添加若干子节点（LLM 场景 = 采样 k 个候选 thought）
3. Simulation/Rollout（模拟）：从子节点随机走到终局，得到回报
4. Backpropagation（回传）：把回报沿路径回传，更新沿途每个节点的 Q 和 N
```

重复 N 次迭代后，选访问次数最多（或 Q 最高）的根节点动作输出。

**LLM 化改造的四个关键问题**（面试连环问重灾区）：

| 经典 MCTS | LLM 推理版改造 |
|---|---|
| 动作空间 = 围棋落子 | 动作 = 一次 thought 生成（连续空间离散化：采样 k 个候选） |
| Rollout = 随机下棋到终局 | 完整 rollout 太贵（多轮自生成 + 终局验证），改为 **value model 单点估计**或 **短程 rollout + PRM 打分**（Day 116 的过程验证器在这里正式上岗） |
| 选择纯靠 UCB 统计 | 加 **LLM 先验**：pUCT（AlphaZero 式）`Q(s,a) + c·P(s,a)·√(ΣN)/(1+N(s,a))`，P 由 policy 模型给出——统计探索 + 语义先验双轮驱动 |
| 回传奖励 = 胜负 | 奖励 = verifier 终局判定（数学 boxed 答案 / 代码单测）+ 中间 PRM 塑形 |

**成本-质量权衡三档**（必背）：
- **完整 rollout 到终局**：准，但一次模拟 = 几十次 LLM 调用，贵到心碎；
- **value model 单点估计**：便宜（一次前向），但估值偏差直接决定剪枝质量；
- **短程 rollout + PRM 打分**：折中主流——展开 2~3 步看趋势，用过程验证器打分，成本约为完整 rollout 的 1/10。

### rStar：免训练 verifier 的互证路线（2024.07，Microsoft Research）

> 📄 《rStar: Mutual Reasoning Makes Smaller LLMs Stronger Problem-Solvers》

**核心洞察**：ToT/MCTS 的瓶颈卡在**评估器从哪来**——训练 value model / verifier 需要数据和算力，小厂小模型玩不起。rStar 的回答很黑客：**让模型自己互证**。

- **两个角色互问互答**：Generator（生成器）用 MCTS 展开推理树，每步产生候选；Discriminator（判别器）对每一步发起**判别式问答**——"这一步用了什么定理？""上一步到这一步哪里变了？"答得自洽才算过。
- **互证一致性 = 伪 reward**：不训练任何 verifier，用"两个独立采样视角对同一推理过程说法一致"作为该分支可信度的代理信号。
- **效果**：数学推理上让 Mistral-7B 级别的模型逼近 GPT-4 水平（当时的对比基准）——证明 test-time compute 对**小模型收益更大**（大模型自己已经"内化"了不少搜索能力，小模型外挂搜索的边际收益更陡）。

### 三范式终极对比表（面试收尾话术）

| 维度 | ToT | MCTS | rStar |
|---|---|---|---|
| 搜索骨架 | BFS/DFS + beam | 四步循环 + UCB | MCTS（复用） |
| 评估器 | LLM 自评/投票（脆弱、免费） | value model / PRM / rollout（贵、准） | **判别式互证**（免费、中准） |
| 训练成本 | 零 | 高（verifier/policy） | 零 |
| 开销 | 中 | 高（迭代次数 × 每迭代评估） | 中高（双倍生成） |
| 适用 | 任务结构清晰、thought 易定义 | 可验证奖励场景（数学/代码/棋类） | verifier 冷启动难的场景 |
| 致命伤 | 评估器被 hack | 延迟爆炸 + value 偏差 | 互证可能"合谋一致地错" |

### 与 RL 的飞轮（把 Week 17 和今天焊上）

Day 114 自博弈埋的伏笔今天收线：**AlphaZero 的循环 = self-play 生成棋谱 → MCTS 改进走法 → 改进策略回灌训练 → 更强的 policy/value → 更强的 MCTS**。MCTS 和 RL 是双轮驱动：搜索产生更好的训练数据，训练产生更好的搜索先验。

而 o1/R1 选择了更激进的路线：**不外挂搜索框架，用 RL 把"搜索能力"内化进模型权重**——长 CoT 里的自我试错、回头检查、"aha moment"，本质上是模型在隐式地做树搜索。路线之争一句话：**外挂搜索（显式树、可控、贵）vs 内化搜索（隐式树、优雅、不可控）**。工业界两条都在走：推理框架侧挂 MCTS（可控性好），训练侧 RL 冲长推理（o1/R1 路线）。

### 工程连环问速答模板

> **Q1：ToT 和 CoT 的本质区别？**
>
> CoT 是贪心单链（序列决策，无回溯）；ToT 是把生成重构为状态空间搜索（每步多候选 + 评估 + 回溯）。一句话：**CoT 是写一步看一步，ToT 是想三步走一步。**

> **Q2：ToT 的评估器有哪三条路？各自死穴？**
>
> LLM 自评（免费但可被"言之凿凿地错"hack）、多数投票（只能用于可分解为有限选项的判断）、训练 verifier（贵但准，和 PRM800K 一个味）。死穴统一指向 Goodhart：评估器一旦成为优化目标就会被针对。

> **Q3：MCTS 四步循环 + UCB 公式各项含义？**
>
> Selection（UCB1 选子：Q 利用 + `c·√(lnN/N_a)` 探索）→ Expansion（扩展子节点）→ Simulation（rollout 得回报）→ Backpropagation（沿路径回传更新 Q、N）。c 控制探索强度，lnN 让访问越多的父节点越鼓励尝试新分支。

> **Q4：LLM 场景 Simulation 怎么做？**
>
> 三档：完整 rollout 到终局（贵、准）；value model 单点估计（便宜、有偏）；短程 rollout + PRM 打分（折中主流）。考的是成本-质量权衡意识——**test-time compute 的每一个 FLOP 都要算账**。

> **Q5：为什么 o1/R1 不直接外挂 MCTS 框架？**
>
> 工程延迟：MCTS 每次迭代 = 多次 LLM 调用 + 多次 verifier 评估，TPOT 爆炸，用户体验不可接受；泛化性：显式树绑死任务分解方式，换任务重调。所以 o1 走内化路线——RL 训练让模型在长 CoT 里隐式搜索，把框架焊进权重。

> **Q6：rStar 为什么能让小模型变强？**
>
> 把"验证"从训练昂贵 verifier 换成"另一个 LLM 实例的判别式问答"，互证一致性当信号——绕过 reward model 冷启动。另一个洞察：**test-time compute 对小模型边际收益更大**，因为大模型已内化搜索能力，小模型外挂搜索从低基线起飞。

> **Q7：搜索和采样怎么选？**
>
> 可分解为多步决策 + 可验证终局 → 树搜索（MCTS 系）；单步生成质量决定一切 / 延迟敏感 → Best-of-N 并行采样；需要多轮打磨而非分支探索 → Self-Refine。判断口诀：**中途有可评估的岔路才值得建树。**

> 💬 **收尾金句**："CoT 是单线程 DFS，ToT 是带评估的 BFS，MCTS 是带统计直觉的搜索，而 o1 是把搜索焊进权重里——四代范式，一个追求：让模型在回答之前，先学会犹豫。"
