## 一、今日算法题：双指敲击键盘的最小代价（LC 514 变种 · Freedom Trail with Two Fingers）

### 题目

环形键盘上有 26 个小写字母（`a`→`z` 顺时针围成一圈，相邻距离 1，`a` 与 `z` 相邻）。你可以用**两根手指**打字：初始时两根手指可以放在**任意**键上（**免费**，不计时间）。输入单词 `word` 时，每次「把某根手指移到目标键 + 敲下」耗时 = 移动距离（环上最短，可顺/逆时针）+ 1（敲下）。**求打完整个单词的最小耗时**。

```
示例 1: word = "jazz"  → 答案 5
示例 2: word = "daq"   → 答案 6
示例 3: word = "helloworld" → 答案 39
```

> 本题是 LC 514 的经典变种：原题是单指转动 + 按按钮（转一格 1 步、按下 1 步分开计），变种为双指 + 移动与敲击合并计。**原题号用于定位难度，变种才是工程模型的形状。**

### 为什么是这道题（工程映射）

今天是长时程 Agent 工程的 Day 1，主角是**状态持久化与 checkpoint**。双指打字是「最小化状态迁移成本」的裸机模型：

- 每敲一个字符 = 一次**状态迁移**（DP 转移），总耗时 = 全链路的迁移成本之和；
- 手指的**初始位置免费** = 系统冷启动恢复「零状态」不收费；
- 刚敲完字符的那只手指 = **活跃状态**（当前 Worker）；闲置在 j 的手指 = **影子 checkpoint**（保存完整上下文、随时可被换回）；
- **换手指 = 任务切换**：代价是 checkpoint 与活跃状态之间的距离（不是历史的函数——Markov！）。

### 核心思路

**第一步：免费起点。** 手指初始任意放置免费 ⟹ 第一个字符永远成本 1（免费放置 + 敲一下），闲置指放哪都行。若两个首字符由不同手指敲，第二只手指放过去敲也只需 1。

**第二步：状态压缩（本题灵魂）。** 打完前 i 个字符后，刚敲的键 `word[i-1]` 上必然停着一根手指。所以**只需记录另一根手指停在哪个键 j**：

```
f[j] = 打完 word[0..i-1] 后，敲击指在 word[i-1]、闲置指在 j 的最小耗时
```

朴素状态是 (两根手指位置) × 步数 = 26²×n；压缩后 = 26×n，滚动数组只需 **O(26)** 空间。

**第三步：转移（两种决策）。** 敲第 i 个字符 cur（prev = word[i-1]）：

```
① 敲击指（在 prev）移过去敲：
   g[j] = f[j] + d(prev, cur) + 1            —— 对所有 j 向量加，O(m)

② 闲置指（在 j）移过来敲：
   新状态 = (敲击指在 cur, 闲置指在 prev)
   g[prev] = min( g[prev], min_j f[j] + d(j, cur) + 1 )   —— O(m) 求 min
```

注意②里的「换指」落地后，闲置指的位置不再是 j 而是 prev——**这正是状态压缩省掉一维的原因**：我们不需要枚举「哪根手指在哪」，只需跟踪「敲击指锚定刚敲的字符，闲置指在哪」。

**最终答案** = min_j f[j]。

### Go 实现（已对拍验证）

```go
package main

import "fmt"

const M = 26
const INF = 1 << 30

// 环形距离：顺/逆时针取小
func dist(a, b int) int {
	d := a - b
	if d < 0 {
		d = -d
	}
	if M-d < d {
		return M - d
	}
	return d
}

// 双指打字最小耗时：O(n·M) 时间，O(M) 空间
func minTime(word string) int {
	n := len(word)
	w := make([]int, n)
	for i := 0; i < n; i++ {
		w[i] = int(word[i] - 'a')
	}
	// 初始：w[0] 由免费放置的敲击指敲下（移动 0 + 敲 1 = 1），闲置指任意位置免费
	f := make([]int, M)
	for j := 0; j < M; j++ {
		f[j] = 1
	}
	for i := 1; i < n; i++ {
		prev, cur := w[i-1], w[i]
		g := make([]int, M)
		// ① 敲击指（在 prev）移过去敲：所有 j 向量加
		step := dist(prev, cur) + 1
		// ② 闲置指（在 j）移过来敲：新状态 (cur, prev)
		best2 := INF
		for j := 0; j < M; j++ {
			g[j] = f[j] + step
			if c := f[j] + dist(j, cur) + 1; c < best2 {
				best2 = c
			}
		}
		if best2 < g[prev] {
			g[prev] = best2
		}
		f = g
	}
	ans := INF
	for j := 0; j < M; j++ {
		if f[j] < ans {
			ans = f[j]
		}
	}
	return ans
}

func main() {
	fmt.Println(minTime("jazz"))       // 5
	fmt.Println(minTime("daq"))        // 6
	fmt.Println(minTime("helloworld")) // 39
	fmt.Println(minTime("zzzz"))       // 4
}
```

> ✅ 本实现与暴力记忆化搜索（状态 = (步数, 指1位置, 指2位置)，初始任意放置）在 2000 组随机样例（长度 1–6，字母表 abcdfgz）上全部一致。

### 复杂度

- 时间 **O(n·m)**（26 键即 O(26n)）—— 状态压缩 + 每步转移 O(m) 向量操作；
- 空间 **O(m)** 滚动数组。
- 对比朴素双指 DP O(m²·n)：压缩的关键不变量——**每步打完，必有一根手指在刚敲的字符上**。

### 手算验证（"jazz" → 5）

| 步 | 敲 | 手指安排 | 累计 |
|---|---|---|---|
| init | j | 指A 免费放到 j 敲下（移动 0 + 敲 1） | 1 |
| 1 | a | 指B 免费放到 a 敲下（移动 0 + 敲 1） | 2 |
| 2 | z | 指B：a→z 环形距离 1（a-z 相邻！）+ 敲 1 | 4 |
| 3 | z | 指B 原地再敲 z（移动 0 + 敲 1） | **5** |

`"daq"` → 6 的路径同理：指B 免费放 q 等着；指A 敲 d（1）→ 移到 a 敲（d→a 距离 3 + 1 = 4，累计 5）→ 指B 在 q 原地敲（1）= 6。**「影子手指提前放在未来要敲的键上」正是 checkpoint 预置的影子状态。**

### 进阶阶梯六连

1. **m 键一般化**（ring 是任意字符串，含重复字符）→ 位置版 DP：敲击指维度从「字符」变「该字符的所有下标」，`f[iIdx][j]`，状态数 O(n·m²)。重复字符的本质：**同一个字符有多个可达状态，取 min**——checkpoint 可以有多个等价物理位置，恢复选最便宜的。
2. **三根手指** → 状态 `f[i][j][k]`（敲击指锚定 + 两根影子），O(n·m²) 状态 O(m) 转移... 能写完但工业界不用：**影子状态一多，精确 DP 原地爆炸**。工程答案：贪心/近似（永远把「影子」放在最近用到的字符上）—— **k 指问题 = 恢复点数量与恢复成本之间的权衡，精确解不可扩展 ⟹ 近似策略**。这是面试里「诚实」的标准答案。
3. **迁移成本非对称**（顺时针便宜 1、逆时针贵 2；或 CPU 重算便宜、状态搬运贵）→ **DP 框架不变，只换 d()**：`d(a,b) = min(顺×w₁, 逆×w₂)`。一句话：**状态机是骨架，成本模型是血肉**——骨架对了，成本模型随业务换。
4. **设计题：给「影子指」加 K 个休息位**（K 个影子 checkpoint）→ 状态 `f[i][j₁..j_K]` = O(n·mᴷ)：精确 DP 直接指数爆炸。工程答案：**事件溯源日志替代影子状态**——不快照 K 个状态，记「从状态 A 到 B 的事件流」，恢复时重放（DeepSeek 的会话状态存数据库 = 全量快照路线；Trigger 事件流 = 日志路线；混合 = 快照 + 增量日志）。
5. **恢复点校验和**：恢复时若发现 checkpoint 校验和不对（磁盘坏/被篡改）→ **回滚到上一个合法恢复点并记审计事件**（Day 151 哈希链同款）。DP 层面不变，工程层面这是「可信恢复」的底线。
6. **逆向问法**：「至少卡住多少键才能让输入不可能的按键数最少」→ 最小化「移除键位」= 图上的最小割/关键路径变体——把「打字」题翻过来看就是「破坏」题：系统鲁棒性 = 对偶问题。

### 工程读法：两根手指 = 活跃状态 + 影子 checkpoint

把 DP 映射到长时程 Agent 系统，每一行都是一句工程原则：

| DP 概念 | Agent 系统对应 | 工程原则 |
|---|---|---|
| 手指 = 执行体，位置 = 状态 | Worker 及其会话上下文 | 状态与执行者一一对应 |
| 敲击指在 `word[i-1]` | 活跃执行状态（当前 Worker） | 永远只有一个「当下」 |
| 闲置指在 j（影子） | 挂起任务的 checkpoint 句柄 | **影子状态随时可被换回** |
| 换手指 = d(j, ch) | 任务切换 = 状态迁移成本 | 迁移成本 = 上下文距离，**与历史无关（Markov）** |
| 初始位置免费 | 冷启动从零状态开始免费 | 空状态恢复代价 ≈ 0，起始点自由选 |
| `f[j]` 只需两位置 | checkpoint 必须自包含 | **恢复不需要重放历史 = 好的 checkpoint** |
| 决策①② = 续 or 换 | 推进活跃任务 or 恢复挂起任务 | 状态机的每一次转移都是这笔账 |

Markov 性质那句值得单独背：**迁移成本只看两个位置，不看中间隔了多少步**——正是存算分离的动机：恢复 Worker 只取它的持久化上下文 + 当前位置，与它跑了多少轮无关。

## 二、面试技巧：长时程 Agent 工程 · 状态持久化与 checkpoint

### 1. checkpoint 五问（被问「怎么让 agent 跑 3 天无人值守」时的答题骨架）

**Q1 存什么？** 按「重放成本」分三类：
- **事件溯源日志（event log）**：用户消息/工具调用/工具返回/模型决策 + 每条的事件 ID、时间戳、trace-id——**黄金真相源**，append-only（Day 149 哈希链同款防篡改）；
- **周期快照（snapshot）**：会话完整上下文 + KV cache 引用 + 任务内局部变量——**恢复加速点**，代价 O(context)；
- **派生状态（derived）**：可重建的索引/缓存（embedding 向量库、检索缓存）——**根本不用存，丢了重建**。
口诀：**事件必须存、快照选着存、派生绝不存。**

**Q2 粒度？** 细（每步）vs 粗（每任务）的老问题。工程答案：**分层 checkpoint**——step 级只进日志（写放大低、恢复贵）；task 边界或 token 阈值处打快照（写放大高、恢复便宜）；临界操作（支付/发布/外部写）强制快照。粒度由「恢复时间目标 RTO」和「可承受丢失量 RPO」反推，不是拍脑袋。

**Q3 怎么恢复才安全（副作用重放）？** Agent 的副作用 = 工具调用。被 kill 在中途的经典解法两板斧：
- **outbox 模式**：意图先落日志再执行，恢复时逐条比对「日志标记完成？」 vs 「副作用真的发生没？」（对账状态机：completed / unknown / confirmed-failed）；
- **幂等键**：每个外部调用挂 idempotency key（Day 150 三件套），重放不产生重复扣款/重复发帖。
一句话：**先记日志再动手，恢复 = 对账，不是重跑。**

**Q4 版本兼容？** checkpoint 带 `schema_version`（Day 149 消息军规同款）：信封 = `{version, created_at, task_id, model, snapshot_hash, event_cursor}`。升级后旧 checkpoint 走迁移链或降级读，迁移失败进隔离区 + 人工处理 + 记审计事件——**恢复路径必须和部署流水线一样被测试**。

**Q5 成本？** checkpoint 写放大三来源：全量上下文每次 O(context)（解决：增量快照/dedup/只存 diff）、高频快照 IOPS（解决：分层）、快照与日志双写的存储膨胀（解决：快照只存指针 + 事件游标，底层日志生命周期管理）。**账单：快照写成本 × 频率 vs 恢复时重放成本 × 频率——取交点。**

### 2. Watchdog 为什么是「外部」控制回路（DeepSeek 原话级考点）

DeepSeek 的设计哲学：**「持久在线的分布式系统很难仅靠主系统内部逻辑保证长期可靠运行，需要在主系统之外引入独立的外部控制回路。」** 三层递进：

1. **主系统内自愈 = 悖论**：判断「自己是否正常」的判断器如果坏了呢？（Gödel 式自指——面试加分术语：**observer 不能观察自己**）
2. **K8s liveness 不够**：进程活着 ≠ 任务在进展。**基建活性（liveness）≠ 语义进展（progress）**——vLLM 92 字节请求：进程健康、调度卡死、/health 全绿（Day 147）。
3. **DeepSeek Watchdog 的具体形态**：独立监控实体 + 独立上下文 + 不共享主系统的判断链条，盯三件事：**任务是否取得进展、是否陷入无效循环、是否偏离目标**——发现异常「尝试介入修复」。

面试时把这句话说完整：**Watchdog 的价值不在于它更聪明，而在于它不在你监控的那套逻辑里。**

### 3. 无进展即停：分层活性检测（liveness ≠ progress）

| 层 | 探针 | 抓什么 | 盲区 |
|---|---|---|---|
| L0 进程 | heartbeat / 容器探针 | crash | 活着但卡死（92 字节请求） |
| L1 活动 | 事件循环 tick / 队列消费计数 | 事件饥饿、死锁 | 空转（spinning） |
| L2 语义进展 | 任务状态机推进 / 中间产物产出 | **无效循环、偏离目标（DeepSeek 无效循环检测）** | 进展太慢（阈值调参） |

**L2 是长时程 agent 的分水岭**：Loop 检测信号 = 工具调用序列重复（哈希指纹）、连续动作语义去重、token 斜率异常（Day 146 成本基线安全版）、写频异常（Day 149）。**L0-L1 全绿 + L2 红 = Agent 系统最典型的故障形态**——面试官就是等着你说出这句。

### 4. 恢复三板斧（escalation ladder）+ 恢复动作必须可观测

三级渐进，预算制（每任务每周期恢复次数上限 + 熔断）：

1. **NUDGE**：Watchdog 经 Router 注入提醒（「请汇报当前进展」）——最便宜，常常够；
2. **CHECKPOINT-RESTART**：强制快照当前状态 → 重启 Worker 上下文（清掉污染/循环），从最近的干净 checkpoint 继续——**清循环不丢进度**；
3. **CANCEL & REASSIGN**：取消任务、从事件日志重派新 Worker——**最后手段，旧路径进失败样本库**。

纪律：**恢复动作本身是一等公民事件**（记日志、可审计、可回放）；恢复后的失败模式进混沌注入库（Day 151）；**紧急停止（kill switch）与自动恢复是两条独立链路**——自动恢复越激进，kill switch 越要独立 + 定期演练（OpenAI 9·20 教训：flag 了没刹住）。

### 5. 事件流可观测三指标（订阅/直通/批处理的运营账本）

DeepSeek 文章给了三组现成的数字：

- **Router 决策频率**：取消直通 +30% → 直通占比 = 事件路由健康度指标；
- **缓存读取 token 量**：2323 万 → 3177 万（+37%）→ **路由拓扑直接进账单**；
- **批处理大小分布**：积压越多单决策成本越低，但注意力稀释 + 上下文长度是上限 → 批大小分布要进监控大盘。

配套指标组：**任务完成时间分布（p50/p95）**（DeepSeek 的 p50 12.4 / p95 15.7 min vs 传统 29.5 min 就是标准报告格式）、**恢复事件计数（按类型分桶）**、**loop 检测命中率/误报率**。

### 6. 模拟面试速答五连

**Q1 设计一个能无人值守跑 3 天的 agent 系统的 checkpoint 策略。**
骨架：事件溯源日志（append-only + hash 链）+ task 边界快照 + 临界操作强制快照（RPO/RTO 反推粒度）+ outbox 对账恢复 + idempotency key 重放 + schema_version 信封 + 快照成本 × 频率 vs 重放成本 × 频率取交点。提 DeepSeek：存算分离 = 参考实现。

**Q2 DeepSeek 的 Watchdog 和 K8s liveness probe 有什么区别？**
K8s 探进程活没活；Watchdog 探任务有没有进展——agent 最常见的死法是**活着但空转**（无效循环/偏离目标）。且 Watchdog 是**主系统之外**的独立控制回路（observer 不自观），介入修复 ≠ 自动决策，恢复三板斧 + 恢复动作可观测。

**Q3 agent 执行到一半进程被 kill，外部副作用已经发生一半，怎么恢复？**
先查 outbox（意图日志）→ 重放未确认事件时带 idempotency key → 三方对账（工具侧/日志/agent 台账）标记 completed/unknown → unknown 逐条人工或 verifier 仲裁 → 恢复后把「哪条事件卡在 unknown」写进混沌注入库。

**Q4 DeepSeek 的 Trigger 批处理会不会丢事件？**
设计上不会：积压不是丢弃而是**合并注入下一轮**——合并进同一次 prefill 并行计算，单个请求耗时增长远慢于批大小；风险在注意力稀释 + 上下文上限（能说出的两个上限 = 加分）。配套：积压超过水位就扩容/降级，批大小分布进监控。

**Q5 不用另一个 agent 盯着，怎么低成本检测长任务「无效循环」？**
三层：结构（工具调用序列哈希指纹/连续动作重复度）→ 统计（写频、token 斜率、错误率 vs 基线偏离）→ 语义（Router 定期要求 Worker 汇报中间产物，看产物是否「换了但没前进」）。再不行注入 nudge 看反应。**检测不在另一个 agent，在便宜的信号 + 探针形状**（Day 147：探针形状决定可见性形状）。

### 7. 今日自检清单（10 项）

1. 说出手指初始位置免费 ⟹ 第一字符成本 1（移动 0 + 敲 1）的推理；
2. 写出状态压缩：每步必有一指在刚敲字符上，状态 = m 个位置（滚动 O(m)）；
3. 写出转移方程（续指 d(prev,cur)+1 / 换指 min_j d(j,cur)+1）；
4. 讲清换指落地：`g[prev] = min(g[prev], min_j f[j] + d(j,cur) + 1)`；
5. 复杂度 O(n·m) 时间 / O(m) 空间（26 键版 O(26n)）；
6. 进阶②三指为什么工程上不用精确 DP（状态爆炸 → 近似）；
7. checkpoint 五问能背：存什么/粒度/恢复/版本/成本；
8. outbox 模式 + idempotency key 的恢复路径；
9. 分层活性检测 L0/L1/L2 的盲区各是什么；
10. 恢复三板斧（nudge/checkpoint-restart/cancel-reassign）+ 恢复动作可观测 + kill switch 独立。

### 8. 高频速答六连

- **事件驱动路由**：router 不轮询、事件推给它，订阅机制减少中转；
- **异步 ReAct loop**：耗时工具调用不阻塞会话；
- **存算分离**：状态与执行环境解耦，跨设备/跨会话续跑；
- **outbox 模式**：意图先落日志再执行，恢复对账；
- **事件溯源 + 快照**：日志是金、快照是加速器；
- **checkpoint 自描述（schema_version）**：恢复路径必须可测试可迁移。

### 9. 今日金句

> **长时程系统不相信「永远健康」，它只相信「坏了能被看见、能被恢复」——所以 Watchdog 在主系统之外，进程活着不算健康、有进展才算健康，恢复动作本身要被记录和演练。DeepSeek 把调度、缓存、存算分离、看门狗搬进 Agent 系统，说破了一句行业暗语：接下来的竞争不是在让模型变聪明，是在让系统变得可运营。当面试官说「设计一个跑一周的 agent」，他真正在问的是：你信不信你自己的进程——不信的话，你的 Plan B 长什么样。**
