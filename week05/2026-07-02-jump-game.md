## 1. 今日算法题

### 题目描述

给定一个非负整数数组 `nums`，你最初位于数组的**第一个下标**。

数组中的每个元素代表你在该位置可以跳跃的**最大长度**。

判断你是否能够到达最后一个下标。

**示例 1:**
```
输入: nums = [2,3,1,1,4]
输出: true
解释: 可以先跳 1 步，从下标 0 到达下标 1，然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2:**
```
输入: nums = [3,2,1,0,4]
输出: false
解释: 无论怎样，你总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0，所以你永远不可能到达最后一个下标。
```

### 解题思路

#### 核心观察：贪心思路

不要纠结「每一步跳多远」，而是问：**目前我能覆盖的最远位置在哪里？**

- 遍历数组时，维护一个变量 `max_reach`，表示当前能到达的最远下标。
- 对于每个位置 `i`，如果 `i` 在 `max_reach` 范围内（即 `i <= max_reach`），说明这个位置是可达的。
- 更新 `max_reach = max(max_reach, i + nums[i])`。
- 如果某个时刻 `max_reach >= n - 1`，说明能到达终点，提前返回 `true`。
- 如果遍历到 `i > max_reach`，说明当前位置 unreachable，且之后也不可能到达终点，返回 `false`。

#### 为什么贪心是对的？

- 我们不需要记录「从哪条路跳过来的」，只需要知道「最远的边界能推到哪」。
- 如果位置 `i` 是可达的，那么所有 `i` 能跳到的位置也是可达的（通过从 `i` 跳过去）。
- 因此，维护一个全局最远可达边界就够了，这就是「局部最优 -> 全局最优」的贪心策略。

### 代码实现（Python）

```python
def canJump(nums: list[int]) -> bool:
    n = len(nums)
    max_reach = 0  # 当前能到达的最远下标
    
    for i in range(n):
        if i > max_reach:
            # 当前位置已经超出了可达范围，直接失败
            return False
        
        # 更新最远可达边界
        max_reach = max(max_reach, i + nums[i])
        
        # 提前退出：已经能到达终点了
        if max_reach >= n - 1:
            return True
    
    return True
```

### 复杂度分析

| 维度 | 结果 | 说明 |
|------|------|------|
| **时间** | O(n) | 只需一次遍历 |
| **空间** | O(1) | 只用一个变量 `max_reach` |

## 2. 面试技巧

### 2.1 如何识别「贪心算法」题目？

贪心题目的常见信号：

| 信号 | 举例 |
|------|------|
| 求「最大/最小」值，且每一步做局部最优选择不会导致全局失败 | 跳跃游戏、无重叠区间 |
| 「排序后选择」有奇效 | 分配饼干、根据身高重建队列 |
| 问题具有**无后效性**（当前决策不影响后续可选范围） | 区间调度、哈夫曼编码 |
| 答案具有「单调性」或可以「验证」某个值是否可行 | 二分答案类问题 |

> **面试官爱问**: 「你怎么证明贪心是对的？」
>
> **答法模板**: 先说明「最优子结构」（问题的最优解包含子问题的最优解），再说明「贪心选择性质」（局部最优能推出全局最优）。如果证不出来，可以主动说「这道题贪心不一定对，需要 DP」，展现你的严谨性。

### 2.2 贪心 vs 动态规划：怎么区分？

| 维度 | 贪心 (Greedy) | 动态规划 (DP) |
|------|--------------|---------------|
| **核心思想** | 每一步做当前最优选择，不回溯 | 枚举所有状态，保存子问题最优解 |
| **适用条件** | 具有贪心选择性质 + 最优子结构 | 具有最优子结构 + 重叠子问题 |
| **时间复杂度** | 通常 O(n) 或 O(n log n) | 通常 O(n²) 或 O(n×m) |
| **空间复杂度** | 通常 O(1) 或 O(n) | 通常 O(n) 或 O(n²) |
| **验证方式** | 很难验证，需要数学证明 | 递推公式天然保证正确性 |
| **典型场景** | 区间调度、最小生成树、哈夫曼编码 | 背包、编辑距离、最长公共子序列 |

**实战口诀**: 先想 DP，看看能不能简化；如果能发现「排序后贪心」或「维护一个边界」，尝试贪心；如果贪心证不出来，老老实实写 DP。

### 2.3 二分答案框架（本周重点）

二分答案不是「在数组里找数」，而是「猜一个答案，验证它是否可行」。

**通用模板（Python）:**

```python
def binary_search_answer():
    left, right = 最小可能值, 最大可能值
    
    while left < right:
        mid = left + (right - left) // 2  # 防溢出
        if check(mid):  # 验证 mid 是否可行
            right = mid    # 可行，尝试更优（更小/更大）
        else:
            left = mid + 1  # 不可行，需要调整边界
    
    return left  # 最终的答案
```

**关键设计**：`check()` 函数。这是二分答案的灵魂，通常是贪心或模拟来验证某个值是否可行。

**经典二分答案题目**：
- [LeetCode 875. 爱吃香蕉的珂珂](https://leetcode.cn/problems/koko-eating-bananas/) — 速度二分
- [LeetCode 1011. 在 D 天内送达包裹的能力](https://leetcode.cn/problems/capacity-to-ship-packages-within-d-days/) — 容量二分
- [LeetCode 410. 分割数组的最大值](https://leetcode.cn/problems/split-array-largest-sum/) — 子数组和二分

### 2.4 面试中的话术模板

**当面试官问「为什么不用 DP？」**
> 「这道题我先考虑了 DP，状态可以是 `dp[i]` 表示是否能到达位置 `i`。但仔细想，我们其实并不需要知道每个位置的详细状态，只需要维护一个全局的最远可达边界。当 `i` 超过这个边界时直接返回 false，这实际上是一个贪心策略，把时间优化到了 O(n)。」

**当面试官问「时间还能优化吗？」**
> 「已经 O(n) 了，每个位置至少访问一次，这是理论下界。空间是 O(1)，也最优了。」

**当面试官追问「如果要求最少跳跃次数呢？」（延伸题 Jump Game II）**
> 「那就是贪心进阶了：维护当前层的最远边界 `current_end` 和下一层的最远边界 `farthest`。当遍历到 `current_end` 时，必须跳一次，然后 `current_end = farthest`。这也是 O(n) 的贪心。」

## 3. 今日总结

- **贪心识别**：看问题是否有「局部最优 -> 全局最优」的结构，是否有无后效性。
