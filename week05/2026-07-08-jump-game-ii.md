## 今日算法题

### 题目描述

给定一个长度为 `n` 的 **0 索引**整数数组 `nums`。初始位置在数组的第一个下标 `0`。

数组中每个元素 `nums[i]` 表示从位置 `i` 可以向前跳跃的**最大长度**（可以跳 1 到 `nums[i]` 的任意长度）。

返回到达数组最后一个位置所需的**最少跳跃次数**。

你可以假设总是可以到达数组的最后一个位置。

**示例 1:**
```
输入: nums = [2,3,1,1,4]
输出: 2
解释: 跳 1 步从下标 0 到达下标 1，然后再跳 3 步到达最后一个下标。
```

**示例 2:**
```
输入: nums = [2,3,0,1,4]
输出: 2
```

**约束:**
- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 1000`
- 题目保证可以到达最后一个下标

---

### 思路分析

这题是 [Day 27 — 跳跃游戏](2026-07-02-jump-game.md) 的进阶版。Day 27 问的是"能不能到达终点"，今天是"最少跳几次"。

#### 方法一：动态规划 O(n²) — 能过但不是最优

定义 `dp[i]` 为到达位置 `i` 的最少跳跃次数。
- `dp[0] = 0`
- 对于每个 `i`，遍历所有 `j < i` 且 `j + nums[j] >= i`，取 `dp[j] + 1` 的最小值

时间 O(n²)，对于 `n = 10^4` 勉强能过，但面试官显然希望你给 O(n)。

#### 方法二：贪心 O(n) ⭐

核心思想：**不要关心每一步具体跳多远，而是维护"当前这一跳能覆盖的范围"和"下一跳能覆盖的最远范围"**。

想象你在玩一个游戏：
- 你现在站在一个圈子里（当前跳跃能到达的范围）
- 你往圈子里每走一步，都在为"下一跳"积攒能量
- 当走到圈子边界时，你必须使用已经攒好的"下一跳"，同时更新再下一跳的范围

**具体做法：**
1. `end`：当前这步跳跃能到达的最远边界
2. `maxReach`：在 `[0, end]` 范围内，下一跳能到达的最远位置
3. `jumps`：已使用的跳跃次数
4. 遍历数组（不遍历最后一个位置，因为到达就算成功）：
   - 每到一个位置，更新 `maxReach = max(maxReach, i + nums[i])`
   - 当 `i == end` 时，说明必须再用一次跳跃了：`jumps += 1`，`end = maxReach`

**为什么贪心正确？**
- 在 `[0, end]` 范围内，我们最多只需要 1 次跳跃就能覆盖（这就是 `end` 的定义）
- 当我们走到 `end` 时，必须开启新的一次跳跃，而 `maxReach` 就是这次新跳跃能到达的最远位置
- 每次"被迫起跳"时，我们都已经攒好了最优的下一跳范围，所以跳跃次数最少

---

### 代码实现（Python）

```python
def jump(nums: list[int]) -> int:
    n = len(nums)
    if n <= 1:
        return 0
    
    jumps = 0          # 已使用的跳跃次数
    end = 0            # 当前这步能跳到的最远边界
    maxReach = 0       # 下一跳能到达的最远位置
    
    # 不需要访问最后一个位置，因为到达就算成功
    for i in range(n - 1):
        maxReach = max(maxReach, i + nums[i])
        
        # 到达当前跳跃的边界，必须使用下一跳
        if i == end:
            jumps += 1
            end = maxReach
    
    return jumps
```

#### 代码要点

1. **`range(n - 1)` 不是 `range(n)`**：最后一个位置不需要跳，到达即成功
2. **`end = maxReach` 而不是 `end += 1`**：maxReach 是全局最优的下一跳范围
3. **初始化 `jumps = 0`**：从位置 0 出发时还没跳，第一次走到边界时才计数
4. **提前返回 `n <= 1`**：只有 1 个元素时不需要跳

### 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 一次遍历数组 |
| 空间 | O(1) | 只使用三个变量 |

---

### 手写推演

以 `nums = [2, 3, 1, 1, 4]` 为例：

| i | nums[i] | i+nums[i] | maxReach | end | 是否起跳 | jumps |
|---|---------|-----------|----------|-----|----------|-------|
| 0 | 2 | 2 | 2 | 0 | ✅ i==end | 1 |
| 1 | 3 | 4 | 4 | 2 | — | 1 |
| 2 | 1 | 3 | 4 | 2 | — | 1 |
| 3 | 1 | 4 | 4 | 2 | ✅ i==end | 2 |

- i=0: maxReach = max(0, 0+2) = 2，i == end，起跳！jumps=1，end=2
- i=1: maxReach = max(2, 1+3) = 4，i ≠ end，继续
- i=2: maxReach = max(4, 2+1) = 4，i == end，起跳！jumps=2，end=4
- i=3: maxReach = max(4, 3+1) = 4，循环结束（range(n-1)）

返回 `jumps = 2`，正确。

## 面试技巧

### 1. 怎么和 Day 27 的跳跃游戏关联起来讲

如果你之前做过跳跃游戏，面试时可以这么开场，显得你有体系感：

> "这道题是跳跃游戏的进阶版。上一题我只需要判断能否到达终点，可以用贪心维护最远可达边界。这道题要求最少跳跃次数，核心升级是：**同时维护两个边界——当前这步能到的边界，和下一跳能到的边界**。"

面试官会很喜欢这种"从已知推导未知"的思维方式。

### 2. 面试中画出"跳跃窗口"图

在纸上画一条数轴：
```
位置:  0   1   2   3   4
数值: [2] [3] [1] [1] [4]
       ↑---↑ 第 1 跳的覆盖范围（end=2）
           ↑-----------↑ 第 2 跳的覆盖范围（end=4）
```

直观展示"边界推进"的过程，比干讲代码更有效。

### 3. 面试官可能的追问

**Q：为什么时间复杂度是 O(n) 而不是 O(n²)？**
> 答：我只遍历数组一次，每次迭代都是 O(1) 操作。虽然看起来我在"枚举所有可能的选择"，但实际上我用 `maxReach` 一次性记录了最优的下一跳范围，不需要回头再算。

**Q：如果要求输出具体的路径（每一步跳到哪里）？**
> 答：需要额外维护一个 `from` 数组记录每个位置是从哪个边界起跳时到达的，或者反向回溯。时间还是 O(n)，空间变成 O(n)。

**Q：如果数组很长（10⁶ 级别），还能这么写吗？**
> 答：O(n) 时间、O(1) 空间已经是理论最优了，因为每个位置至少要看一次。如果还要优化，可能需要考虑并行或向量化，但算法层面没有更好的了。

### 4. 常见翻车点

| 翻车场景 | 原因 | 解法 |
|----------|------|------|
| `range(n)` 而不是 `range(n-1)` | 最后一个位置不需要跳，会多算一次 | 改 `range(n-1)` |
| `jumps` 初始化为 1 | 从位置 0 出发时还没跳 | 初始化为 0，到边界才加 |
| `end = i + 1` | 错误地认为下一跳只能从下一个位置开始 | 应该是 `end = maxReach` |
| 用 BFS/DP 写了个 O(n²) | 能过但面试官不满意 | 主动提出"可以用贪心优化到 O(n)" |

### 5. 一句话总结

> **"维护当前跳的边界和下一跳的最远可达，走到边界就起跳"** — 这句话说出来，面试官就知道你掌握了核心思想。
