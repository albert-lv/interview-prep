## 今日算法题

### 题目描述
整数数组 `nums` 按升序排列，数组中的值**互不相同**。

在传递给函数之前，`nums` 在预先未知的某个下标 `k`（`0 <= k < nums.length`）上进行了**旋转**，使数组变为 `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]`。

给定旋转后的数组 `nums` 和一个整数 `target`，如果 `target` 在 `nums` 中存在，返回它的下标；否则返回 `-1`。

**必须在 O(log n) 时间复杂度内完成。**

**示例**：
- 输入：`nums = [4,5,6,7,0,1,2], target = 0`
- 输出：`4`
- 输入：`nums = [4,5,6,7,0,1,2], target = 3`
- 输出：`-1`

---

### 解题思路

旋转排序数组有个关键特性：**二分之后，一定有一半是有序的**。

利用这个有序 half，我们可以快速判断 `target` 是否落在这一半里。

#### 核心直觉
> 不管怎么转，砍一刀下去，总有一半是"正常"的。

#### 算法步骤
1. 初始化 `left = 0, right = len(nums) - 1`
2. 当 `left <= right` 时循环：
   - 计算 `mid = (left + right) // 2`
   - 如果 `nums[mid] == target`，返回 `mid`
   - **判断哪一半有序**：
     - 如果 `nums[left] <= nums[mid]`：左半有序
       - 若 `target` 在 `[nums[left], nums[mid])` 范围内，往左走：`right = mid - 1`
       - 否则往右走：`left = mid + 1`
     - 否则：右半有序
       - 若 `target` 在 `(nums[mid], nums[right]]` 范围内，往右走：`left = mid + 1`
       - 否则往左走：`right = mid - 1`
3. 没找到，返回 `-1`

#### 为什么至少有一半有序？
因为原数组是升序的，旋转点只有一个。`mid` 不是落在旋转点左侧就是右侧，所以 `left` 到 `mid` 要么全部有序，要么 `mid` 到 `right` 全部有序。

---

### 代码示例（Python）

```python
def search(nums, target):
    left, right = 0, len(nums) - 1
    
    while left <= right:
        mid = (left + right) // 2
        
        if nums[mid] == target:
            return mid
        
        # 判断左半部分是否有序
        if nums[left] <= nums[mid]:
            # target 在左半有序区间内？
            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1
        else:
            # 右半部分有序
            # target 在右半有序区间内？
            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1
    
    return -1
```

---

### 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(log n) | 每次排除一半，经典二分 |
| **空间** | O(1) | 仅使用常数变量 |

## 面试技巧

### 1. 二分查找的万能起手式
看到"有序数组"或"旋转有序数组"，先想二分。面试时可以直接说：
> "数组有序，我首先考虑二分查找，目标是 O(log n)。"

这句话一出口，面试官就知道你抓住了考点。

### 2. 旋转数组的陷阱：不要下意识排序
很多人看到"旋转"先想排序恢复，但排序是 O(n log n)，不符合题目要求。

正确思路：**不恢复，直接利用有序 half 做二分**。

### 3. 边界条件速查表
二分最容易翻车的地方就是边界，记住这个口诀：

> **"左闭右闭用 `<=`，左闭右开用 `<`"**

本题用 `left <= right`（左闭右闭），因为 `right = len(nums) - 1`，左右都是有效下标。

### 4. 如何向面试官解释"哪一半有序"
现场画图，用具体例子：

```
数组：[4, 5, 6, 7, 0, 1, 2]
         left     mid        right

mid = 7，nums[left] = 4 <= 7，所以左半 [4,5,6,7] 是有序的！

target = 0，不在 [4,7] 里，所以去右半找。

target = 6，在 [4,7] 里，所以去左半找。
```

面试官看到你能在脑子里"分区"，就知道你理解了本质。

### 5. 进阶追问：如果数组中有重复元素？
这是 LeetCode 81（搜索旋转排序数组 II），原题变形。

当 `nums[left] == nums[mid] == nums[right]` 时，无法判断哪一半有序，只能 `left += 1` 或 `right -= 1` 缩小范围，最坏情况退化到 O(n)。

面试时被问到，答出这个点就加分。

### 6. 同类题目扩展
- **寻找旋转排序数组中的最小值**（LeetCode 153）：也是二分，判断哪一半有序，最小值在无序 half 的边界
- **搜索插入位置**（LeetCode 35）：标准二分，找第一个 `>= target` 的位置
- **在排序数组中查找元素的第一个和最后一个位置**（LeetCode 34）：两次二分，找左边界和右边界
- **x 的平方根**（LeetCode 69）：二分答案，经典套路

### 7. 一句话总结
> **"旋转数组二分的关键：不看全局有序，只看局部有序；half 有序就能判断 target 在不在里面。"**
