## 今日算法题

### 题目描述
给定一个区间的集合 `intervals`，其中每个区间 `intervals[i] = [start_i, end_i]`。  
返回需要移除区间的**最小数量**，使剩余区间互不重叠。

**注意**：区间 `[1, 2]` 和 `[2, 3]` 在端点接触时**不算重叠**。

**示例**：
- 输入：`[[1,2], [2,3], [3,4], [1,3]]`
- 输出：`1`
- 解释：移除 `[1,3]` 后，剩余 `[1,2], [2,3], [3,4]` 互不重叠。

---

### 解题思路

这是**贪心算法**在区间调度问题上的经典应用。

#### 核心直觉
> **结束越早的区间，留给后面的空间越大。**

假设你已经选了一些不重叠的区间，现在面临选择：下一个选哪个？  
——当然选**结束时间最早**的那个，这样后面能塞下更多区间。

#### 算法步骤
1. 把所有区间按**结束时间**升序排序；
2. 维护一个变量 `end`，表示当前已选区间的最晚结束时间；
3. 遍历排序后的区间：
   - 如果当前区间的 `start >= end`：不重叠，保留，更新 `end = 当前结束时间`；
   - 否则：重叠了，必须移除，`count += 1`。

#### 为什么不是按开始时间排序？
按开始时间排序容易陷入局部最优：一个开始很早但结束很晚的区间会占满整个时间线，导致后面很多区间进不来。按结束时间排序才是全局最优的。

---

### 代码示例（Python）

```python
def eraseOverlapIntervals(intervals):
    if not intervals:
        return 0
    
    # 按结束时间升序排序（关键！）
    intervals.sort(key=lambda x: x[1])
    
    count = 0          # 需要移除的区间数
    end = intervals[0][1]  # 当前已选区间的最晚结束时间
    
    for i in range(1, len(intervals)):
        if intervals[i][0] < end:
            # 重叠了，必须移除
            count += 1
        else:
            # 不重叠，保留，更新 end
            end = intervals[i][1]
    
    return count
```

---

### 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(n log n) | 主要是排序，遍历是 O(n) |
| **空间** | O(1) | 仅使用常数变量（排序栈空间不计） |

## 面试技巧

### 1. 开口三问，展示细心
遇到区间题，先别急着写代码，问面试官：
- "区间是闭区间还是半开半闭？端点接触算重叠吗？"
- "区间集合是否已经按某个维度排好序？"
- "如果输入为空，期望返回什么？"

这些问题不仅能展示你的边界意识，还能争取 30 秒思考时间。

### 2. 如何证明贪心是对的（交换论证）
面试官如果问"为什么选结束最早的？"，可以用**交换论证**（Exchange Argument）：

> 假设最优解的第一个区间不是结束最早的，那把它替换成结束更早的那个区间。这个替换不会增加任何重叠（因为它结束更早），也不会影响后续选择。因此，最优解一定可以被调整成包含结束最早的区间。

这一句话就能让面试官知道：你不是在蒙，而是真的理解贪心正确性。

### 3. 常见变种：背会一个，通杀一类
- **最多能参加多少会议**：本质就是求**最多不重叠区间的数量**，公式：`len(intervals) - 需要移除的数量`
- **射箭射气球**：按右端点排序，每次射箭尽量射在右端点，能射穿的气球都射穿
- **合并区间**：按开始时间排序，重叠就合并，不重叠就新开一个
- **分发糖果**：左右两次遍历，双向贪心

### 4. 现场画图技巧
面试官面前，画图是最快让双方都理解的方式：

```
时间线：1  2  3  4  5  6  7  8
[1,3]  ████
[2,4]   ████     ← 重叠，必须二选一
[3,5]      ████
[5,7]         ████ ← 不重叠，保留

按结束时间排序后：先选 [1,3]（结束最早），[2,4] 被排除，[3,5] 重叠被排除，[5,7] 保留。
```

### 5. 一句话总结
> **"区间调度问题的贪心核心：结束越早，机会越多。"**
