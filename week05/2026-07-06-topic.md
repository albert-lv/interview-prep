## 🎯 今日算法题

### 题目描述

峰值元素是指其值严格大于左右相邻值的元素。

给你一个整数数组 `nums`，找到峰值元素并返回其索引。数组可能包含多个峰值，在这种情况下，返回 **任何一个峰值** 所在位置即可。

你可以假设 `nums[-1]` 和 `nums[n]` 都是负无穷。也就是说，数组两端都被认为是下坡。

**示例 1：**
```
输入：nums = [1, 2, 3, 1]
输出：2
解释：3 是峰值元素，你的函数应该返回其索引 2。
```

**示例 2：**
```
输入：nums = [1, 2, 1, 3, 5, 6, 4]
输出：5
解释：你的函数可以返回索引 5，其峰值元素为 6；或者返回索引 2，其峰值元素为 1 也是正确的。
```

**约束条件：**
- `1 <= nums.length <= 1000`
- `-2^31 <= nums[i] <= 2^31 - 1`
- `nums[i] != nums[i + 1]`（相邻元素不相等）

---

### 解题思路

#### 暴力解法 O(n)

直接遍历数组，找到第一个满足 `nums[i] > nums[i-1]` 且 `nums[i] > nums[i+1]` 的位置。

但这个题的关键在于：**它要求你用 O(log n) 的时间复杂度解决**。

#### 二分查找 O(log n) ⭐

这题的精髓在于：**数组不是有序的，但二分仍然适用**。

核心观察：
1. 由于两端都是负无穷，数组中**一定存在峰值**（可以想象成从负无穷出发，最终必须回到负无穷，中间必有最高点）。
2. 对于中间元素 `nums[mid]`：
   - 如果 `nums[mid] > nums[mid+1]`，说明 `mid` 右侧是"下坡"，峰值可能在左侧（包含 `mid` 本身）。
   - 如果 `nums[mid] < nums[mid+1]`，说明 `mid` 右侧是"上坡"，峰值一定在右侧。

**为什么这个判断是对的？**
- 如果 `nums[mid] < nums[mid+1]`，右边在上升，而右边最终会回到负无穷，所以右边一定存在一个峰值。
- 如果 `nums[mid] > nums[mid+1]`，左边可能在上升也可能在下降，但 `mid` 本身已经比右边高了，如果左边也在下降那 `mid` 就是峰值；如果左边在上升，那左边一定有个峰值。所以峰值在 `[left, mid]` 范围内。

这种二分被称为"**二分答案的另一种形态——基于趋势的局部二分**"，它不依赖全局有序，而是利用"趋势保证存在性"。

---

### 代码实现

#### Python

```python
def findPeakElement(nums: list[int]) -> int:
    left, right = 0, len(nums) - 1
    
    while left < right:
        mid = (left + right) // 2
        
        if nums[mid] > nums[mid + 1]:
            # 下坡方向，峰值在左侧（包含 mid）
            right = mid
        else:
            # 上坡方向，峰值在右侧
            left = mid + 1
    
    return left
```

#### 代码要点解析

1. **循环条件 `left < right`**：不是 `<=`，因为我们最终要收敛到一个点。
2. **`right = mid`** 而不是 `mid - 1`：因为 `mid` 本身可能就是峰值。
3. **`left = mid + 1`**：因为 `mid` 一定不是峰值（它比右边小）。
4. **不需要处理边界**：题目保证 `nums[-1]` 和 `nums[n]` 都是负无穷，所以数组两端天然是"下坡"。

---

### 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(log n) | 二分查找，每次排除一半元素 |
| 空间 | O(1) | 只使用常数额外空间 |

## 🎤 面试技巧

### 1. 如何向面试官展示思路

**开场（30秒）：**
> "这道题我首先注意到一个关键条件：数组两端都是负无穷。这意味着数组里一定存在峰值。我可以用二分查找在 O(log n) 时间内找到它。"

**核心论证（1分钟）：**
> "对于中间元素，我只比较它和右边元素：
> - 如果 `nums[mid] < nums[mid+1]`，右边在上升，而右边最终要回到负无穷，所以右边一定存在峰值；
> - 如果 `nums[mid] > nums[mid+1]`，mid 已经比右边高了，峰值可能在 mid 本身，也可能在左边。
> 这样每次都能排除一半，达到 O(log n)。"

### 2. 面试官可能的追问

**Q：为什么时间复杂度是 O(log n) 而不是 O(n)？**
> 答：因为每次比较后我都能确定峰值在哪一半，不需要遍历整个数组。这和普通二分的本质是一样的——利用信息排除一半搜索空间。

**Q：如果数组中有多个峰值，返回哪个？**
> 答：这道题返回任意一个即可。我的算法会根据中点的趋势选择方向，最终返回的是"顺着趋势走"遇到的第一个峰值。

**Q：相邻元素可以相等吗？**
> 答：题目说了不能相等。如果可以相等，判断逻辑会更复杂，需要处理平台区。

**Q：能不能用递归写？**
> 答：可以，但面试中建议写迭代版本，空间复杂度更优（O(1) vs O(log n) 递归栈）。

### 3. 常见翻车点

| 翻车场景 | 原因 | 解法 |
|----------|------|------|
| `right = mid - 1` | 错误地排除了 `mid` 本身可能是峰值的情况 | 应该用 `right = mid` |
| 用 `left <= right` | 会导致死循环或索引越界 | 用 `left < right`，最后返回 `left` |
| 同时比较左右两边 |  unnecessarily 复杂化 | 只比较右边就够了，信息已经足够做决策 |
| 没理解为什么能二分 | 以为二分只能用于有序数组 | 关键是"排除法"，不是"有序性" |

### 4. 这道题在考什么

面试官出这道题，通常想考察：
1. **你是否能识别出"二分查找的非标准应用场景"**
2. **你对二分查找本质的理解**（排除法 vs 有序性依赖）
3. **边界条件的处理能力**

**加分项：** 能提到"这类似于求函数的局部极大值，梯度下降的反方向"。
