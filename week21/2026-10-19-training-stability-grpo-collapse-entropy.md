## 🧩 今日算法题：最长重复子串（Longest Duplicate Substring, LC 1044）

### 题目描述

给定字符串 `s`，返回 `s` 中**最长的重复子串**（该子串必须在 `s` 中**至少出现两次**，两次出现**可以重叠**）。如果没有重复子串，返回 `""`。约束：`2 <= s.length <= 3 * 10⁴`，`s` 由小写英文字母组成。

```
输入: s = "banana"
输出: "ana"        # "ana" 出现 2 次（可重叠）；"an"/"na" 更短不是最优

输入: s = "abcd"
输出: ""           # 没有重复
```

**工程语境包装**：这就是 **RAGEN-2 模板坍缩检测器的算法内核**。把 N 条 rollout 轨迹用分隔符拼成一个大字符串 `s`：如果模型开始"背模板"——对不同输入复述同一套与输入无关的话术——拼接串里就会出现**跨输入的长重复片段**。最长重复子串长度突然暴涨 = 模板坍缩的报警信号。同理它也用于： plagiarism 检测、DNA 重复序列（串联重复致病）、日志模板提取、代码克隆检测。今天这题就是"监控 RL 训练健康度"的那块仪表。

### 解题思路：二分答案 + Rabin-Karp 滚动哈希

**关键观察：存在性判定是单调的**。如果长度为 `L` 的子串有重复，那么长度 `L-1` 的子串必然也有重复（重复片段砍掉尾巴还是重复）。单调 → **二分答案长度**。

**判定「长度为 L 的子串是否有重复」**：用 **Rabin-Karp 滚动哈希**，O(n) 扫一遍，把所有长度为 L 的子串哈希值放进哈希集合，出现重复即命中。窗口右滑一位时，新哈希 = 旧哈希减去滑出字符的贡献、乘 base、加上滑入字符——**O(1) 更新**，不是重新算。

两步合起来：**O(n log n) 时间 / O(n) 空间**，面试标准答。

> ⚠️ 哈希碰撞：单哈希 + 大模数（或直接用 2^64 自然溢出）工程够用；被追问就答**双哈希**（两个不同 base/模数，两个都撞才算撞），或者冲突候选做 O(L) 字符级二次确认。

### 代码实现（Python：二分 + 双哈希，面试可直接写）

```python
class Solution:
    def longestDupSubstring(self, s: str) -> str:
        n = len(s)
        nums = [ord(c) - ord('a') for c in s]
        MOD1, MOD2 = 10**9 + 7, 10**9 + 9   # 双哈希防碰撞
        BASE = 26

        def has_dup(L: int):
            """长度为 L 的子串是否存在重复；存在则返回其中一个起点"""
            if L == 0:
                return 0
            h1 = h2 = 0
            p1 = p2 = 1
            for i in range(L):                     # 初始窗口哈希
                h1 = (h1 * BASE + nums[i]) % MOD1
                h2 = (h2 * BASE + nums[i]) % MOD2
                p1 = (p1 * BASE) % MOD1            # BASE^L % MOD
                p2 = (p2 * BASE) % MOD2
            seen = {(h1, h2)}
            for i in range(L, n):                  # 窗口右滑：O(1) 滚动
                out = nums[i - L]
                h1 = (h1 * BASE - out * p1 + nums[i]) % MOD1
                h2 = (h2 * BASE - out * p2 + nums[i]) % MOD2
                key = (h1, h2)
                if key in seen:
                    return i - L + 1               # 重复出现，返回起点
                seen.add(key)
            return -1

        lo, hi, start = 0, n - 1, -1
        while lo <= hi:                            # 二分最长长度
            mid = (lo + hi) // 2
            pos = has_dup(mid)
            if pos != -1:
                start = pos                        # mid 可行 → 尝试更长
                lo = mid + 1
            else:
                hi = mid - 1
        return s[start:start + lo - 1] if start != -1 else ""
```

### 进阶版：后缀数组（Suffix Array）+ Height 数组

`3×10⁴` 二分+哈希够用，但被问"更优/确定性的做法"就上**后缀数组**：

1. 对所有后缀排序（SA-IS 或倍增法 O(n log n)）得到 `sa[]`；
2. `height[i]` = 第 i 名后缀与第 i-1 名后缀的**最长公共前缀（LCP）**；
3. **答案 = max(height)**，对应两个后缀就是两次出现位置（天然不重叠可通过位置差判定）。

口诀：「**排序消除一半比较，height 的峰值就是最长重复**」——和 Day 134 Pareto 前沿「排序+扫描」是同一手「**消除半序**」的算法手法。后缀数组的优势：**无碰撞、确定性**、天然支持"至少出现 k 次"（height 数组里找长度为 k-1 的连续窗口最小值）和"不可重叠"（同一窗口内首末后缀位置差 ≥ L）两种变体。

### 复杂度分析

| 方案 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 二分 + 滚动哈希 | **O(n log n)** | O(n) | 面试首选，实现快 |
| 后缀数组 + height | O(n log n)（SA-IS 可到 O(n)） | O(n) | 确定性，变体题通吃 |
| 暴力哈希枚举 | O(n²) 最坏 | O(n²) | 只有证明哈希不可靠时才提 |

### 面试官连环问（模板坍缩检测仪视角）

**Q1：哈希撞了怎么办？** → 双哈希（两个模数同时撞的概率 ≈ 10⁻¹⁸ 级）；或冲突候选 O(L) 二次确认；后缀数组是确定性终极答案。面试答「先双哈希兜底，追问就上 SA」即满分。

**Q2：数据流版——训练监控要在线跑，轨迹一条一条进来怎么办？** → 环形缓冲保留最近 W 条轨迹的拼接串，窗口内跑今天的二分+哈希；超过窗口的老轨迹滑出。报警条件别用绝对长度，用**相对指标**：最长重复子串长度 / 平均轨迹长度 的比值突增（3σ 告警），否则轨迹变长会误报。

**Q3：模板坍缩的工程定义是"同一模板出现在不同输入的轨迹里"——怎么改？** → 哈希值映射改为 `{hash: set(轨迹id)}`，判定从"出现两次"改为"**出现在 ≥k 条不同轨迹**"。拼接时轨迹间插**唯一分隔符**（不在字母表内），防止跨轨迹的假重复——这个坑现场要会主动说。

**Q4：不允许重叠的变体？** → 二分判定里命中时检查两个起点下标差 `>= L`，或后缀数组版在 height 连续窗口里找首末位置差 ≥ L。

**Q5：和 Day 119「最长重复子数组」什么关系？** → 同一族：Day 119 是**两个给定数组**间的最长公共**连续**段（DP 后缀状态 `dp[i][j]` 不匹配清零）；今天是**一个字符串内部**自我重复（二分+哈希/SA）。刷题时是两道题，工程上是同一个监控器的两个读数：前者比对 golden trace vs 实际轨迹（过程偏离），今天检测跨输入复述（模板坍缩）。

**Q6：怎么把今天的题嵌进训练监控大盘？** → 三级仪表：① **entropy**（便宜但会被骗——见面试技巧）② **今日题的跨轨迹重复率**（每 100 条 rollout 采样跑一次，分钟级开销）③ **互信息 I(X;Z) 估计**（贵但准，RAGEN-2 金标准，离线小时级跑）。生产用 ①+② 做实时报警，③ 做深度归因。

**Q7：n = 10⁸（一天的全量轨迹）怎么办？** → 后缀数组外存/分布式版（D-CASA）；或先 n-gram 粗筛（统计所有 8-gram 的出现次数，候选高频片段再做精确扩展）= **先粗后精**（Day 130 AC 自动机两段式同哲学）。

### 0. 开场一张表：三大崩溃模式先立住

| 崩溃模式 | 坍缩维度 | 谁会被骗 | 检测金指标 | 主修复 |
|---|---|---|---|---|
| **熵坍缩** entropy collapse | **组内**：同一输入的 G 条 rollout 趋同 | reward 还在涨（前期） | 策略熵 H(π) 曲线 | clip-higher·熵奖励·动态温度 |
| **模板坍缩** template collapse（RAGEN-2） | **跨输入**：输出与输入无关地复述固定话术 | **entropy 监控**（高熵假象） | **互信息 I(X;Z) 下降** + 今日题的跨轨迹重复率 | SNR 感知正则·零方差组过滤 |
| **奖励黑客** reward hacking | 目标维度：钻奖励函数空子 | 奖励曲线（越涨越糟） | held-out 人类评估 + 轨迹审查 | 奖励修补·CPO 硬预算（Day 114/134） |

面试起手式：**"RL 后训练最常见的三类死法——组内多样性消失（熵坍缩）、跨输入退化（模板坍缩）、钻奖励空子（hacking）。前两者今天讲透，第三个之前 Day 114/134 已覆盖。"**

### 1. 主教材 RAGEN-2：模板坍缩 —— 高熵值为什么骗人

**现象**（RAGEN-2，帝国理工+微软+斯坦福+西北大学，2026.04）：多轮 agent RL 训练中，模型看似对每道题都在"推理"，实际是在复述一套**与具体输入无关的、预训练背好的模板化答案**。多轮交互里这个退化会被 tool 调用和 observation 掩盖，更隐蔽。

**为什么 entropy 监控失效**：熵只度量 `H(Z|X=x)`——**同一个问题**下回答的多样性。模板坍缩时模型对**不同问题**给出结构雷同的回答，但只要措辞还能抖几个同义词，token 级熵照样很高。**高熵 ≠ 没坍缩；高熵只保证组内多样，不保证跨输入区分。** 真正的指纹是：**条件熵低 + 互信息 I(X;Z) 持续下降**（输入 Z 和推理轨迹 Z 的关联被切断了）。

**SNR 机制（全文最锋利的一刀）**：策略梯度总梯度可分解为

```
g_total = g_task + g_reg
```

- `g_task` **任务信号**：来自奖励，大小正比于**组内奖励方差 Var(R|X)**——同一输入采出的 G 条轨迹 reward 差异越大，"哪条好哪条坏"的信息越清晰；
- `g_reg` **正则化噪声**：来自 KL 散度 / 熵正则项，**输入无关**，对所有轨迹施加统一约束。

当模型对某类输入**全对或全错**（零方差）时，`g_task ≈ 0`，正则化噪声主导更新——模型开始优先满足正则化约束（高熵、流畅、贴近初始分布），而不是任务需求。日积月累就学会"投机取巧"的模板化行为：流畅、高熵、与输入无关。**低奖励方差组 = 训练噪声放大器。**

**修复四板斧**（面试按序背）：
1. **数据侧**：全对/全错组本来就对梯度零贡献（GRPO 组基线天然跳过）——但 RAGEN-2 的洞察是它们仍通过**正则项**在施加噪声，所以更进一步：**主动过采样中等难度（方差高）的 prompt**，砍掉长期零方差样本（curriculum 的 SNR 版）；
2. **权重侧**：按组内奖励方差自适应调节正则化强度（方差低 → 降 KL/熵正则权重，别让噪声独占梯度）；
3. **检测侧**：互信息估计太贵就用代理指标——**今日算法题**（跨轨迹最长重复片段长度）、不同输入间 n-gram overlap、perplexity 异常平稳；
4. **归因侧**：坍缩发生在哪个 turn / 哪个 tool 之后，用 Day 128 的轨迹回放逐段定位（先粗后精）。

### 2. 熵坍缩：机制 + 修复工具箱

**机制**（多篇论文交叉验证，含火山引擎/字节的工程复盘）：对 softmax 策略，相邻两步的熵变化满足「**熵变化与 logp×Δlogit 的协方差负相关**」——而 GRPO 训练中这个协方差**恒为正**，所以熵**单调下降**。实测数据：前 200 步（1/12 训练量）烧掉 **73% 的熵**换 76% 的性能提升；前 1/3 步烧掉 94% 熵；**后 2/3 步只剩 7% 提升，边际收益趋零**。熵耗尽 = 探索死亡 = RL 失去意义。

**修复工具箱**（按面试出场频率排）：

1. **DAPO clip-higher**（2025.04，经典必答）：PPO-CLIP 上界 `1+ε` 会系统性**打压低概率 token**（exploration token 刚冒头就被 clip 砍回去），下界 `1−ε` 反而保护高概率 token → 加剧坍缩。DAPO 把上界放松到 0.28（下界保持 0.2）：**给探索留天花板**。veRL 里就是 `clip_ratio_low=0.2 / clip_ratio_high=0.28` 两个旋钮，Day 113 的配置审计过；
2. **熵奖励**（entropy bonus）：loss 里加 `−c·H(π)`，`c` 手调（veRL `entropy_coeff`）；
3. **top-entropy-quantile**（Dr.GRPO 一脉 / TRL `top_entropy_quantile`）：序列内只保留 top-ρ 高熵 token 的熵项（2/8 法则，ρ=0.2），低熵 token 的熵项是噪声别让它稀释梯度；
4. **UEC-RL 统一熵控制**（2026.04）：单向修复（只会减速衰减）升级为**双向控温**——难题升温（恢复探索）、易题降温（稳定收敛），配回放缓冲复用轨迹，每步训练时间 ~0.79×；
5. **动态 KL/entropy 系数**：熵掉太快就自动抬 bonus，比固定系数稳。

**一句对比背下来**：clip-higher 是**改更新规则**（让探索 token 活过 clip），熵奖励是**改目标函数**（给多样性发工资），UEC 是**改调度策略**（按难度分桶控温）。

### 3. 辅教材 GLM-5.2：PPO 迁移工程的近端信任域细节

GRPO 删 Critic 省显存，但很多工业团队（GLM-5.2 为代表）在 LLM 上坚持 PPO 并把它调稳，细节全是考点：

- **Critic 初始化**：从 reward model 初始化 value head，warmup 几步再开 actor 更新，否则 value 早期噪声直接毒化优势估计；
- **Reward whitening**：reward 先标准化（减均值除标准差）再进 GAE，防 returns 尺度漂移引爆 value loss；
- **GAE(λ)**：λ 越大方差越小偏差越大（0.9~0.95 起步），长轨迹 agent 任务要更低 λ 保偏差可控；
- **监控 clip fraction**：clip 比例长期 >0.3 = 步长过大/样本过旧，降 LR 或减少 PPO epoch；**ratio 几乎全为 1 = old/new logprob 混用**（采样端没固化 logprob 的字段错误，新人第一坑）；
- **梯度裁剪 + 混合精度**：advantage 异常或 fp16 溢出时 gradient norm spike，grad_clip=1.0 兜底 + 检查 reward 分布。

### 4. 🔥 本周热点缝合：PyTorch Conf 明天的「Rollout-Train 不一致」闪电演讲

字节跳动 × UVA 的闪电演讲题目就是本周的题眼：**「当 Rollout 与训练不一致时」**——rollout 引擎（vLLM/SGLang）和训练路径对**同一条轨迹重算的 token logprob 存在微小数值差**，这个差绝非无害：它让 importance ratio `r = π_train/π_old` 系统性偏离 1，**悄悄把 PPO/GRPO 的近端信任域目标改写成你不知道的另一个目标**。工程三件套对策：

1. **同源计算**：训练和采样尽量同 kernel/同精度（bf16 vs fp16 混用是重灾区），或对采样 logprob 做训练侧校准；
2. **固化采样 logprob**：rollout 时把每个 token 的 logprob 落盘随轨迹走，训练端 trust 而不是重算（与 GLM-5.2「ratio 全为 1 检查项」互补——固化对了 ratio 就该在 1 附近抖动）；
3. **监控 ratio 分布**：训练 dashboard 上 ratio 均值/方差进告警（偏离 1 超阈值 = 数值一致性破了），这正是 Day 113 veRL 监控六指标里「KL 突刺」的姊妹指标。

### 5. 症状 → 原因 → 处理：诊断表（背熟这张表 = 拿到稳定性质问题的入场券）

| 症状 | 可能原因 | 优先处理 |
|---|---|---|
| entropy 快速下降、reward 还在涨 | 熵坍缩早期（协方差恒正） | 先别高兴——clip-higher + 熵奖励提前干预 |
| **entropy 很高但 reward 不升** | **模板坍缩**（SNR 失衡）或探索噪声过大 | 查 I(X;Z) + 今日题的跨轨迹重复率；过滤零方差组 |
| entropy 很高 + 输出流畅 + 跨输入雷同 | 模板坍缩实锤 | 按 RAGEN-2 四板斧修复 |
| KL 突然 spike | LR 过高 / reward 尺度异常 / 样本 stale（异步积压） | 降 LR、增大 β、限制队列年龄（Day 136 版本差告警回收） |
| KL 长期 ≈ 0 | KL 太强 / reward 太弱 / mask 错误 | 降 β、检查 reward scale、做梯度链路测试 |
| reward 上升但人工评估质量下降 | 奖励黑客 / 长度偏置 / judge 偏差 | 抽样审查、按长度切片、校准 reward（Day 114） |
| response length 持续变长 | 长度黑客 / max token 过大 | 长度受控评估、长度惩罚 |
| clip fraction 很高 | 步长过大 / PPO epoch 多 / 样本过旧 | 降 LR、减 epoch、提高同步频率 |
| ratio 几乎全为 1 | old/new logprob 混用（固化字段错） | 检查轨迹数据字段（Conf 闪电演讲同款） |
| value loss 爆炸 | returns 尺度异常 / critic 学不稳 | reward whitening、降 critic LR |

### 6. 答题框架：训练稳定性五步法

面试官问「你的 RL 训练不稳定，怎么排查？」，按这个顺序答：

1. **先定量**：dashboard 三大指标齐看——**策略熵曲线 / KL 曲线 / 组内奖励方差分布**（单看 reward 是最低级错误）；
2. **归因**：熵塌 → 更新规则问题（clip/熵奖励）；熵高 reward 不涨 + 跨输入雷同 → SNR 问题（模板坍缩）；reward 涨质量降 → hacking。用今日题/embedding 相似度做廉价初筛，互信息做金标准确认；
3. **修复**：从工具箱选 2~3 个对症手段，**一次只改一个变量**（RL 调参的铁律——多变量同改，效果归因 impossible，GPU 小时全烧在玄学上）；
4. **验证**：held-out prompt 集上看 pass@1 + 多样性双指标，防"修好了 reward 修坏了模型"；
5. **沉淀**：这次坍缩的轨迹进黄金回归集，下次发版全量回归（Day 132 红队飞轮同款哲学——**每一次崩溃都是免费的难例**）。

### 7. veRL / Agent Arena 连接

- **veRL 旋钮对照表**：`entropy_coeff`（熵奖励）·`clip_ratio_high/low`（DAPO clip-higher）·`kl_loss_coef` + `use_kl_loss`（KL 侧）·`filter_groups`（DAPO dynamic sampling：过滤全对/全错组=零方差组，SNR 修复的数据侧，veRL 已内置）·`top_entropy_quantile`（TRL 系）·监控：`entropy/response_length/kl/ratio` 四个量进同一个 dashboard；
- **filter_groups 深挖**：max_num_gen_batches=5 内反复重采直到攒够有效组——本质就是**用采样算力换 SNR**，呼应 Day 136 的资源画像：rollout 反正占 43.8% 成本，多花 10% 采样换梯度质量是划算的；
- **Agent Arena 视角**：做 rollout provider 时，轨迹里**附带每个 token 的采样 logprob + 采样温度 + policy 版本号**（Day 136 版本 tag 的延续）= 让下游训练方能固化 old logprob、算 ratio、监控版本差——**数据格式里预留稳定性元字段，是 provider 的专业度分水岭**。

### 8. 高频速答（连环八问）

- **Q：GRPO 组基线为什么天然防一部分坍缩？** 全对/全错组 advantage 全零、梯度归零自动跳题——但它只消掉了任务项噪声，**正则化噪声还在**（RAGEN-2 的核心补充），所以 filter_groups 之后还要 SNR 感知正则。
- **Q：为什么熵会单调降？** softmax 策略下熵变化 ≈ −Cov(logp, Δlogit)，训练中该协方差恒正 → 熵只能往下走，前 1/12 步烧掉 73%。
- **Q：clip-higher 原理一句话？** 上界放松让低概率 exploration token 的更新不被砍掉——PPO-CLIP 的上界本质是"探索税"。
- **Q：模板坍缩和熵坍缩区别一句话？** 熵坍缩是**组内**多样性没了（越答越像），模板坍缩是**跨输入**多样性没了（什么题都答成同一个样）——而且后者熵可以很高。
- **Q：最便宜的模板坍缩检测？** 今日算法题：跨轨迹最长重复片段长度/轨迹长度比值，配 3σ 告警。
- **Q：rollout-train 不一致为什么有害？** ratio 偏离 1 → 近端信任域目标被改写 → clip 触发模式失真 → 有效学习率漂移（PyTorch Conf 闪电演讲题眼）。
- **Q：异步训练（Day 136）对稳定性加什么新风险？** staleness 放大 ratio 偏差 + 版本混组污染组基线——version manager 的 Δ 阈值就是稳定性防线。
- **Q：调参铁律？** 一次只改一个变量；每个实验固定 seed 并记录四元组（数据/超参/环境/代码版本）。

### 9. 金句收尾

> **「熵是 RL 的氧气——前 1/12 步烧掉 73% 没人报警，因为 reward 还在涨；等发现不涨的时候，模型已经憋死了。而模板坍缩更阴险：它让模型当着你的面高谈阔论，说的却全是与问题无关的背诵——检测它的唯一办法，不是问模型（Anthropic 刚承认模型的自我解释不可信），而是量它和输入之间的互信息。奖励方差是信噪比的分水岭：方差为零的组，正则化噪声称王。稳定性工程的全部艺术，就是在『奖励还在涨』的时候，就已经看见『多样性正在死』。」**
