## 一、今日算法题

### 题目：买卖股票的最佳时机 IV（LC 188）——含手续费版本（LC 714）＝ 成本归因思维的 DP 形态

**描述**

给定数组 `prices`，第 `i` 天价格为 `prices[i]`。你**最多完成 k 次交易**（一次交易 = 买入一次 + 卖出一次，不能同时持有两笔），求最大利润。

**进阶（成本归因版）**：每次卖出要付**手续费 `fee`**（买入免费）。求扣完手续费后的**最大净利润**。

```
示例 1（LC 188）：
prices = [3,2,6,5,0,3], k = 2
输出：7
解释：第 2 天买(2) 第 3 天卖(6) 赚 4；第 5 天买(0) 第 6 天卖(3) 赚 3；共 7。

示例 2（含手续费，LC 714）：
prices = [1,3,2,8,4,9], fee = 2
输出：8
解释：1 买 8 卖 赚 7-2=5；4 买 9 卖 赚 5-2=3；净利润 8。
     （若忽略手续费会算成 12 —— 差出来的 4 就是「摩擦」）
```

### 思路

**状态机 DP**：任何一天只有两种状态——`hold`（持有中）和 `cash`（空仓/已了结）。

**含手续费版（先易后难，成本归因主菜）：**

```
cash[i] = max(cash[i-1], hold[i-1] + prices[i] - fee)   // 继续空仓 vs 卖出并付手续费
hold[i] = max(hold[i-1], cash[i-1] - prices[i])         // 继续持有 vs 买入
```

- 手续费只挂在**卖出**动作上（等价于挂买入，单边建模即可，双边会重复计）。
- 初始化：`cash = 0`（不买立赚 0），`hold = -prices[0]`（第一天买入，浮亏）。
- 滚动数组 O(1) 空间。O(n) 时间。

**k 次交易版（LC 188 本体）：**

- `k >= n/2` 时退化为**无限次交易**（每天都可以卖），直接贪心：所有上升段都吃掉，`sum(max(0, p[i]-p[i-1]))`。
- 否则开 `k` 对状态：`buy[j]` = 第 j 次交易持有中的最大净值，`sell[j]` = 第 j 次已卖出的最大净值：
  ```
  buy[j]  = max(buy[j],  sell[j-1] - p)     // 上一次的钱拿去买
  sell[j] = max(sell[j], buy[j] + p)        // 卖出落袋
  ```
- 关键初始化：`buy[j] = -INF`（还没赚过钱），`sell[0] = 0`。一次交易内 buy→sell 成对转移，天然满足「不能重叠」。

### 代码（Go 完整实现）

```go
package main

import "fmt"

// LC 714: 含手续费 —— 成本归因版
func maxProfitFee(prices []int, fee int) int {
    cash, hold := 0, -prices[0]
    for i := 1; i < len(prices); i++ {
        cash = max(cash, hold+prices[i]-fee) // 卖出：落袋并扣摩擦
        hold = max(hold, cash-prices[i])     // 买入：用净利润接货
    }
    return cash
}

// LC 188: 最多 k 次交易
func maxProfitK(prices []int, k int) int {
    n := len(prices)
    if k >= n/2 { // 无限次：贪心吃光所有上升段
        ans := 0
        for i := 1; i < n; i++ {
            if prices[i] > prices[i-1] {
                ans += prices[i] - prices[i-1]
            }
        }
        return ans
    }
    const INF = int(^uint(0) >> 1)
    buy := make([]int, k+1)
    sell := make([]int, k+1)
    for j := range buy {
        buy[j] = -INF
    }
    for _, p := range prices {
        for j := 1; j <= k; j++ {
            buy[j] = max(buy[j], sell[j-1]-p)
            sell[j] = max(sell[j], buy[j]+p)
        }
    }
    return sell[k]
}

func max(a, b int) int { if a > b { return a }; return b }

func main() {
    fmt.Println(maxProfitK([]int{3, 2, 6, 5, 0, 3}, 2))      // 7
    fmt.Println(maxProfitFee([]int{1, 3, 2, 8, 4, 9}, 2))    // 8
    fmt.Println(maxProfitK([]int{2, 4, 1}, 2))               // 2
}
```

### 复杂度

- 手续费版：**O(n) 时间 / O(1) 空间**。
- k 次版：**O(n·k) 时间 / O(k) 空间**；k ≥ n/2 时贪心退化 O(n)。

### 面试三坑

1. **手续费挂在哪一边？** 挂卖出（或买入）单边即可，双边都挂会重复计。被追问「真实市场双边收费」→ 模型改成 `buy` 时也减 fee，结构不变。
2. **k 很大为什么退化？** n 天最多产生 ⌊n/2⌋ 个独立上升段（一买一卖至少占 2 天），k 超过这个数就是无限次——**上限由结构决定，不是由参数决定**，这句是分水岭答案。
3. **为什么不能用「每笔交易独立最优」贪心？** 交易共享资金池：买在低点占用了下次交易的本金。DP 的价值正在于**全局记账**——和成本归因同构：每个决策都要全局对账，不能局部最优拼全局。

### 进阶六连

1. **冷冻期版（LC 309）**：卖出后隔一天才能买 → `cash[i] = max(cash[i-1], hold[i-1]+p[i])`，`hold[i] = max(hold[i-1], cash[i-2]-p[i])` = 状态机加一条边。**映射：GPU 任务切换的 setup 时间就是冷冻期——今天调度省的钱要扣掉明天的冷启动。**
2. **每次交易有固定成本 + 比例成本**：fee = a + b·p → 卖出动作 `hold+p-a-b·p`，结构不变——**固定成本吃小额交易、比例成本吃大额交易，阈值以下不该交易** = 推理小请求不该上旗舰模型的经济学版。
3. **最多 k 次 + 手续费联合**： sell[j] 转移时扣 fee；k 的退化阈值随 fee 变化（摩擦太大时减少交易次数更优）——**手续费改变最优策略的结构**，这就是成本入模的 DP 语言。
4. **双变量维度爆炸时换排序键**：如果还有「每笔最大仓位限制」，变成二维 DP 背包；被问如何降维 → 按「单位摩擦收益」排序贪心 + 交换论证（呼应 Day 169 铁律：排序键 = 宣布优化什么）。
5. **数据流版（在线交易）**：价格流式到达 → 只能维护有限状态，k 维滚动；类比在线推理路由：请求流到达，你不能预知未来价格，只能按当前状态机决策（呼应 Day 169 在线 List Scheduling 2-竞争比）。
6. **对照现实：杠杆 ETF 的复利损耗**：2x 每日再平衡在高波动下的净值漂移 ≈ 每个交易日都付一笔「隐式手续费」。模拟面试被问「为什么高波动时 2x ETF 长期跑不到 2x」→ 每日调仓摩擦 + 复利路径依赖，正是本题的连续版。

## 二、工程映射：推理 Token 成本模型 —— 把一张账单拆成七行

今天的设计题（面试高频）：**「估一下你这个推理集群每百万 token 的成本，并给出三个降本抓手」**。标准拆法：

```
每 token 成本 = GPU 时价 × 单 token 占用时长 ÷ 有效并发
           = 硬件摊销 + 电力(PUE) + 网络/存储 + 运维人力
             ───────────────────────────────────────
             有效产出 token 数（扣掉空转·重算·碎片）
```

| 账单行 | 归因维度 | 工程抓手 |
|---|---|---|
| 硬件摊销 | GPU 购置价 ÷ 折旧年限（3-5 年）÷ 365 ÷ 24 | 提高利用率 = 摊薄分子（Day 169 路由）|
| 电力 | kWh × 电价 × PUE（1.2-1.5）÷ 有效 token | 潮汐调度 + 低 PUE 选址（Day 171）|
| 利用率 | MFU：实际算力 ÷ 峰值算力（decode 阶段天然低） | batch size、连续批处理、prefill/decode 分离 |
| KV 缓存 | 长上下文重复 prefill 的算力浪费 | prefix caching / 语义缓存命中率（Week 22）|
| 空转与碎片 | 排队、抢占损失、显存碎片装不下新 batch | 调度水位线 + 显存水位线（Day 169/171）|
| 失败重算 | 超时/报错重试的重复计费 | 熔断三旋钮 + 幂等（Day 161）|
| 折价项 | 缓存命中按 5-10% 计费的反向项 | 提高缓存命中率 = 直接增厚毛利 |

**三个降本抓手怎么选（按杠杆排序）**：① 利用率（分子分母同时动，10% 利用率提升 ≈ 摊薄所有固定成本 10%）；② 缓存命中率（直接砍掉 prefill 成本，命中率高 20 个点可能省 30% 算力）；③ 路由把请求放对机器（Day 169：已购算力的变现率）。

**单位经济学的三个决策指标**（被问「降本」先反问口径，再报这三个）：
- **cost per token**：供应商报价语言，CFO 语言；
- **cost per request**：产品语言（用户一次操作用多少 token）；
- **cost per correct / completed task**（呼应 Day 168 Gemini 4 Carbon 教训 + AI 周报「token 降价但单任务变贵」）：决策语言——**便宜模型要三次才做对时，它比贵模型贵**。

## 四、模拟面试速答四连

- **Q：客户要求降价 50%，怎么办？**
  A：先拆账不降本。七行账单里找出随规模改善的三行（利用率/缓存/路由），用「单位成本曲线」回应「降价要求」→ 同意按量阶梯降价，但绑定最低消费承诺（阿里节省计划模式：承诺换折扣）。**把降价谈判变成容量承诺谈判，成本模型就是你的筹码。**

- **Q：怎么证明你的推理集群是赚钱的？**
  A：三表：① 每 token 完全成本（七行账单）；② 每 token 收入（合同价×命中率折算）；③ 敏感性（电价 ±20%、利用率 ±10pp、缓存命中率 ±15pp 各对毛利影响多少）。**能报敏感性的成本模型才配进决策会。**

- **Q：token 降价了你为什么总账没降？（Jevons 之问）**
  A：单位成本降 ≠ 总成本降。Vercel 的 43.3% 数据就是行业实况——能力涨得比降价快，调用量弹性 > 1。容量规划要把「每 token 成本下降」和「总 token 需求弹性」乘起来看总账，再决定扩容节奏。

- **Q：2x 杠杆 ETF 为什么长期跑不到 2x？（用今天的 DP 答）**
  A：每日再平衡的调仓摩擦 + 复利路径依赖（波动率税）。把每天当作一次带手续费的交易：净值 = ∏(1 ± 2r_t − fee_t)，高波动下 ∏(1+2r) < 1+2∑r。**毛收益和净收益之间隔着摩擦，忽略摩擦的模型都是行为艺术**——这也是我们做 token 成本归因的同一句话。
