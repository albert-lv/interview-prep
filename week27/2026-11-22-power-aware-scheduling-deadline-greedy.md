## 一、今日算法题

### 题目：训练集群的潮汐排班——带 Deadline 与峰谷电价的任务调度

**描述**

你负责一台 GPU 训练节点（单机器）。有 `n` 个训练任务，第 `i` 个任务：

- 需要**连续/累计运行** `t_i` 小时（功耗恒定，1 单位/小时）；
- 必须在 `deadline d_i` **之前完成**（即占用的时间槽都 `< d_i`，时间槽从 0 编号）。

电价曲线 `price[h]` 表示第 `h` 小时的电价（元/单位功耗）。

**问题一（经典版）**：任务不可抢占。求**最多能完成多少个任务**？

**问题二（进阶版）**：任务**可抢占**（工程上靠 checkpoint/restore，把任务切成任意多小时执行，总时长仍为 `t_i`）。要求**完成全部任务**，求**最小总电费**；若无法全部完成返回 `-1`。

```
示例（问题二）：
tasks = [{t:3, d:5}, {t:2, d:3}]   price = [5, 1, 4, 2, 10]
解释：槽位 0..4 价格 5,1,4,2,10；任务按 deadline 排序先处理 {2,3}，
     占据 [0,3) 内最便宜的 2 个槽：槽1(1)、槽2(4)；
     再处理 {3,5}，在 [0,5) 剩余槽位中最便宜 3 个：槽3(2)、槽0(5)、槽4(10)。
     最小电费 = 1+4+2+5+10 = 22。
```

### 思路

**两个问题共用同一个骨架：按 deadline 升序处理 + 交换论证。** 这是 deadline 类调度问题的通用套路。

**问题一（LC 630 课程表 III 变体）：**

1. 按 `d` 升序排序；
2. 顺序扫描，维护已选任务的**时长最大堆**和累计占用 `cur`；
3. 每来一个任务：`cur += t`，入堆；若 `cur > d`，说明超期，**弹出堆顶（耗时最长）的任务**，`cur -= t`。

**为什么对（交换论证）**：排序后，所有已处理任务的 deadline 都不晚于当前任务。一旦累计时长超过当前 deadline，必须抛弃一个任务；抛弃"耗时最长"的那个是最优的——在 deadline 同样满足的前提下，它占用资源最多、释放的收益最大。若最优解抛弃的是更短的任务，把"最长任务换成短任务"不劣于它。

**问题二（可抢占 + 电价最小化）：**

1. 按 `d` 升序排序（EDF 顺序）；
2. 维护 `used[]` 槽位占用表。逐个任务处理：在 `[0, d_i)` 的**空闲槽位中挑最便宜的 `t_i` 个**占掉，累加电费；
3. 若 `[0, d_i)` 内空闲槽位不足 `t_i`，返回 `-1`（容量不可行）。

**为什么对（交换论证）**：按 EDF 顺序，后处理的任务 deadline 更晚，其可用槽位集合 `[0, d)` 是前面任务的**超集**。设当前处理的任务 `J` 是剩余中 deadline 最紧的，某个最优解给 `J` 安排了槽位集合 `S_O`。`J` 的最优槽位必然可以替换成 `[0, d_J)` 内最便宜的 `t_J` 个槽 `S_G`：把 `J` 挪进 `S_G`，原来占用 `S_G` 的其他任务 `K`（`d_K ≥ d_J`）可以挪到 `J` 让出的 `S_O` 里——因为 `S_O ⊆ [0, d_J) ⊆ [0, d_K)`，对 `K` 依然可行，且电费不增（`S_G` 是最便宜选择）。逐次替换下去，贪心解不劣于最优解。∎

**一句话记忆**：*deadline 题先排序；不可抢占用最大堆"丢最长的"，可抢占用"紧任务先挑便宜槽"。*

### Go 代码

```go
package main

import (
	"container/heap"
	"fmt"
	"sort"
)

type Task struct {
	T int // 运行时长（小时）
	D int // deadline：占用的时间槽必须 < D
}

// ---- 问题一：不可抢占，最多完成多少个任务（LC 630 变体） ----
type MaxHeap []int

func (h MaxHeap) Len() int           { return len(h) }
func (h MaxHeap) Less(i, j int) bool { return h[i] > h[j] } // 大顶堆
func (h MaxHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *MaxHeap) Push(x any)         { *h = append(*h, x.(int)) }
func (h *MaxHeap) Pop() any {
	old := *h
	n := len(old)
	v := old[n-1]
	*h = old[:n-1]
	return v
}

func MaxTasks(tasks []Task) int {
	sort.Slice(tasks, func(i, j int) bool { return tasks[i].D < tasks[j].D })
	h := &MaxHeap{}
	heap.Init(h)
	cur := 0
	for _, tk := range tasks {
		cur += tk.T
		heap.Push(h, tk.T)
		if cur > tk.D { // 超期：丢弃已选中最耗时的任务
			cur -= heap.Pop(h).(int)
		}
	}
	return h.Len()
}

// ---- 问题二：可抢占（checkpoint/restore），完成全部任务的最小电费 ----
func MinCostAllTasks(tasks []Task, price []int) int {
	sort.Slice(tasks, func(i, j int) bool { return tasks[i].D < tasks[j].D })
	T := len(price)
	used := make([]bool, T)
	cost := 0
	for _, tk := range tasks {
		need, lim := tk.T, tk.D
		if lim > T {
			lim = T
		}
		for h := 0; h < lim && need > 0; h++ { // 前缀内从最便宜的空闲槽开始占
			if !used[h] {
				used[h] = true
				cost += price[h]
				need--
			}
		}
		if need > 0 {
			return -1 // deadline 前容量不足，不可行
		}
	}
	return cost
}

func main() {
	// {t:1,d:2} {t:2,d:4} {t:2,d:5} {t:3,d:5}：最多完成 3 个（{1,2}+{2,4}+{2,5} = 5h 刚好排下）
	fmt.Println(MaxTasks([]Task{{1, 2}, {2, 4}, {2, 5}, {3, 5}}))                  // 3
	fmt.Println(MinCostAllTasks([]Task{{2, 3}, {3, 5}}, []int{5, 1, 4, 2, 10})) // 22
}
```

### 复杂度

| 问题 | 时间 | 空间 |
|------|------|------|
| 问题一（不可抢占） | **O(n log n)** | O(n) |
| 问题二（可抢占，实现版） | **O(n · T)**（T = max deadline） | O(T) |

**进阶追问（面试加分项）**：当 `T` 很大（如一年 8760 小时 × 多年）时，"前缀内挑 k 个最便宜空闲槽"可用**离线预处理 + 平衡树/树状数组**优化到 O((n + T) log T)；若槽位价格有结构化特征（峰谷分段），还可以用并查集维护"下一段空闲槽"。

### Follow-ups（面试官可能的追问）

1. **抢占但有切换开销**（每次 checkpoint/restore 有固定成本 `c`）→ 任务被切成段数受限，问题退化为"分段数 ≤ k"的约束优化，可用 DP：`dp[i][k]` 表示前 `i` 个任务切 `k` 段的最小成本。
2. **多机版**：`m` 台机器 → 问题一变成负载均衡 + deadline 的 NP-hard 问题，可讲 LPT 近似（呼应 Day 169）；问题二的可抢占版本可按"槽位 × 机器"并行度扩展贪心。
3. **Online 版**：任务陆续到达、电价实时变化 → 常用"预测 + 滚动时域（rolling horizon）"，训练任务当 flexible load，推理请求当刚性负载。
4. **碳强度多目标**：把 `price[h]` 换成合并成本 `λ·price[h] + (1−λ)·carbon[h]`，或求 Pareto 前沿（电费 vs 碳排）——这是"碳感知调度"的面试加分话术。

## 二、面试技巧

### 🔥 用今日热点讲"电力成本"的三个层次

今天 NVIDIA 被 SEC + 加州 AG 双重调查、单周蒸发 9,000 亿美元，表面是会计和治理问题，底层是同一个焦虑：**AI 基础设施的成本结构和需求真实性**。面试中谈"电力成本与潮汐调度"，要展示出你能把这个宏观议题落到系统设计。

### 技巧一：把"省电"翻译成目标函数，而不是口号

面试官想听的不是"我们会错峰训练"，而是"**你的调度器在优化什么**"。标准的三层成本模型：

- **电量电费**（kWh × 分时电价）：可时移负载（训练、批量推理、评测）的主战场；
- **容量电费 / 需量电费**（demand charge，按峰值功率计费）：这就是为什么潮汐调度要和功率封顶（power capping）联动——把集群功率削平，可能比挪几个小时更省钱；
- **PUE 折算与碳强度**：同样 1 kWh，白天和夜间、不同区域电网的碳强度差异巨大（WattTime / Electricity Maps 数据）。

**一句话速答**：*"我们的目标函数是三层的：分时电价决定'什么时候跑'，需量电费决定'跑多快'，碳强度决定'在哪跑'——训练任务做时移，推理流量做功率封顶。"*

### 技巧二：讲清楚"为什么推理和训练必须混部"——以及混部的代价

这是 infra 岗的高频追问。好的回答分三点：

1. **资源画像互补**：训练是"重计算、可延迟、可抢占"（deadline 以天计）；推理是"重显存、有 SLO、刚性"（延迟以毫秒计）。混部让一个集群全天打满：推理低谷期（夜间）跑训练，高峰期训练让路。
2. **抢占的工程前提**：今天 NVIDIA 发布的 **Snapshot（GPU checkpoint/restore <45s）** 就是让抢占变便宜的关键——没有秒级 checkpoint，"抢占训练任务"的代价高到混部不划算。面试时把这个工程细节和算法题里"可抢占假设"对应起来，会非常加分。
3. **代价也要主动说**：混部的成本是**噪声邻居**（训练流量打爆 NVLink/显存带宽，推理 P99 抖动）和**碎片**（推理要连续显存，训练占着不放）。工程解法：cgroup / MPS 隔离、显存水位线、推理优先级抢占 + 训练 checkpoint 粒度调优。

**一句话速答**：*"混部不是资源复用一句话，是'训练可时移、推理有 SLO'两个画像互补；前提是 checkpoint 足够快（NVIDIA Snapshot 已把 GPU 快照压到 45s 内），代价是噪声邻居和显存碎片，用隔离 + 水位线兜底。"*

### 技巧三：用"财务尽调视角"回答容量与需求质疑（今日 NVDA 事件的正确打开方式）

NVDA 这周崩掉的直接诱因，是市场对 **neocloud 循环融资、应收账期 64 天、芯片转口** 的质疑——本质是在问："**需求是真的吗？现金流撑得住吗？**" 如果面试官问"如果客户砍单 30%，你的容量规划怎么办"，很多人的回答是"留 buffer"，更好的回答是引入**对冲结构**：

1. **电价合同对冲**：签固定电价合约锁定基线（对应刚性推理负载），现货/实时电价只覆盖弹性部分（训练）——需求下滑时弹性部分自动收缩，成本同步下降；
2. **可抢占优先级分层**：推理（刚性）> 客户训练（合同 deadline）> 内部实验（best-effort）。砍单时从底部自动收缩，刚性 SLO 不受影响；
3. **折旧与利用率视角**：GPU 折旧按天计提，空转就是烧钱——潮汐调度的 ROI 可以用"每度电产出的 token 数"来度量（呼应 Day 172 明天的单位经济学专题）。

**一句话速答**：*"我把容量拆成'合约基线 + 弹性现货'两层：基线对冲刚性推理负载，弹性层吃训练任务；需求波动时弹性层自动伸缩，配合固定电价合约，砍单 30% 时成本是非线性地往下掉，而不是等比例出血。"*

### 面试官会怎么问（今日模拟）

1. **问**："训练任务挪到夜间，推理白天高峰期怎么办？训练被抢占了不就白跑了？"
   **答**："所以工程前提是 checkpoint 够快（NVIDIA Snapshot 已 <45s）+ 抢占粒度够小。白跑的部分 = 从上次 checkpoint 到被抢占点的进度，靠缩短 checkpoint 间隔把损失压到百分之几以内；这正好对应算法题里'可抢占假设'的现实含义。"
2. **问**："电价预测错了怎么办？调度器依赖预测会不会被反噬？"
   **答**："用 rolling horizon：只承诺未来几小时的调度决策，电价和任务队列滚动更新；训练任务 deadline 越近优先级越高，预测误差由'可时移余量'吸收。"
3. **问**："碳强度和电费打架时怎么选？"
   **答**："看公司口径：对外承诺（24/7 carbon-free）是硬约束，内部优化是软目标；实际做法是把 `λ·price + (1−λ)·carbon` 合成一条成本曲线喂给调度器，λ 由 ESG 目标定。"
