## 一、今日算法题

### 题目：腐烂的橘子（Rotting Oranges）

**LeetCode 994** | 难度：🟡 中等 | 推荐指数：⭐⭐⭐⭐⭐

---

### 题目描述

在给定的 `m × n` 网格中，每个单元格可以有以下三个值之一：

- `0` 表示空单元格
- `1` 表示新鲜橘子
- `2` 表示腐烂橘子

每分钟，任何与腐烂橘子**相邻**（上下左右）的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的**最小分钟数**。如果不可能，返回 `-1`。

**示例 1：**

```
输入: grid = [[2,1,1],[1,1,0],[0,1,1]]
输出: 4
```

**示例 2：**

```
输入: grid = [[2,1,1],[0,1,1],[1,0,1]]
输出: -1
解释: 左下角的橘子（第 2 行，第 0 列）永远不会腐烂。
```

---

### 核心思路：多源 BFS 🍊

这道题是 **BFS 的经典进阶**。和昨天的"岛屿数量"不同，这里有**多个起点**（所有腐烂橘子同时开始扩散）。

**关键洞察：**
1. 所有初始腐烂橘子是**同一时刻开始"发功"**的
2. 每分钟，腐烂向四周扩散一层
3. 问"最少需要多少分钟"= 问 BFS 的最大层数

**所以这不是普通 BFS，是多源 BFS（Multi-source BFS）。**

> 💡 对比记忆：
> - 单源 BFS（如岛屿数量）：从一个起点扩散，找最短路径
> - 多源 BFS（如腐烂橘子）：从多个起点同时扩散，求最晚被覆盖的时间

---

### 代码实现（Python）

```python
from collections import deque

class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        queue = deque()
        fresh = 0  # 统计新鲜橘子数量

        # Step 1: 初始化 —— 所有腐烂橘子入队，同时统计新鲜橘子
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 2:
                    queue.append((r, c))
                elif grid[r][c] == 1:
                    fresh += 1

        # 没有新鲜橘子，直接返回 0
        if fresh == 0:
            return 0

        minutes = 0
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        # Step 2: BFS 层层扩散
        while queue and fresh > 0:
            minutes += 1
            # 关键：只处理当前层的节点
            for _ in range(len(queue)):
                r, c = queue.popleft()
                for dr, dc in directions:
                    nr, nc = r + dr, c + dc
                    # 越界、空单元格、已腐烂，都跳过
                    if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                        grid[nr][nc] = 2  # 腐烂它！
                        fresh -= 1
                        queue.append((nr, nc))

        # Step 3: 检查是否还有新鲜橘子
        return minutes if fresh == 0 else -1
```

---

### 为什么是多源 BFS？

普通 BFS 从一个起点开始。但这道题有**多个腐烂橘子同时发功**，如果把每个腐烂橘子都当作一次独立 BFS，效率极低。

**聪明做法：把所有初始腐烂橘子一起入队，当作第 0 层。**

这样，每一轮 while 循环对应"过了一分钟"，所有当前在队列里的腐烂橘子同时向四周扩散。

```
初始：queue = [(0,0), (2,2)]  ← 两个腐烂橘子同时入队

第 1 分钟：从 (0,0) 和 (2,2) 同时扩散
第 2 分钟：从第 1 分钟新腐烂的橘子继续扩散
...
```

---

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(M × N) | 每个格子最多入队一次 |
| **空间** | O(M × N) | 队列最坏情况装所有格子 |

---

### 🎯 常见变体 & 扩展

| 变体 | 思路 |
|------|------|
| "求最后被腐烂的橘子坐标" | BFS 过程中记录最后处理的节点 |
| "有障碍物的版本" | 把 `0` 当作不可通行，其他同上 |
| "每个橘子腐烂速度不同" | 带权 BFS，需要用 Dijkstra |

## 二、面试技巧

### 🤝 如何"从不会聊到思路"

这道题看起来描述很生活化（橘子腐烂），但抽象一下很清晰：

**推荐话术：**

> "这道题的本质是**多源扩散问题**。每个腐烂橘子是一个扩散源，每分钟扩散到相邻新鲜橘子。我需要一个方法能同时追踪所有扩散源的状态... 这让我想到 BFS，但普通的单源 BFS 不够，需要**多源 BFS** —— 把所有初始腐烂橘子同时放入队列。"

**关键要提到：**
1. 识别出"多源同时扩散"的特征
2. 说明为什么不用 DFS（DFS 是一条路走到黑，不适合"最短/最短时间"问题）
3. 提到"层数 = 分钟数"的对应关系

---

### 🎯 常见追问 & 满分回答

| 追问 | 面试官想考察 | 回答要点 |
|------|-------------|---------|
| "为什么不用 DFS？" | 算法选择能力 | "DFS 能找到一条腐烂路径，但不一定是最短的。BFS 按层扩散，天然适合求最短时间。" |
| "如果只有一个腐烂橘子呢？" | 对多源 BFS 的理解 | "那就是单源 BFS 了，代码不用改，逻辑完全兼容。" |
| "怎么知道最后有没有新鲜橘子剩下？" | 边界情况处理 | "初始化时统计 fresh 数量，每次腐烂一个就减 1，最后检查是否为 0。" |
| "空间能优化吗？" | 原地修改的理解 | "可以原地把 `1` 改 `2`，不需要额外 visited 数组，已经这么做了。" |

---

### 📝 代码书写技巧

1. **先统计 fresh 数量**：面试官看你有没有考虑"一开始就没有新鲜橘子"的情况
2. **`for _ in range(len(queue))` 是精髓**：确保每次只处理当前层的节点，这样 `minutes += 1` 才正确
3. **提前返回优化**：`if fresh == 0: return 0` —— 展示你考虑边界

---

### 💡 面试常犯的错误

| 错误 | 为什么错 | 怎么改 |
|------|---------|--------|
| 用 DFS | 找不到最短时间 | 改用 BFS |
| 不用 `len(queue)` 控制层数 | 分钟数统计错误 | 用 `for _ in range(len(queue))` 分层 |
| 忘记检查最后 fresh 是否为 0 | 返回了错误答案 | 最后 `return minutes if fresh == 0 else -1` |
| 每次只入队一个腐烂橘子 | 复杂度爆炸 | 所有初始腐烂橘子一起入队 |
