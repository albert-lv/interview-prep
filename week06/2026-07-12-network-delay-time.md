## 一、今日算法题

### 题目：网络延迟时间（Network Delay Time）

**LeetCode 743** | 难度：🟡 中等 | 推荐指数：⭐⭐⭐⭐⭐

---

### 题目描述

有 `n` 个网络节点，标记为 `1` 到 `n`。给你一个列表 `times`，表示信号经过有向边的传递时间。`times[i] = (u, v, w)`，其中 `u` 是源节点，`v` 是目标节点，`w` 是一个信号从源节点传递到目标节点的时间。

现在，从某个节点 `K` 发出一个信号。需要多久才能使所有节点都收到信号？如果不能使所有节点收到信号，返回 `-1`。

**示例 1：**

```
输入：times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2
输出：2
```

**示例 2：**

```
输入：times = [[1,2,1]], n = 2, k = 1
输出：1
```

**示例 3：**

```
输入：times = [[1,2,1]], n = 2, k = 2
输出：-1
```

---

### 核心思路：Dijkstra 算法 — 单源最短路经典框架 🛣️

这道题的本质是：**在一个有向带权图中，求从源点 K 到所有其他节点的最短距离，取其中的最大值。** 如果有些节点不可达，返回 -1。

**Dijkstra 算法** 是解决单源最短路径问题的经典算法，核心思想是：

> **贪心策略**：每次从未确定最短路径的节点中，选择距离源点最近的那个，确定它的最短距离，然后用它去松弛（更新）邻接节点的距离。

**为什么能用贪心？** 因为图中边的权重都是非负数。如果存在负权边，Dijkstra 就不适用了，需要用 Bellman-Ford 或 SPFA。

**两种实现方式：**
- **朴素版本**：O(V²)，用数组找最小距离节点
- **堆优化版本**：O(E log V)，用优先队列（小根堆）找最小距离节点

**面试中推荐写堆优化版本，时间复杂度更优，也更能展示你的数据结构功底。**

---

### 代码实现：Dijkstra（堆优化）

```python
import heapq
from typing import List

class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        # 1. 构建邻接表：graph[u] = [(v, w), ...]
        graph = [[] for _ in range(n + 1)]  # 节点编号 1~n
        for u, v, w in times:
            graph[u].append((v, w))

        # 2. 初始化距离数组，dist[i] 表示从 K 到 i 的最短距离
        INF = float('inf')
        dist = [INF] * (n + 1)
        dist[k] = 0  # 源点到自己的距离为 0

        # 3. 优先队列：(当前距离, 节点编号)
        # 堆顶始终是目前距离源点最近的未确定节点
        heap = [(0, k)]

        while heap:
            d, u = heapq.heappop(heap)

            # 如果当前距离已经比记录的大，跳过（旧数据）
            if d > dist[u]:
                continue

            # 用 u 松弛所有邻接节点
            for v, w in graph[u]:
                if dist[u] + w < dist[v]:
                    dist[v] = dist[u] + w
                    heapq.heappush(heap, (dist[v], v))

        # 4. 找最大距离（即信号到达所有节点的最短时间）
        max_dist = max(dist[1:])  # 忽略 dist[0]，节点从 1 开始
        return max_dist if max_dist != INF else -1
```

---

### 为什么这样能找到最短路？

**核心直觉：一旦一个节点被从堆中取出（即它的最短距离被"确定"），就不会再被更新。**

```
示例：times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2

建图：
  1 <--1-- 2 --1--> 3 --1--> 4

Step 1: 初始化 dist = [INF, INF, 0, INF, INF]
        堆 = [(0, 2)]

Step 2: 弹出 (0, 2)，松弛邻接节点
        dist[1] = min(INF, 0+1) = 1 → 堆加入 (1, 1)
        dist[3] = min(INF, 0+1) = 1 → 堆加入 (1, 3)
        dist = [INF, 1, 0, 1, INF]

Step 3: 弹出 (1, 1)，没有出边，跳过

Step 4: 弹出 (1, 3)，松弛邻接节点
        dist[4] = min(INF, 1+1) = 2 → 堆加入 (2, 4)
        dist = [INF, 1, 0, 1, 2]

Step 5: 弹出 (2, 4)，没有出边，跳过

堆为空，结束。max_dist = 2，返回 2 ✅
```

### 朴素版本（不用堆）

```python
class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        # 构建邻接矩阵或邻接表
        graph = [[-1] * (n + 1) for _ in range(n + 1)]
        for u, v, w in times:
            graph[u][v] = w

        INF = float('inf')
        dist = [INF] * (n + 1)
        dist[k] = 0
        visited = [False] * (n + 1)

        for _ in range(n):
            # 找未访问节点中距离最小的
            u = -1
            min_dist = INF
            for i in range(1, n + 1):
                if not visited[i] and dist[i] < min_dist:
                    min_dist = dist[i]
                    u = i

            if u == -1:
                break

            visited[u] = True

            # 松弛 u 的所有邻接节点
            for v in range(1, n + 1):
                if graph[u][v] != -1 and dist[u] + graph[u][v] < dist[v]:
                    dist[v] = dist[u] + graph[u][v]

        max_dist = max(dist[1:])
        return max_dist if max_dist != INF else -1
```

> 朴素版本每次用线性搜索找最小距离节点，时间复杂度 O(V²)。对于稠密图（E ≈ V²），朴素版本可能比堆优化更快；但对于稀疏图，堆优化更优。面试中两种都要能写出来，根据题目特点选择。

---

### 复杂度分析

| 实现方式 | 时间复杂度 | 空间复杂度 | 适用场景 |
|---------|-----------|-----------|---------|
| **堆优化** | O(E log V) | O(V + E) | 稀疏图（大多数面试题） |
| **朴素版本** | O(V²) | O(V²) | 稠密图、节点数较少时 |

> **关键点**：面试中如果节点数 n ≤ 10⁴，边数 times ≤ 10⁴，堆优化版本更安全。如果面试官说"数据范围很小"，写朴素版本也 OK。

---

### 🎯 扩展：为什么要判断 `d > dist[u]`？

这是堆优化 Dijkstra 中一个经典技巧。**同一个节点可能被多次入堆**，因为每次发现更短路径时都会 push 一次。当堆顶的 `(d, u)` 中 `d` 已经大于当前记录的 `dist[u]`，说明这个 entry 是"过期数据"，直接跳过。

没有这个判断，算法仍然正确，但会多做一些无效操作。加上它，时间复杂度严格保证为 O(E log V)。

### 🤝 如何"从不会聊到思路"

这道题表面是网络延迟，本质是图的最短路问题。

**推荐话术结构：**

> "看到'从节点 K 到所有节点的最短时间'，我意识到这是一个**单源最短路**问题。图中边有权重（传输时间），而且是**非负权重**，所以适合用 **Dijkstra 算法**。如果存在负权边，我会考虑 Bellman-Ford 或 SPFA..."

**面试官想听的：**
1. 你能把"网络延迟"抽象成带权有向图的最短路问题
2. 你知道 Dijkstra 的适用条件（非负权边）
3. 你能对比不同最短路算法的适用场景

---

### 🎯 常见追问 & 满分回答

| 追问 | 面试官想考察 | 回答要点 |
|------|-------------|---------|
| "Dijkstra 和 BFS 有什么区别？" | 算法本质理解 | "BFS 解决无权图最短路（边权全为1），Dijkstra 解决非负权图最短路（边权任意非负数）。Dijkstra 可以看作 BFS 的加权版本，用优先队列代替普通队列。" |
| "如果边权有负数怎么办？" | 知识广度 | "Dijkstra 要求非负权边。如果有负权边，需要用 Bellman-Ford（O(VE)）或 SPFA（平均 O(E)，最坏 O(VE)）。如果还有负权环，Bellman-Ford 可以检测出来。" |
| "堆优化和朴素版本怎么选？" | 算法选型 | "稀疏图（E ≈ V）选堆优化 O(E log V)；稠密图（E ≈ V²）选朴素版本 O(V²)，常数更小。" |
| "时间复杂度为什么是 O(E log V)？" | 复杂度分析 | "每个节点最多入堆出堆一次，堆操作 O(log V)，共 V 次。每条边最多引发一次松弛和入堆，共 E 次。总体 O(E log V)。" |
| "如果要求输出最短路的路径呢？" | 进阶思考 | "在更新 dist[v] 时，同时记录 `pre[v] = u`。最后用 pre 数组回溯即可得到完整路径。" |
| "多源最短路怎么做？" | 知识迁移 | "可以建一个超级源点，连向所有源点（边权为0），然后跑 Dijkstra；或者每个源点各跑一次 Dijkstra。Floyd 算法也能处理多源最短路，但时间复杂度 O(V³) 较高。" |

### 📝 代码书写技巧

1. **节点编号注意**：这道题节点从 1 开始编号，数组要开 `n + 1` 的大小，遍历时从 1 开始
2. **邻接表 vs 邻接矩阵**：稀疏图用邻接表，稠密图用邻接矩阵。面试中默认用邻接表
3. **堆中的过期数据**：记得判断 `if d > dist[u]: continue`，避免用旧距离去松弛
4. **INF 的处理**：最后检查 `max_dist != INF`，区分"可达但距离很大"和"不可达"
5. **图不连通的边界情况**：如果堆为空但还有节点没被访问，说明图不连通，返回 -1

---

### 💡 面试常犯的错误

| 错误 | 为什么错 | 怎么改 |
|------|---------|--------|
| 用 BFS 做（普通队列） | BFS 只能处理无权图 | 带权图必须用 Dijkstra（优先队列）或 Bellman-Ford |
| 忘记处理不可达节点 | 返回了错误的 max_dist | 检查 `max_dist != INF`，否则返回 -1 |
| 节点编号从 0 开始 | 题目明确节点 1~n | 数组开 `n+1`，遍历时 `range(1, n+1)` |
| Dijkstra 用于负权图 | 贪心策略失效，结果错误 | 负权边用 Bellman-Ford 或 SPFA |
| 邻接表存成无向图 | 网络延迟是有向的 | `times[i] = (u, v, w)` 是单向边 |
