## 今日算法题

### 题目描述

给你一个二维整数数组 `envelopes`，其中 `envelopes[i] = [wi, hi]`，表示第 `i` 个信封的宽度和高度。

当另一个信封的**宽度和高度都比这个信封大**的时候，这个信封就可以放进另一个信封里，如同俄罗斯套娃一样。

请计算最多能有多少个信封能组成一组"俄罗斯套娃"信封（即可以把一个信封放到另一个信封里面）。

**注意**: 不允许旋转信封。

**示例**:
```
输入: envelopes = [[5,4],[6,4],[6,7],[2,3]]
输出: 3
解释: 最多信封的个数为 3, 组合为: [2,3] => [5,4] => [6,7]
```

**提示**:
- `1 <= envelopes.length <= 10^5`
- `envelopes[i].length == 2`
- `1 <= wi, hi <= 10^5`

---

### 解题思路

这道题的核心是**降维 + LIS 二分优化**。

#### 第一步：直觉的 DP 想法

如果直接按某个维度排序，然后对另一个维度求最长递增子序列，看似可行：
- 按宽度升序排序
- 在高度数组上求 LIS

但有个陷阱：**宽度相同的信封不能互相套**。如果宽度相同，即使高度递增，也不能选多个。

#### 第二步：处理宽度相同的冲突

排序策略：
- **宽度升序**，这样宽度小的排前面
- **宽度相同时，高度降序**

为什么高度要降序？
> 假设有两个信封 `[6,4]` 和 `[6,7]`，宽度都是 6。如果高度也升序排成 `[6,4], [6,7]`，那么在高度数组 `[4, 7]` 上求 LIS 会得到长度 2，误以为这两个信封可以套娃。
>
> 但如果高度降序排成 `[6,7], [6,4]`，高度数组是 `[7, 4]`，LIS 长度就是 1，正确反映了"宽度相同的只能选一个"。

#### 第三步：在高度上求 LIS（二分优化版）

经典 LIS 二分优化：
- 维护一个 `tails` 数组，`tails[i]` 表示长度为 `i+1` 的递增子序列的最小结尾元素
- 对于每个高度 `h`，用二分查找找到 `tails` 中第一个 `>= h` 的位置，替换掉它
- 如果 `h` 比所有末尾都大，就扩展 `tails`

这样可以把 O(n²) 降到 **O(n log n)**。

---

### 代码实现

```python
from bisect import bisect_left

class Solution:
    def maxEnvelopes(self, envelopes: List[List[int]]) -> int:
        # 关键排序：宽度升序，宽度相同则高度降序
        # 这样宽度相同的信封在高度上形成"阻碍"，不会被同时选入 LIS
        envelopes.sort(key=lambda x: (x[0], -x[1]))
        
        # 在高度数组上求 LIS（二分优化版）
        heights = [h for w, h in envelopes]
        
        tails = []  # tails[i] = 长度为 i+1 的递增子序列的最小结尾高度
        
        for h in heights:
            # 找到第一个 >= h 的位置
            pos = bisect_left(tails, h)
            
            if pos == len(tails):
                # h 比所有末尾都大，可以接在后面，LIS 长度 +1
                tails.append(h)
            else:
                # 替换，保持 tails 尽可能小（贪心思想）
                tails[pos] = h
        
        return len(tails)
```

---

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | **O(n log n)** | 排序 O(n log n) + LIS 二分 O(n log n) |
| 空间 | **O(n)** | `tails` 数组，最坏情况存储 n 个元素 |

> 💡 如果不用二分优化，纯 DP 解法是 O(n²)，对于 `n <= 10^5` 会直接超时。

---

### 关键要点总结

1. **排序策略是灵魂**：`(宽升序, 高降序)`，这一步错了后面全崩
2. **降维思想**：二维问题 → 排序后变成一维 LIS 问题
3. **二分优化的本质**：`tails` 数组维护的是"长度为 k 的递增子序列的最小结尾"，贪心替换保证最优子结构
4. **边界情况**：宽度全相同 → 高度降序保证只选一个；高度全相同 → 只能选 1 个

## 面试技巧

### 🔥 高频考点：排序 + DP 优化

这类题在面试中属于" Hard 题里的中等 Hard"——思路清晰就能写对，但面试者常常卡在两个地方：

**卡壳点 1：为什么高度要降序？**
- 错误回答："随便排的" ❌
- 正确回答："宽度相同时不能互相套娃，所以我要让同宽度的信封在高度上呈递减，这样 LIS 不会选到同一个宽度的多个信封。"

**卡壳点 2：LIS 二分优化的原理说不清楚**
- 要能解释 `tails` 数组的含义
- 要能说明为什么替换操作是对的（贪心：更小的结尾更利于后面接更多元素）

### 🗣️ "从不会做聊到思路"话术模板

> "这道题我第一眼想到的是二维 LIS，但纯二维 DP 会超时。我先想想能不能降维——如果我们固定一个维度，另一个维度就变成一维 LIS 了。"
>
> "按宽度排序后，问题变成在高度上找最长递增子序列。但有个问题：宽度相同的不能算。所以我的处理方式是……（接排序策略）"
>
> "一维 LIS 用 DP 是 O(n²)，数据范围 10^5 会超时，所以我用二分优化到 O(n log n)。"

### 🎯 面试官可能追问

1. **"如果不限制旋转信封呢？"**
   - 每个信封可以旋转，即 `[w, h]` 和 `[h, w]` 等价
   - 预处理：对每个信封，保证 `w <= h`（或统一某种规则），再按原题做

2. **"如果要求输出具体选了哪些信封呢？"**
   - 二分优化版的 LIS 不方便输出具体序列
   - 需要额外维护 `parent` 数组记录前驱，或者先用 O(n²) 的 DP 写法存路径

3. **"时间复杂度还能优化吗？"**
   - 排序是瓶颈，O(n log n) 已经是下界（基于比较的排序）
   - 如果宽度范围很小（比如 `wi <= 1000`），可以用计数排序做到 O(n + W)
