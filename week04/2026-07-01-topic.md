## 今日算法题

### 题目描述

有 `n` 位学生和 `n` 位导师，需要你为每位学生**恰好分配一位不同的导师**（一对一匹配）。

给定 `n × n` 的兼容性评分矩阵 `compatibility`，其中 `compatibility[i][j]` 表示第 `i` 位学生与第 `j` 位导师的兼容度评分。

请返回**最大总兼容性评分和**。

**约束条件**:
- `1 <= n <= 8`（注意：n 很小，这是状压 DP 的关键信号）
- `compatibility[i][j]` 为整数（通常范围 `0` 到 `100` 左右）

**示例**:
```
输入: compatibility = [[3, 1], [2, 4]]  (n=2)
输出: 6
解释: 学生0→导师1(1), 学生1→导师0(2) → 总评分 1+2=3
       学生0→导师0(3), 学生1→导师1(4) → 总评分 3+4=6 ✓
```

---

### 解题思路

#### 第一步：识别信号
拿到题目先扫一眼约束：`n <= 8`。这个量级极其关键——它暗示了 **2^n 级别的算法** 是完全可以接受的（`2^8 = 256`），状态压缩 DP 是天然的选择。

如果 n <= 20，也要考虑状压；如果 n <= 10~12，那是状压的"舒适区"。

#### 第二步：状态设计
用 `mask` 的二进制位表示导师的分配状态：
- `mask` 的第 `j` 位为 `1` → 导师 `j` 已被分配
- `mask` 中 `1` 的个数（popcount）→ 已经分配了多少位学生，也即当前该分配第 `i = popcount(mask)` 位学生

定义 `dp[mask]`：当已分配导师集合为 `mask` 时，能达到的**最大兼容性评分和**。

#### 第三步：状态转移
当前要分配第 `i` 位学生（`i = popcount(mask)`），枚举所有**尚未分配**的导师 `j`：

```
dp[mask | (1 << j)] = max(dp[mask | (1 << j)], dp[mask] + compatibility[i][j])
```

#### 第四步：初始化与答案
- `dp[0] = 0`（什么都不分配，评分为 0）
- 答案：`dp[(1 << n) - 1]`（所有导师都被分配，即所有学生都匹配完毕）

#### 核心位运算技巧
- `mask & (1 << j)`：判断导师 `j` 是否已被分配
- `mask | (1 << j)`：将导师 `j` 标记为已分配
- `bin(mask).count('1')`：计算已分配学生数（即当前学生下标）

---

### 代码实现（Python）

```python
from typing import List

def maxCompatibilitySum(compatibility: List[List[int]]) -> int:
    n = len(compatibility)
    # dp[mask]: 已分配导师集合为 mask 时的最大评分和
    dp = [-1] * (1 << n)
    dp[0] = 0
    
    for mask in range(1 << n):
        if dp[mask] < 0:
            continue
        # i = 已经分配的学生数 = 当前该分配第 i 位学生
        i = bin(mask).count('1')
        if i >= n:
            continue
        for j in range(n):
            # 导师 j 还未被分配
            if not (mask & (1 << j)):
                new_mask = mask | (1 << j)
                dp[new_mask] = max(dp[new_mask], dp[mask] + compatibility[i][j])
    
    return dp[(1 << n) - 1]


# 测试
if __name__ == "__main__":
    compatibility = [[3, 1], [2, 4]]
    print(maxCompatibilitySum(compatibility))  # 6
    
    compatibility2 = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
    print(maxCompatibilitySum(compatibility2))  # 15 (1+5+9 或 3+5+7 等)
```

---

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | `O(n * 2^n)` | 共 `2^n` 个状态，每个状态枚举 `n` 个导师 |
| **空间** | `O(2^n)` | 一维 DP 数组 |

对于 `n = 8`：`8 * 256 = 2048` 次运算，轻轻松松。

---

### 变体与扩展

1. **最小化总成本**：把 `max` 换成 `min`，初始化 `dp[0] = 0`，其余设为正无穷。
2. **允许不分配全部**：加一维表示已分配学生数，或者答案取所有 `dp[mask]` 的最大值。
3. **带约束的匹配**：如某学生不能匹配某导师，在转移时跳过即可。
4. **匈牙利算法**：如果 `n` 可以达到 `500`，状态压缩就不行了，需要用匈牙利算法（`O(n^3)`）解决二分图最大权匹配。面试中问到 "n 很大怎么办" 时，这是加分回答。

## 面试技巧

### 1. 状压 DP 的识别信号（三句话搞定）

面试官出一道题，你快速判断状压是否适用：

> **"n 很小（<= 15），要在一个集合上做选择/匹配/覆盖，且每个元素只能选一次。"**

常见信号词：*分配、匹配、子集、选择、排列、覆盖*，且 `n <= 15`。

### 2. 状压 DP 的万能代码框架

```python
dp = [-inf] * (1 << n)
dp[0] = 0

for mask in range(1 << n):
    i = popcount(mask)  # 当前处理到第几个元素
    for j in range(n):
        if not (mask & (1 << j)):  # j 还未被选中
            dp[mask | (1 << j)] = max(dp[mask | (1 << j)], 
                                       dp[mask] + value[i][j])

return dp[(1 << n) - 1]
```

**把这个框架背下来**，面试时 80% 的状压题都能套进去。面试官看到你能快速写出这个结构，会直接判定你"熟悉状压 DP"。

### 3. 从暴力到优化的"面试话术"

如果面试官问 "你怎么想到用状压？"，你可以这样回答：

> "我先看了数据范围，n <= 8，非常小。全排列的暴力解法是 `O(n!)`，`8! = 40320` 其实也能过，但不够优雅。注意到这本质上是一个**集合上的递推问题**，每个状态只关心'哪些导师已被分配'，不关心分配顺序，所以用 `2^n` 个状态来表示所有子集，这就是状态压缩 DP。"

这段话的亮点：
- **先提数据范围**（展示你做题先看约束的习惯）
- **提到暴力解法**（展示你思考过其他方案）
- **指出'不关心顺序，只关心集合'**（这是 DP 的核心思想：状态去重）
- **自然引出状压**（逻辑流畅，不说"我背过这道题"）

### 4. 常见坑点

| 坑 | 怎么避免 |
|----|----------|
| `popcount` 计算错 | 在 Python 中用 `bin(mask).count('1')`，或 `bit_count()`（Python 3.8+） |
| 位运算优先级 | `1 << j` 要加括号，建议写成 `(1 << j)` |
| 初始化错误 | 求最大值时 `dp` 初始化为 `-inf`，求最小值时为 `+inf` |
| 状态顺序 | 枚举 `mask` 从小到大即可，因为 `mask | (1 << j)` 总是大于 `mask` |

### 5. 如果 n 变大怎么办？

面试中常有的 follow-up："如果 n = 500，你还能用状压吗？"

标准回答：
> "n = 500 时 `2^n` 完全不可行。但注意到这个题目本质是**二分图最大权匹配**，可以用匈牙利算法（KM 算法）在 `O(n^3)` 内解决。这说明了'先识别问题本质，再选择算法'的重要性。"

**进阶加分**：如果 n 很大但评分矩阵很稀疏，还可以用最小费用最大流。

### 6. Week 4 小结：DP 优化思维清单

这一周你接触了多种 DP 优化技巧，面试中遇到 DP 题时，可以按这个顺序思考：

1. **状态压缩优化**：`n` 很小（<= 15）时，用 bitmask 表示集合状态
2. **二分/单调性优化**：如 LIS 的 `O(n log n)` 贪心 + 二分
3. **多状态维护**：如最大乘积子数组同时维护 `max` 和 `min`
4. **预计算优化**：如接雨水先计算左右最大值，避免重复计算
5. **滚动数组**：空间优化，只保留上一行/几行状态
6. **状态机 DP**：如股票问题的 `hold/sold/cooldown` 状态

> **面试金句**："DP 优化的核心，不是把代码写得更复杂，而是把'冗余的状态'和'重复的计算'砍掉。"
