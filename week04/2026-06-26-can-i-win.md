## 一、今日算法题

### 题目描述（LeetCode 464）

在 "100 game" 这个游戏中，两名玩家轮流从 `1` 到 `maxChoosableInteger` 中选择一个**未被选过**的整数，并将其累加到当前总和中。最先使累计整数和达到或超过 `desiredTotal` 的玩家获胜。

假设两位玩家都以最优策略进行游戏，判断**先手**是否能必胜。

**示例 1：**
```
输入: maxChoosableInteger = 10, desiredTotal = 11
输出: false
解释: 无论先手拿什么（1-10），后手都能拿一个数凑到 11。例如先手选 3，后手拿 8 就赢了。
```

**示例 2：**
```
输入: maxChoosableInteger = 10, desiredTotal = 0
输出: true
解释: 目标已经是 0，先手不选就赢了。
```

**约束条件：**
- `1 <= maxChoosableInteger <= 20`
- `0 <= desiredTotal <= 300`

---

### 思路分析

#### 🔑 关键观察 1：范围小到可以用状态压缩
`maxChoosableInteger <= 20`，这意味着我们可以用一个 **20 位二进制整数** 来表示「哪些数字已经被选过」。

- 第 `i` 位为 `1` → 数字 `i+1` 已被使用
- 状态总数最多 `2^20 ≈ 100万`，完全可以接受

#### 🔑 关键观察 2：博弈的递归结构
定义 `dfs(state, current_sum)` 表示：**在当前状态下，当前行动的玩家是否能赢**。

- 如果存在一个未使用的数字 `i`，使得 `current_sum + i >= desiredTotal` → 直接选它，当前玩家获胜 ✅
- 否则，枚举每个可用数字 `i`：
  - 如果选 `i` 之后，**对手必败** → 当前玩家必胜 ✅
- 所有选择都试过了，没有必胜策略 → 当前玩家必败 ❌

这是博弈论中经典的 **「必胜态 / 必败态」** 分析。

#### 🔑 关键观察 3：只需要记录 state，current_sum 可以推导
实际上，`current_sum` 可以由 `state` 推导出来（已选数字之和），但为了代码清晰，也可以一起记忆化。更优的做法是只记 `state`，因为和是确定的。

---

### 代码实现（Python）

```python
from functools import lru_cache

class Solution:
    def canIWin(self, maxChoosableInteger: int, desiredTotal: int) -> bool:
        # 剪枝 1：如果所有数字之和小于 desiredTotal，永远无法达到目标
        total_sum = (1 + maxChoosableInteger) * maxChoosableInteger // 2
        if total_sum < desiredTotal:
            return False
        
        # 剪枝 2：如果 desiredTotal 为 0，先手直接赢
        if desiredTotal == 0:
            return True

        @lru_cache(maxsize=None)
        def dfs(state: int) -> bool:
            # 计算当前已选数字的和
            current_sum = 0
            for i in range(maxChoosableInteger):
                if state >> i & 1:
                    current_sum += i + 1
            
            for i in range(1, maxChoosableInteger + 1):
                # 检查数字 i 是否已被使用
                if state >> (i - 1) & 1:
                    continue
                
                # 选 i 就能直接获胜
                if current_sum + i >= desiredTotal:
                    return True
                
                # 选 i 后，轮到对手。如果对手必败，则当前玩家必胜
                next_state = state | (1 << (i - 1))
                if not dfs(next_state):
                    return True
            
            # 所有选择都试过了，没有必胜策略
            return False
        
        return dfs(0)
```

#### 更简洁的版本（预计算和，避免每次求和）

```python
from functools import lru_cache

class Solution:
    def canIWin(self, maxChoosableInteger: int, desiredTotal: int) -> bool:
        if (1 + maxChoosableInteger) * maxChoosableInteger // 2 < desiredTotal:
            return False
        
        # 预计算每个状态对应的已选数字之和
        # 也可以不预计算，直接在递归中传参
        
        @lru_cache(maxsize=None)
        def dfs(state: int, current_sum: int) -> bool:
            for i in range(1, maxChoosableInteger + 1):
                if state >> (i - 1) & 1:  # 已使用
                    continue
                
                # 直接获胜
                if current_sum + i >= desiredTotal:
                    return True
                
                # 让对手陷入必败态
                next_state = state | (1 << (i - 1))
                if not dfs(next_state, current_sum + i):
                    return True
            
            return False
        
        return dfs(0, 0)
```

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(2^M × M) | M = maxChoosableInteger，每个状态枚举 M 个选择 |
| **空间** | O(2^M) | 记忆化数组，最多 2^20 ≈ 100万 个状态 |

> 💡 2^20 = 1,048,576，乘以 20 约 2000 万次操作，Python 可以轻松通过。

## 二、面试技巧

### 🎯 1. 如何向面试官引出「状态压缩」

**不要上来就扔术语**，先分析问题：

> *"我注意到可选数字的范围很小（最多 20 个），这让我想到可以用一个二进制数来表示'哪些数字已经被选过'——这就是所谓的状态压缩。"*

**关键话术：**
- **"位运算代替集合"**："如果用数组或 HashSet 记录已用数字，每次操作是 O(M)。但用整数的位运算，判断和更新都是 O(1)，状态本身也只是一个 int，非常适合当记忆化的 key。"
- **"状态数估算"**："20 个数字，总状态数是 2^20，大约 100 万，在时间和空间上都是可行的。"

---

### 🎯 2. 博弈类问题的「万能模板」

几乎所有**两人轮流、最优策略、完全信息**的问题都可以套这个框架：

```
当前玩家必胜 = 存在某个合法行动，使得（行动后直接获胜）或（行动后对手必败）
```

用代码说就是：
```python
for move in all_possible_moves:
    if win_immediately(move):
        return True  # 当前玩家胜
    if not dfs(next_state):  # 对手败
        return True  # 当前玩家胜
return False  # 所有路都走不通，当前玩家败
```

**面试中这样表达：**
> *"这类博弈问题的核心思路是'或'逻辑——当前玩家只要能找到一个让对手无路可走的选择，自己就稳了。不需要评估所有分支的得分，只关心'能不能赢'。"*

---

### 🎯 3. 主动提出剪枝，展示工程意识

这道题有两个明显的剪枝点，面试中主动提到会加分：

| 剪枝 | 条件 | 复杂度 |
|------|------|--------|
| **总和不足** | 1+2+...+M < desiredTotal | O(1) |
| **目标为 0** | desiredTotal == 0 | O(1) |

**话术示例：**
> *"我先做一个快速判断：如果 1 到 M 的所有数字加起来都小于目标值，那无论如何都不可能达到，直接返回 false。还有 desiredTotal 为 0 的边界情况，也先做掉。"*

### 🎯 4. 常见 Follow-up 及应对

**Q1：如果 maxChoosableInteger 达到 30 怎么办？**  
→ 2^30 状态太多，需要换思路。可以问面试官确认约束，或提出**启发式搜索 / Alpha-Beta 剪枝**。

**Q2：如何输出具体的必胜策略（每一步选什么）？**  
→ 在 DFS 中记录「导致胜利的选择」，回溯时重建路径。

```python
# 伪代码：记录策略
choice = {}  # state -> 当前应该选什么

def dfs(state):
    for i in available:
        if win_or_make_opponent_lose(i):
            choice[state] = i  # 记录这个状态下的最优选择
            return True
```

**Q3：两人都不以最优策略玩呢？**  
→ 引入概率模型，变成**期望 DP** 或**蒙特卡洛模拟**。

### 🎯 5. 状压 DP 的面试「避坑指南」

| ❌ 不要这样 | ✅ 要这样 |
|-----------|----------|
| "我用一个数组记录选了哪些数" | "我用一个 int 的每一位表示选/没选" |
| "状态就是当前的和" | "状态是选了哪些数，和可以推导或作为辅助参数" |
| 不提复杂度 | 主动说 "2^20 约 100 万状态，可以接受" |
