## 一、今日算法题：LFU 缓存（LFU Cache, LC 460）

### 题目

设计一个 LFU（最不经常使用）缓存数据结构，支持 `get` 和 `put`，两者都要求 **O(1)** 时间复杂度。当缓存满时，**淘汰使用频率最低的 key**；如果多个 key 频率相同，淘汰**最久未使用**的那个（LRU tie-break）。

```
示例:
LFUCache cache = new LFUCache(2);
cache.put(1, 1);
cache.put(2, 2);
cache.get(1);      // 返回 1，key=1 频率升到 2
cache.put(3, 3);   // 淘汰 key=2（频率 1 最低）
cache.get(2);      // 返回 -1（已被淘汰）
cache.get(3);      // 返回 3，key=3 频率升到 2
cache.put(4, 4);   // 淘汰 key=1（频率都是 2，但 1 更久未用）
cache.get(1);      // 返回 -1
cache.get(3);      // 返回 3
cache.get(4);      // 返回 4
```

**约束**：`0 <= capacity <= 10^4`，调用次数最多 `10^5` 次。

### 为什么今天选这道题（主题同构）

Day 125 说"tool orchestration = 状态图最短路"，今天这道题是 agent 记忆系统的**硬件级同构**——缓存就是记忆：

| 缓存概念 | 记忆系统对应 |
|---|---|
| `capacity` 容量 | 工作记忆上限（context window） |
| `freq` 访问计数器 | **记忆强度**——每次 `get` 都是一次"提取练习"，心理学上提取练习正是强化记忆的手段 |
| `minFreq` 淘汰 | **遗忘曲线**：最弱的记忆最先被遗忘 |
| LRU tie-break | 同样强度的记忆，最久没想起的先忘 |
| TTL（扩展） | 记忆时效衰减——"上次用户地址"放久了就该过期 |

**你写过的每一个缓存设计题，都是记忆系统的预科。** LFU 的 freq 计数器 = 记忆重要性评分，eviction = 遗忘执行器。面试讲这道题时主动把映射点出来，是把算法题讲成系统设计题的免费升维。

### 思路：三件套结构（O(1) 的命门是 minFreq 指针）

```
cache:    key → [value, freq]                    # 定位 O(1)
freq_map: freq → 双向链表（同频率的 key，头新尾旧）   # 同频率内维持 LRU 序
min_freq: 当前最小频率                             # 淘汰时 O(1) 找到牺牲者
```

三个不变量：
1. 每个 key 恰好出现在一个频率链表中
2. 每条频率链表内部是 LRU 序（尾端 = 最久未用 = 淘汰候选）
3. `min_freq` 始终指向非空的最小频率链表

```python
from collections import OrderedDict, defaultdict

class LFUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.min_freq = 0
        self.cache = {}                              # key -> (value, freq)
        self.freq_map = defaultdict(OrderedDict)     # freq -> OrderedDict[key -> None]

    def _touch(self, key: int, value: int, freq: int) -> None:
        """访问即强化记忆：摘除旧频率，挂到 freq+1 链表头。"""
        del self.freq_map[freq][key]
        if not self.freq_map[freq]:                  # 旧频率链表空了
            del self.freq_map[freq]
            if freq == self.min_freq:                # 抽空的是最小频率 → 上移
                self.min_freq += 1
        self.freq_map[freq + 1][key] = None          # 新频率链表头（最新）
        self.cache[key] = (value, freq + 1)

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        value, freq = self.cache[key]
        self._touch(key, value, freq)
        return value

    def put(self, key: int, value: int) -> None:
        if self.capacity == 0:
            return
        if key in self.cache:                        # 已存在：改值 + 强化
            _, freq = self.cache[key]
            self._touch(key, value, freq)
            return
        if len(self.cache) >= self.capacity:         # 满了：执行遗忘
            evict_key, _ = self.freq_map[self.min_freq].popitem(last=False)  # 尾端=最旧
            del self.cache[evict_key]
        self.min_freq = 1                            # 新 key 频率为 1
        self.cache[key] = (value, 1)
        self.freq_map[1][key] = None
```

**面试手撕版**：若面试官要求"不许用语言自带结构"，把 `OrderedDict` 换成手写双向链表（节点存 key/value/freq + prev/next），`freq_map[freq]` 存 `(head, tail)` 两个哨兵节点，`touch` 和 `evict` 都是标准 DLL 摘除/头插操作——结构和 LRU 完全一致，只是多了一层频率索引。**LRU + 频率分桶 = LFU**，记住这个叠加关系，手撕时先写 LRU 再套桶就不会慌。

**易错点（面试必考）**：
- **`put` 已存在的 key 不算插入**，不触发淘汰、频率照常 +1（很多人在这里多淘汰一个）
- **新 key 插入前 `min_freq = 1`**：淘汰发生在插入前，此时 `min_freq` 还是旧值，淘汰完必须重置为 1
- `get` miss **不能动 `min_freq`**（没有访问就没有频率变化）
- `capacity = 0` 的边界
- **复杂度**：get/put 均 O(1)（每个操作只碰常数个哈希桶和链表节点），空间 O(capacity)

### 连环问：从 LFU 到记忆系统工程

**Q1: LRU 和 LFU 怎么取舍？各自什么时候翻车？**
- **LRU 怕缓存污染（cache pollution）**：一次性的批量扫描（如备份任务读了 10 万个冷数据）会立刻挤掉所有热点——它只认"最近"，分不清"常用"和"刚看过一次"
- **LFU 怕新数据冷启动**：新 key 频率为 1，热点数据频率上千，新数据几乎必死——**老化机制（aging）**：周期性把所有 freq 减半（`freq >>= 1`），久不访问的会自然沉底，新数据能快速爬升——这就是"记忆消退"的工程实现
- 工业界混合策略：**LRU-K**（看最近 K 次访问，抗扫描）、**ARC**（自适应双队列，SCAN-resistant）、**W-TinyLFU**（Caffeine 的准入窗口 + 频率 sketch，"先考察再转正"=记忆的试用期机制）

**Q2: 加 TTL 怎么设计？**
- 节点加过期时间，惰性删除（访问时发现过期就当 miss + 顺带清理）+ 后台定期抽样清理（Redis 的 lazy + 定期同款）
- `min_freq` 链表被清空时惰性重算
- 过期优先于频率淘汰——**时效性高于重要性**（"用户旧地址"使用频率再高也该过期）

**Q3: 频率计数器溢出 / 内存膨胀？**
- freq 用 int64 不可能溢出；如果每条 key 都存 freq 太贵，退化方案：概率计数器（Count-Min Sketch 式近似）、或只分桶（热/温/冷三档，TF-IDF 式对数分桶——很多记忆系统的"重要性评分"就是三档）

**Q4: 如何输出当前最热 Top-K？**
- 频率链表按 freq 降序扫，每条内按 LRU 序——O(K)。追问实时性：改为分层时间轮或跳表索引。

**Q5: 分布式版本（多实例共享一个 LFU）？**
- 严格 O(1) 全局一致性不现实 → 近似方案：本地 LFU + 周期性同步计数器（Gossip 式，呼应 Day 104），或一致性哈希分片让同一 key 固定落到同一节点。

## 二、面试技巧：记忆系统三层设计与失效降级

### 1. 三层记忆模型（人类认知科学 → Agent 工程的标准映射）

面试被问"怎么给 agent 设计记忆"，先甩这张表（认知科学背书 + 工程落地，一秒建立框架感）：

| 人类记忆 | Agent 对应 | 存储介质 | 读延迟 | 容量 | 持久性 | 写入方式 |
|---|---|---|---|---|---|---|
| **工作记忆** | context window / system prompt | KV cache（推理时） | 已在场=零检索 | 100K~1M tokens | 会话级 | 每轮自然写入 |
| **情景记忆** | 对话历史库 / 向量库 | 向量 DB + 文件系统 | 检索 10~100ms | GB 级 | 长期 | 事件触发 + 批量巩固 |
| **语义记忆** | 模型参数 | 权重文件 | 推理时天然携带 | 固定 | 最持久 | 训练 / fine-tune |
| （程序性记忆） | skill 文件 / CLAUDE.md / 工具模式 | 磁盘文件 | 启动加载 | 小 | 长期 | 人工/自动固化 |

三个关键论断：
1. **工作记忆是唯一"模型能直接思考"的地方**——context window 是显存（Day 124），外部记忆必须换入才能被使用
2. **情景记忆是性价比之王**：读写都便宜、容量大、可热更新——生产系统 90% 的"记忆工程"发生在这一层
3. **语义记忆写入最贵**（训练）但回答"你最擅长什么"这一层说了算—— continual learning 是开放难题，面试别提"把对话 fine-tune 进去"这种方案，除非谈 LoRA 适配层的轻量做法

### 2. 四个设计决策（面试官想听的不是名词，是取舍）

**① 写入路径（what to remember）**——不是所有对话都配进长期记忆：
- **重要性评分**：LLM 对每条候选记忆打 1-10 分（Mem0/Letta 的做法），只存 ≥ 阈值的
- **纠错记忆价值最高**：用户纠正、工具失败、意外分支——失败是信息密度最高的时刻（veRL 失败轨迹同理，Day 123 Reflexion 燃料）
- **写入即合并**：新事实与旧记忆冲突时**更新而非追加**（"用户搬家了"要覆盖旧地址，不是存两条让模型自己猜）——很多 demo 级记忆系统死在这条上

**② 读取路径（when to recall）**——检索比存储难：
- 每轮全量检索（贵、噪声大）vs 触发式检索（检测到任务相关才查）——生产用触发式 + 兜底
- 注入位置服从 Lost in the Middle（Day 124）：关键记忆放 prompt 前部或后部，别埋中段
- **相关性阈值是生命线**：无关记忆比没有记忆更糟——"负记忆"会带偏模型（上下文污染的变体）

**③ 巩固（consolidation）**——人类睡眠时海马体向皮层转移记忆，agent 的对应物是**离线批处理**：
- 会话结束后/低峰期，把当日对话批量摘要 → 压缩 → 去重合并 → 写入长期存储
- 这是 Day 124「摘要压缩」的长期记忆版：有损但不可逆地省空间，consolidation 的质量决定了记忆系统天花板

**④ 遗忘（forgetting）**——不是 bug，是预算约束下的特性：
- 容量驱逐（LFU 式）、TTL 时效衰减、重要性衰减（定期降权=aging）三件套
- **忘不了是噩梦**：隐私合规要求"被遗忘权"，记忆只进不出 = 法律风险 + 噪声累积

### 3. MemGPT/Letta：虚拟上下文分页（追问"长记忆怎么做"的黄金答案）

如果面试官追问"具体怎么实现大容量记忆"，讲 MemGPT（2023.10，后更名 Letta）的 OS 类比——这是把记忆系统讲出系统设计高度的标准答案：

- **核心洞察**：LLM 的 context window 固定且昂贵，就像物理内存条 → 用 OS 虚拟内存的思路管理它
- **LLM = CPU**：只能直接"访问"context 里的内容；外部存储 = 磁盘，想要必须换入
- **函数调用 = 缺页中断**：agent 需要某条记忆时主动调用 `archival_memory_search` / `core_memory_append`——agent 自己管理自己的分页，这是"LLM 作为 OS 系统调用发起方"的范式
- 四区架构：**core memory**（小而关键的 K/V 块：用户画像、当前任务状态，永驻 context，LLM 可主动改写）/ **recall context**（滚动对话窗口）/ **archival memory**（向量库，按需检索）/ **memory blocks**（带 schema 的结构化槽位）
- 面试讲法："把 paging 三要素讲全——换入时机（检索触发）、换出策略（LRU/重要性驱逐）、地址翻译（embedding 语义索引），OS 课全对上"

### 4. 失效降级设计（degradation ladder）

记忆系统的面试加分项不是讲功能，是讲**挂了怎么办**。标准答案是一条降级阶梯，每层都可独立失效：

```
L0 全功能：向量检索 + 关键词 + 工作记忆
L1 向量库挂 → 降级 BM25/关键词检索
L2 检索层全挂 → 纯工作记忆运行（无历史）
L3 连上下文都超限 → 滚动摘要 + 明确告知用户
```

**六种失效模式速查表**（面试官问"你的记忆系统怎么容错"直接背）：

| 失效模式 | 现象 | 降级/缓解 |
|---|---|---|
| 存储挂掉 | 向量库连接失败 | L1→L2 降级 + 内存队列缓冲写入，恢复后重放 |
| 检索空召回 | 有相关记忆但没查到 | prompt 显式标注"无相关历史"——**防止模型幻觉编造历史**（无记忆运行必须可感知） |
| 陈旧记忆 | 记忆与现实矛盾 | TTL + 版本号 + 冲突时新盖旧 + 定期 re-rank 清理 |
| **记忆中毒** | 恶意内容写入长期记忆，每次检索都回灌 | 写入端校验（来源分级、注入模式检测、敏感内容确认门）+ 检索端标注来源——**长期记忆是注入攻击的持久化载体**（Day 125 tool poisoning 的记忆版） |
| 记忆膨胀 | 记忆库噪声累积、检索质量下降 | 重要性衰减（aging）+ 摘要压缩 + LFU 驱逐——**就是今天那道题** |
| 上下文污染 | 无关记忆带偏模型 | 相关性阈值 + Cross-Encoder rerank + 注入数量上限 |

### 5. 连环问速答

**Q1: 为什么不能把一切塞进长上下文，要记忆系统干嘛？**
三笔账：成本账（每轮全价重读，长上下文是"能装"不是"该装"）、信噪账（Lost in the Middle + context rot，Day 124）、延迟账（prefill O(L²)，TTFT 爆炸）。记忆系统 = 用检索把"存"和"用"解耦。

**Q2: 记忆和 RAG 什么关系？**
RAG 是记忆的**读取路径实现之一**，不是记忆系统本身。记忆系统 = 存储层（写什么/存哪）+ 写入策略（何时写/怎么合并）+ 读取路径（何时检索/注入哪）+ 遗忘策略。知识库（静态、只增）和记忆库（动态、要更新要遗忘）可共用检索基础设施，**写入侧逻辑完全不同**——这是面试里区分"用过 RAG"和"设计过记忆系统"的分水岭。

**Q3: 记忆通过 tool 暴露还是框架自动管理？**
两派：MemGPT 式——记忆操作做成 tool 让模型自己调（灵活，但消耗 tool 名额和 token，且模型可能忘了调）；框架式——自动注入/自动固化（透明省心，但模型无感知）。趋势是混合：读开放（模型主动检索），写受控（框架拦截 + 评分过滤）——**读放开、写把关**。

**Q4: 多智能体共享记忆怎么设计？（Week 16 回声）**
私有记忆 + 共享黑板（blackboard）：黑板写入要单 writer 或 LWW 仲裁（Week 16 一致性轻量版）；agent 间只传结论不传流水（Day 124 sub-agent 外部化在多智能体版）；记忆分区防上下文互相污染。

**Q5: 怎么评估记忆系统好不好？**
离线：召回准确率@k（相关记忆是否进前 k）、噪声率（注入了多少无关）；在线：端到端任务 ablation（有记忆 vs 无记忆）、记忆命中率（检索结果被实际引用的比例）、用户纠正率（"你记错了"频率——这是最真实的长指标）。

**Q6: 记忆隐私与合规？**
遗忘权三层执行：向量库删条目 → 摘要/派生记忆清除（防"摘要里还留着"）→ 权重 unlearning（开放难题，实务用过滤 + LoRA 适配层重训）；用户级记忆分区隔离 + 最小化写入（只存必要 facts，不囤原始对话）。

### 6. 今日金句

> **「好的记忆系统不是没有遗忘，而是忘得对。LFU 的 freq 计数器记的是记忆强度，minFreq 淘汰执行的是遗忘曲线——记不住是残疾，忘不了是噩梦，记忆工程就是在两者之间调参。」**
