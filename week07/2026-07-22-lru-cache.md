## 今日算法题

### 题目描述

设计一个「最近最少使用（LRU）缓存」数据结构，支持以下操作：

- `get(key)` — 如果 key 存在，返回对应的 value；否则返回 -1
- `put(key, value)` — 插入或更新 key-value。如果容量已满，淘汰最久未使用的 key

**要求**：`get` 和 `put` 操作的时间复杂度均为 **O(1)**。

> 原题链接：[LeetCode 146. LRU Cache](https://leetcode.com/problems/lru-cache/)

---

### 思路解析

这道题是经典的**系统设计型算法题**。面试官真正想考察的不是你会不会写链表，而是：

1. **为什么 O(1) 必须组合两种数据结构？**
2. **哈希表和链表各自负责什么？**
3. **边界情况怎么处理（容量为0、重复put、访问顺序更新）？**

**核心洞察**：
- 哈希表 → 负责 **O(1) 查找**：key → 链表节点指针
- 双向链表 → 负责 **O(1) 移动/删除**：把节点移到头部、删除尾部都不需要遍历

**链表设计要点**：
- 使用**伪头部（dummy head）和伪尾部（dummy tail）**，避免处理空链表的边界情况
- 每次访问（get/put）都把节点移到链表头部 → 头部是最近使用的
- 容量满时淘汰链表尾部 → 最久未使用的

**为什么是双向链表？**  
因为需要把中间某个节点快速移到头部，双向链表才能 O(1) 找到前驱节点。

### 代码实现

```python
class DLinkedNode:
    """双向链表节点"""
    def __init__(self, key=0, value=0):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}  # key -> DLinkedNode
        self.size = 0
        
        # 伪头部和伪尾部，避免空链表判断
        self.head = DLinkedNode()
        self.tail = DLinkedNode()
        self.head.next = self.tail
        self.tail.prev = self.head

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        
        node = self.cache[key]
        self._move_to_head(node)  # 访问过 → 移到头部
        return node.value

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            # 更新已有节点
            node = self.cache[key]
            node.value = value
            self._move_to_head(node)
        else:
            # 插入新节点
            node = DLinkedNode(key, value)
            self.cache[key] = node
            self._add_to_head(node)
            self.size += 1
            
            if self.size > self.capacity:
                # 淘汰尾部最久未使用
                removed = self._remove_tail()
                del self.cache[removed.key]
                self.size -= 1

    # ----- 双向链表辅助方法 -----
    def _add_to_head(self, node):
        """在链表头部插入节点（伪头之后）"""
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node

    def _remove_node(self, node):
        """删除链表中指定节点"""
        node.prev.next = node.next
        node.next.prev = node.prev

    def _move_to_head(self, node):
        """把节点移到头部 = 先删除再插入"""
        self._remove_node(node)
        self._add_to_head(node)

    def _remove_tail(self):
        """删除并返回链表尾部节点（伪尾之前）"""
        node = self.tail.prev
        self._remove_node(node)
        return node
```

### 复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| `get` | O(1) | O(capacity) |
| `put` | O(1) | O(capacity) |

- 哈希表查找 O(1)，双向链表移动 O(1)
- 额外空间用于存储最多 `capacity` 个节点

### 常见变种与追问

**Q1：如果用 Python，可以用 `OrderedDict` 偷懒吗？**  
可以，面试中先写 OrderedDict 版本展示对语言特性的熟悉，但手撕链表更能体现功底：
```python
from collections import OrderedDict

class LRUCache(OrderedDict):
    def __init__(self, capacity):
        self.capacity = capacity
    
    def get(self, key):
        if key not in self:
            return -1
        self.move_to_end(key)  # 标记为最近使用
        return self[key]
    
    def put(self, key, value):
        if key in self:
            self.move_to_end(key)
        self[key] = value
        if len(self) > self.capacity:
            self.popitem(last=False)  # 淘汰最旧的
```

**Q2：如果要线程安全怎么办？**  
加锁（如 Python 的 `threading.Lock`），或者使用 `collections.OrderedDict` 配合 `RLock`。

**Q3：如果是 LFU（最少使用频率）缓存呢？**  
需要维护访问频率 → 用「频率 → 双向链表」的哈希表，再加一个节点到频率的映射。LeetCode 460 题。

**Q4：缓存容量很大，怎么优化内存？**  
- 考虑 Weak Reference（允许 GC 回收）
- 或者引入 TTL（过期时间），配合定时清理

## 面试技巧

### 设计题通用话术框架

遇到「设计一个数据结构」类题目，不要急着写代码，按这个顺序展开：

**1. 需求澄清（30秒）**
> "我先确认一下，这个缓存需要支持并发吗？key 和 value 的类型有范围限制吗？"

**2. 方案概述（1分钟）**
> "我的思路是用哈希表 + 双向链表。哈希表保证 O(1) 查找，双向链表维护使用顺序，每次访问把节点提到头部，淘汰时删尾部。两个操作都是 O(1)。"

**3. 细节确认（边说边写）**
> "我用伪头尾节点来简化边界处理，这样链表永远非空，不用判空。"

**4. 复杂度主动分析**
> "时间和空间都是 O(capacity)，因为最多存这么多节点。"

### 面试官爱挖的坑

| 坑 | 怎么躲 |
|----|--------|
| 单向链表行不行？ | 不行，删除中间节点需要前驱指针 |
| 容量为0怎么办？ | 初始化时判断，直接不存任何数据 |
| 重复 put 同一个 key | 更新 value 并移到头部，不增加 size |
| 为什么不用数组/队列？ | 数组删除中间元素 O(n)，队列无法随机访问 |

### 手写链表的小技巧

- **先画再写**：在纸上画出 head ↔ node ↔ tail 的关系，确认四个指针操作顺序
- **四行公式**：插入节点到某位置后，永远先改 `node.prev/next`，再改两边的指针，避免断链
- **边界兜底**：dummy head/tail 是面试中的加分细节，体现工程思维
