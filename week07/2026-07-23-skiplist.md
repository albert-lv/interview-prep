## 🎯 今日算法题

### 题目：设计跳表（LeetCode 1206）

**描述：**

不使用任何库函数，设计一个 **跳表（Skiplist）**。跳表是在 O(log n) 时间内完成增加、删除、搜索操作的数据结构。

相比树堆或红黑树，跳表的 **优势** 在于：
- 实现简单，代码量少
- 并发场景下锁粒度更细（Redis 用它替代平衡树）
- 区间查询友好

你需要实现 `Skiplist` 类：

- `Skiplist()` 初始化跳表对象。
- `bool search(int target)` 返回 `target` 是否在跳表中。
- `void add(int num)` 插入 `num` 到跳表中。
- `bool erase(int num)` 从跳表中删除 `num`。如果 `num` 不在跳表中，返回 `false`；否则返回 `true`。如果有多个 `num`，删除其中一个即可。

**约束：**
- `0 <= num, target <= 2 × 10⁴`
- 调用 `search`、`add`、`erase` 的次数不超过 `5 × 10⁴`

---

### 💡 核心思路

跳表的核心思想是 **"多层有序链表"**，用空间换时间：

```
Level 3:  head ──────────────► 30 ──────────────────► tail
Level 2:  head ──────► 15 ──► 30 ──────► 45 ────────► tail
Level 1:  head ──► 5 ──► 15 ──► 30 ──► 45 ──► 60 ──► tail
Level 0:  head ──► 5 ──► 10 ──► 15 ──► 20 ──► 30 ──► 40 ──► 45 ──► 50 ──► 60 ──► tail
```

**三个关键操作，共用同一套 "找前驱节点" 逻辑：**

#### 1️⃣ 搜索 `target`
从最高层开始，向右走到 **≤ target 的最后一个节点**，如果值等于 target 就返回 true；否则下到下一层继续。到最底层还没找到就返回 false。

#### 2️⃣ 插入 `num`
先 **从最高层往下走**，每层记录 "该层中小于 num 的最后一个节点"（叫 `update[]` 数组）。

然后在 **最底层插入新节点**。接着抛硬币决定是否向上层提升——每次有 50% 概率升高一层，期望层数是 O(1)，所以插入均摊 O(log n)。

#### 3️⃣ 删除 `num`
同样先找每层的前驱。如果底层存在目标节点，就把它从各层链表中摘掉。注意：**某一层可能没有该节点**（因为抛硬币没抛到那么高），所以要判断 `update[i].next[i] == targetNode` 再删。

### 📝 参考代码（Go）

```go
package main

import (
	"math/rand"
)

type Node struct {
	val  int
	next []*Node // next[i] = 第 i 层的下一个节点
}

type Skiplist struct {
	maxLevel int
	head     *Node
	// 不用存 tail，用 nil 表示尾
}

func Constructor() Skiplist {
	const maxLevel = 16
	head := &Node{val: -1, next: make([]*Node, maxLevel)}
	return Skiplist{maxLevel: maxLevel, head: head}
}

// 返回 target 所在的节点（nil 表示不存在）
// 同时填充 update[]：每一层中，小于 target 的最后一个节点
func (this *Skiplist) _find(target int, update []*Node) *Node {
	cur := this.head
	for i := this.maxLevel - 1; i >= 0; i-- {
		// 向右走到该层最后一个 < target 的节点
		for cur.next[i] != nil && cur.next[i].val < target {
			cur = cur.next[i]
		}
		if update != nil {
			update[i] = cur
		}
	}
	// 现在 cur 是最底层中 < target 的最后一个节点
	// cur.next[0] 就是第一个 >= target 的节点
	if cur.next[0] != nil && cur.next[0].val == target {
		return cur.next[0]
	}
	return nil
}

func (this *Skiplist) Search(target int) bool {
	return this._find(target, nil) != nil
}

func (this *Skiplist) Add(num int) {
	update := make([]*Node, this.maxLevel)
	this._find(num, update) // 找到每一层的前驱

	level := 1
	for rand.Int()%2 == 1 && level < this.maxLevel {
		level++
	}

	newNode := &Node{val: num, next: make([]*Node, level)}
	for i := 0; i < level; i++ {
		newNode.next[i] = update[i].next[i]
		update[i].next[i] = newNode
	}
}

func (this *Skiplist) Erase(num int) bool {
	update := make([]*Node, this.maxLevel)
	target := this._find(num, update)
	if target == nil {
		return false
	}

	for i := 0; i < len(target.next); i++ {
		// 安全检查：这一层 target 是否真的被链上了
		if update[i].next[i] == target {
			update[i].next[i] = target.next[i]
		}
	}
	return true
}
```

### ⏱️ 复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| `Search` | **O(log n)** 期望 | O(1) |
| `Add` | **O(log n)** 期望 | O(log n) 期望（新节点的层数） |
| `Erase` | **O(log n)** 期望 | O(1) |

**为什么期望是 O(log n)？**
- 每个节点期望层数 = 1 + 1/2 + 1/4 + ... = **2**
- 跳表层数期望 = O(log n)（类似抛硬币连续正面的次数）
- 所以搜索路径长度期望 = O(log n)

### 🔗 举一反三

| 延伸题目 | 关联点 |
|---------|--------|
| **Redis 为什么用跳表而不是红黑树？** | 跳表实现简单 + 区间查询友好 + 并发锁粒度细 |
| **跳表 vs B+ 树** | B+ 树更适合磁盘（页对齐），跳表更适合内存 |
| **如何支持 rank 查询？** | 每个节点加 `span`（到下一个节点的跨度），类似 Redis 的 zset |
| **如何做到 O(1) 索引访问？** | 不能，跳表不支持随机访问，这是和数组的本质区别 |

## 🎤 面试技巧

### 1. 遇到 "设计一个数据结构" 类题目，怎么开口？

**推荐话术模板：**

> "我先确认一下约束：数据规模多大？操作频次多少？是否需要支持并发？这些会决定我是用平衡树、跳表还是哈希表。"

然后按这个结构展开：
1. **分析需求** — 读/写比例？是否需要范围查询？是否需要排序？
2. **对比选型** — 哈希表 O(1) 单点查询但不支持范围；平衡树 O(log n) 全支持但实现复杂；跳表折中
3. **核心原理** — 讲清楚 "多层链表 + 抛硬币升层" 的思想
4. **边界处理** — 删除时某层可能没有该节点；层数上限控制

---

### 2. 面试官追问："Redis 为什么选跳表实现 ZSET？"

**标准答案：**
1. **实现简单** — 几百行代码 vs 红黑树几千行，降低 bug 概率
2. **范围查询友好** — `ZRANGEBYSCORE` 是跳表的自然优势，O(log n) 定位起点后顺序遍历
3. **并发优化空间大** — 跳表可以按层级/区间加锁，红黑树的旋转涉及大量节点重排
4. **内存局部性** — 跳表节点按需分配，红黑树需要额外颜色标记字段

---

### 3. 白板coding易错点

| 坑 | 怎么避免 |
|---|---------|
| 删除时越界访问 `target.next[i]` | 用 `len(target.next)` 作为循环上限，不是 `maxLevel` |
| 忘记处理 "某层没有该节点" | 删之前检查 `update[i].next[i] == target` |
| 抛硬币死循环 | 加 `level < maxLevel` 上限 |
| 搜索时 `<=` vs `<` 搞混 | 统一用 `< target` 向右走，最后用 `==` 判断 |

---

### 4. 一个加分细节

如果面试有时间，可以提一句 **"索引节点可以只存指针不存数据"**（类似 Redis 的做法），这样高层节点很小，缓存友好。面试官会觉得你不仅做过这道题，还真的理解跳表的工程优化。
