## 🧩 今日算法题

### [236. 二叉树的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/)

> 给定一个二叉树，找到该树中两个指定节点的最近公共祖先（LCA）。
> 
> 最近公共祖先的定义为：对于有根树 T 的两个节点 p、q，最近公共祖先表示为一个节点 x，满足 x 是 p、q 的祖先且 x 的深度尽可能大（一个节点也可以是它自己的祖先）。

**示例：**
```
输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
输出：3
解释：节点 5 和节点 1 的最近公共祖先是节点 3。
```

---

### 💡 核心思路：递归分治 + 后序遍历

LCA 问题的核心观察：

**对于任意节点 `root`，p 和 q 的 LCA 只可能出现三种情况：**

1. **p 和 q 分别在 root 的左右子树中** → `root` 就是 LCA
2. **p 和 q 都在左子树中** → LCA 在左子树里
3. **p 和 q 都在右子树中** → LCA 在右子树里

所以用后序遍历（左右根），先看左右子树能不能找到 p 或 q：
- 左子树找到一个，右子树也找到一个 → 当前 root 就是 LCA
- 只有一边找到 → 那边继续往上返回
- 都没找到 → 返回 null

**递归终止条件：**
- 遇到 null → 返回 null
- 遇到 p 或 q → 返回当前节点（表示"在这里找到了"）

---

### 📝 代码实现

```python
class TreeNode:
    def __init__(self, x):
        self.val = x
        self.left = None
        self.right = None

class Solution:
    def lowestCommonAncestor(self, root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
        # 终止条件：空节点，或者找到了 p/q
        if not root or root == p or root == q:
            return root
        
        # 后序遍历：先去左右子树找
        left = self.lowestCommonAncestor(root.left, p, q)
        right = self.lowestCommonAncestor(root.right, p, q)
        
        # 左右子树各找到一个 → 当前 root 就是 LCA
        if left and right:
            return root
        
        # 只有一边找到 → 返回那一边的结果
        return left if left else right
```

---

### ⏱️ 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(N) | 每个节点最多访问一次 |
| **空间** | O(H) | 递归栈深度，H 为树高，最坏 O(N)（退化为链表），平衡树 O(log N) |

### 🔥 进阶：倍增法求 LCA（适用于多次查询）

如果树的结构不变，但要回答很多 LCA 查询，每次递归遍历整棵树太亏了。

**倍增法（Binary Lifting）预处理：**
1. 先 DFS 一遍，记录每个节点的深度 `depth[u]`
2. 预处理 `up[k][u]`：节点 u 的第 2^k 个祖先
   - `up[0][u] = parent[u]`
   - `up[k][u] = up[k-1][ up[k-1][u] ]`
3. 查询时：
   - 先把深的节点往上跳到同一深度
   - 然后两人一起往上倍增跳，找最浅的公共祖先

```python
# 预处理（O(N log N)）
LOG = 20
up = [[0] * (n+1) for _ in range(LOG)]
depth = [0] * (n+1)

def dfs(u, p):
    up[0][u] = p
    for k in range(1, LOG):
        up[k][u] = up[k-1][ up[k-1][u] ]
    for v in adj[u]:
        if v != p:
            depth[v] = depth[u] + 1
            dfs(v, u)

# 查询（O(log N)）
def lca(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    # u 往上跳到和 v 同一深度
    diff = depth[u] - depth[v]
    for k in range(LOG-1, -1, -1):
        if diff >> k & 1:
            u = up[k][u]
    if u == v:
        return u
    # 一起往上跳
    for k in range(LOG-1, -1, -1):
        if up[k][u] != up[k][v]:
            u = up[k][u]
            v = up[k][v]
    return up[0][u]  # 返回父节点
```

**适用场景：** 静态树 + 大量 LCA 查询（比如树上路径问题、树链剖分）。

### 🌳 树链剖分思想简述

树链剖分（Heavy-Light Decomposition, HLD）是把一棵树剖分成若干条链，使得从任意节点到根的路径最多经过 O(log N) 条链。配合线段树/树状数组，可以在 O(log²N) 时间内完成**树上路径修改/查询**。

**核心思想：**
- 每个节点选择一个「重儿子」（子树最大的儿子）
- 重儿子和父节点在同一条链上
- 轻儿子开启一条新链

虽然今天不展开完整实现，但要记住：**树链剖分 = 把树拍扁成链 + 链上用线段树**。这是处理树上路径问题的终极武器。

## 🎯 面试技巧

### 1. LCA 问题的「分类讨论」话术

面试官问 LCA 时，不要直接丢代码。先展示你的分析能力：

> "这道题我首先会想到用递归 + 后序遍历。核心思路是分三种情况讨论：如果 p 和 q 分别在当前节点的左右子树，那当前节点就是 LCA；如果都在左子树，就去左边继续找；都在右子树就去右边找。时间复杂度是 O(N)，因为每个节点只访问一次。"

### 2. 主动提及「多次查询」的优化

如果面试官追问"如果要查很多组 LCA 怎么办"，这就是展示进阶知识的机会：

> "如果树的结构不变，但查询次数很多，可以用倍增法预处理。预处理 O(N log N)，每次查询 O(log N)。原理是预处理每个节点的第 2^k 级祖先，查询时先把两个节点提到同一深度，再一起往上倍增跳。"

### 3. 把 LCA 和实际场景联系起来

LCA 不只是算法题，实际系统中很常见：
- **文件系统的路径关系**：两个文件的最深公共目录
- **组织架构树**：两个员工的最近公共主管
- **DOM 树**：两个 DOM 节点的最近公共父节点
- **Git 分支合并**：找共同祖先（git merge-base）

### 4. 手写递归时的边界条件

```
if not root or root == p or root == q:
    return root
```
这个条件同时处理了三种情况，很简洁。面试时可以说：
> "终止条件我把它合并写了：遇到空返回 null，遇到 p 或 q 也返回。这样后面判断的时候，如果 left 和 right 都不为空，说明两边各找到一个，当前节点就是 LCA。"

### 5. 如果树不是二叉树怎么办？

> "如果是多叉树，思路完全一样：遍历所有子节点，统计哪些子树里找到了 p 或 q。如果多个子树都有结果，当前节点就是 LCA；如果只有一个子树有，返回那个结果。代码从递归左右子树变成递归所有子节点。"
