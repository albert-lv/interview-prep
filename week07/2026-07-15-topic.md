## 今日算法题

### 题目描述

有 `n` 个城市，其中一些彼此相连，另一些没有相连。如果城市 `a` 与城市 `b` 直接相连，且城市 `b` 与城市 `c` 直接相连，那么城市 `a` 与城市 `c` 间接相连。

**省份** 是一组直接或间接相连的城市，组内不含其他没有与该组内任何城市相连的城市。

给你一个 `n x n` 的矩阵 `isConnected`，其中 `isConnected[i][j] = 1` 表示第 `i` 个城市和第 `j` 个城市直接相连，而 `isConnected[i][j] = 0` 表示二者不直接相连。

返回矩阵中 **省份** 的数量。

**示例 1：**

```
输入：isConnected = [[1,1,0],[1,1,0],[0,0,1]]
输出：2
解释：城市 0 和 1 相连，构成一个省份。城市 2 单独构成一个省份。
```

**示例 2：**

```
输入：isConnected = [[1,0,0],[0,1,0],[0,0,1]]
输出：3
解释：三个城市各自独立，构成 3 个省份。
```

---

### 解题思路

这道题的本质是：**求无向图中连通分量的个数**。

并查集（Union-Find）是解决这类问题的神兵利器。它的核心思想很简单：

1. **初始状态**：每个城市自成一个集合，每个集合有一个"代表元"（可以简单理解为集合的"老大"）
2. **合并操作（Union）**：如果两个城市相连，就把它们所在的集合合并
3. **查找操作（Find）**：查询某个城市属于哪个集合（找它的"老大"是谁）

全部合并完成后，统计还有多少个不同的"老大"，就是省份的数量。

#### 并查集的两个经典优化

- **路径压缩（Path Compression）**：查找时把沿途所有节点的父节点直接指向根节点，让树变得超级扁平，后续查找几乎是 O(1)
- **按秩合并（Union by Rank）**：合并时让较小的树挂在较大的树下，防止树退化成链表

这两个优化加在一起，单次操作的均摊时间复杂度接近 **O(α(n))**，其中 α 是阿克曼函数的反函数，增长极其缓慢，可以视为常数级别。

---

### 代码实现

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))  # 每个节点的父节点，初始指向自己
        self.rank = [0] * n           # 树的秩（高度估计），用于按秩合并
        self.count = n                # 当前连通分量数量

    def find(self, x):
        """查找 x 的根节点 + 路径压缩"""
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # 递归压缩路径
        return self.parent[x]

    def union(self, x, y):
        """合并 x 和 y 所在的集合"""
        root_x = self.find(x)
        root_y = self.find(y)

        if root_x == root_y:
            return  # 已经在同一个集合，无需合并

        # 按秩合并：矮树挂高树
        if self.rank[root_x] < self.rank[root_y]:
            root_x, root_y = root_y, root_x
        self.parent[root_y] = root_x

        if self.rank[root_x] == self.rank[root_y]:
            self.rank[root_x] += 1

        self.count -= 1  # 连通分量数减 1

    def get_count(self):
        return self.count


class Solution:
    def findCircleNum(self, isConnected: List[List[int]]) -> int:
        n = len(isConnected)
        uf = UnionFind(n)

        for i in range(n):
            for j in range(i + 1, n):  # 只需要遍历上三角，避免重复
                if isConnected[i][j] == 1:
                    uf.union(i, j)

        return uf.get_count()
```

---

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n² × α(n)) | 遍历矩阵 O(n²)，每次 union/find 接近 O(1) |
| 空间 | O(n) | parent 数组 + rank 数组 |

> α(n) 是反阿克曼函数，对于任何实际应用中 n 的值（哪怕 n = 10⁹），α(n) ≤ 4，所以可以直接当成常数。

---

### 拓展：DFS/BFS 也能做，为什么还要学并查集？

这道题当然也可以用 DFS/BFS 遍历图来解决（找到所有连通分量），时间复杂度同样是 O(n²)。

**但并查集的优势在于：**
- **动态连通性**：边是逐步加入的，需要实时查询连通状态（如 LeetCode 684. 冗余连接）
- **离线查询**：先批量处理所有合并，再批量回答查询
- **可扩展性强**：配合按秩合并、路径压缩后，性能极其稳定
- **是 Kruskal 最小生成树算法的基础设施**

简单说：DFS/BFS 是"一次性遍历"，并查集是"持续维护连通关系"。两者都要会，看场景选武器。

## 面试技巧

### 1. 面试官问"这道题你能用几种方法做？"

这是送分题，但也是展示知识面的好机会：

> "这道题我可以用三种思路：
> - **DFS/BFS**：把矩阵看成邻接矩阵，遍历图找连通分量，O(n²)
> - **并查集**：更适合动态维护连通性，O(n² × α(n))
> - **BFS 染色**：从每个未访问城市出发，BFS 把能到的都标记为同一省份
> 实际工程中如果关系是动态变化的，我倾向用并查集。"

### 2. 手写并查集时要不要写优化？

**一定要写路径压缩**，这是并查集的精华。按秩合并可以视时间决定是否写（如果写了当然加分）。

如果面试官说"你先写个最基础的版本"，那可以先写不带优化的，但记得补充："实际应用中我会加上路径压缩，把复杂度降到近乎常数。"

### 3. 被问到并查集的应用场景

准备几个经典场景，显得你不是背题而是真懂：
- **社交网络中的好友圈分析**（本题就是）
- **Kruskal 最小生成树算法**（判断加边是否成环）
- **迷宫生成**（随机合并格子直到连通）
- **图片处理中的连通区域标记**
- **LeetCode 684. 冗余连接** — 检测无向图中的环

### 4. 现场 coding 的小技巧

- 把 `UnionFind` 封装成独立类，结构清晰，面试官一看就舒服
- `find()` 用递归写路径压缩最简洁，迭代版也行但代码稍长
- 遍历邻接矩阵时注意 `i` 和 `j` 的关系：只需要上三角（`j > i`）就够了，避免重复 union
- 最后返回 `uf.count` 比再遍历一遍 parent 数组找根节点要优雅

### 5. 如果被追问"并查集的时间复杂度怎么证明？"

大部分面试官也不会真的让你证，但能提一句显得很专业：

> "并查集用路径压缩 + 按秩合并后，单次操作的均摊复杂度是 O(α(n))。这个证明涉及反阿克曼函数，它增长非常缓慢，实际使用中可以看作常数。"
