## 1) 今日算法题

### 矩阵中的最长递增路径（LC 329 · Longest Increasing Path in a Matrix）

**题目描述：**

给定 `m × n` 的整数矩阵 `matrix`，找出其中**最长的严格递增路径**的长度。路径中的每步只能上下左右移动一格，且下一格的值必须**严格大于**当前格。

```
输入: matrix = [[9,9,4],[6,6,8],[2,1,1]]
输出: 4
解释: 最长递增路径为 [1, 2, 6, 9]，长度 4

输入: matrix = [[3,4,5],[3,2,6],[2,2,1]]
输出: 4
解释: 最长递增路径为 [1, 2, 6, 9] 或 [1, 2, 6, 7]... 实际为 [3→4→5→6] 长度 4
```

**收官工程读法：记忆化搜索 = 回归测试最小覆盖集。** 把矩阵看成「系统状态空间」：每格是一个状态，边是「状态 A 能严格进化到状态 B」。**严格递增 = 永不回退 = 无回归**：路径上一旦出现环（走回更差的格子）就是版本回退、旧 bug 重现。`memo[i][j]` = 「从状态 (i,j) 出发能维持多少步严格改进」——**这张表本身就是回归测试的最小覆盖集：每个状态只验证一次，验证过的结论永不重算**。K3.1 Pro 学走路是活样本：从倒地到 11.2 秒连续行走，每一步迭代都必须严格更好，36 处力臂错误修完即入册（重犯=回归）。**答案 = 系统能支撑的最长连续改进链；memo 表 = 保证这条链不被打断的最小测试资产。**

### 思路：记忆化 DFS（自顶向下）

**核心观察：**

1. **子问题重叠**：从 (i,j) 出发的最长路径，其子问题「从邻居出发的最长路径」会被反复计算——裸 DFS 是指数级，**加一张 memo 表每个格子只算一次**。
2. **严格递增天然无环**：邻居必须比当前大，路径上的值单调上升 → 不可能是环 → **不需要 visited 数组**（这是面试官最爱挖的坑：问「要不要防重复访问？」答「严格递增本身就是防环的」）。
3. **DAG 上求最长路径**：记忆化 DFS 是通用模板——状态 = 节点，依赖 = 边，`memo[v] = max(1, memo[邻居] + 1)`。

**Go 实现：**

```go
func longestIncreasingPath(matrix [][]int) int {
    if len(matrix) == 0 || len(matrix[0]) == 0 {
        return 0
    }
    m, n := len(matrix), len(matrix[0])
    memo := make([][]int, m)
    for i := range memo {
        memo[i] = make([]int, n) // 0 = 未计算
    }
    dirs := [][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}

    var dfs func(i, j int) int
    dfs = func(i, j int) int {
        if memo[i][j] > 0 {
            return memo[i][j] // 已验证的状态不重算 = 回归集命中
        }
        best := 1
        for _, d := range dirs {
            ni, nj := i+d[0], j+d[1]
            if ni >= 0 && ni < m && nj >= 0 && nj < n && matrix[ni][nj] > matrix[i][j] {
                if l := dfs(ni, nj) + 1; l > best {
                    best = l
                }
            }
        }
        memo[i][j] = best
        return best
    }

    ans := 0
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if l := dfs(i, j); l > ans {
                ans = l
            }
        }
    }
    return ans
}
```

**复杂度：时间 O(m·n)**（每格入栈一次、四个方向各看一次）**·空间 O(m·n)**（memo + 递归栈最深 O(m+n)——**面试官追问栈溢出：m,n ≤ 10³ 时 DFS 递归深度最坏 O(m+n)=2×10³，Go 默认栈够；Java 要给 JVM 加栈或改迭代**）。

**正确性一句话**：memo[i][j] 的计算只依赖「值更大」的邻居，而严格递增保证依赖图是 DAG，无后效性成立——自顶向下记忆化与自底向上拓扑序等价。

**进阶阶梯六连：**

① **双解收官·Kahn 剥层（直接 callback Day 152 的 LC 207！）**：把「小 → 大」的有向边建出来，**出度为 0 的是山顶（四周没有更大的格子）**，从山顶反向剥层，剥了 k 层答案就是 k——**同一道题，Day 5 的算法是 Day 6 的第二种解法**：记忆化 DFS 自顶向下，Kahn 自底向上，都是 O(mn)。能说出「这题本质是 DAG 最长路径，DFS+memo 和拓扑排序是一体两面」= 图论 maturity 的收官证明。

② **通用模板：DAG 最长路径记忆化搜索**：任何「状态 + 严格转移」的问题都能套——树形 DP（根节点状态依赖子树）、区间 DP、数位 DP 全是它的变体。**口诀：定义状态 → 写转移 → memo 兜底 → 全图扫一遍取 max**。

③ **非严格递增（≥）怎么办**：允许相等值 → 可能成环 → 记忆化失效，**先缩点（Tarjan）把 SCC 压成超节点再跑**——「面试官把『严格』两个字拿掉，就是想把裸背题的人筛出去」。

④ **输出路径本身**：memo 值决定方向——从全局最大 memo 格出发，每次走 memo 值恰好 -1 的邻居，逆推即得路径；**工程读法：不仅知道能改多少步，还知道每一步改什么=回归集按序执行清单**。

⑤ **最小覆盖集视角（面试技巧主线呼应）**：memo 表每个非零格子 = 一条已验证结论；全表 = 覆盖所有状态的最小验证资产——**回归测试设计的第一性原理：不重测已验证的、不漏测未验证的、每个状态恰好一条断言**。Day 152「行为维度覆盖 > 输入覆盖」在算法层的镜像。

⑥ **并行化**：矩阵按值分治 + 分层同步（Kahn 版天然层间并行，层内任意并行）——**工程读法：回归集分层执行，前一层绿了才跑下一层=CI 流水线的波次调度（Day 152 关键路径=wall-clock 下限）**。

### 混合模拟面试：一间会议室考六天

**场景题**：面试官说——「设计一个 50-agent 的自动化代码工厂：接需求 → 拆任务 → 写码 → 测试 → 审查 → 交付。开始吧。」然后连环追问。

**Q1（协调·Day 148）：50 个 agent 怎么组织？**
可拆可验 → **supervisor + 分层**：架构 router → 代码/测试/审查 specialist（A2A/MCP 标准化接入）→ review agent 裁决。三必答件：交接点 JSON Schema 校验、每 agent token 预算硬顶、终止条件（max rounds + 新颖性检测 + 挂钟 deadline）。**加分项**：先反问任务耦合度——耦合低才 supervisor；需求模糊先黑板收敛再 supervisor 执行。

**Q2（消息·Day 149）：它们之间怎么通信？聊爆/聊死怎么办？**
三类信息三种载体：指令=强 schema 消息（version 最外层+tolerant reader）、事实=黑板条目（带来源时间戳）、协商=会话消息（过期语义）。聊爆→新颖性检测+每轮发言上限+频道收敛；聊死→消息等待图画环找死锁+全局 deadline 强杀。**金句级收尾：「讨论要有个沉淀层——消息是过程，看板是状态」**。

**Q3（预算·Day 150）：token 钱谁管？**
账本树：task_id 主键五元组（task/agent/model/in/out tokens），消息按边记账，管理节点税单列（METR 式「管理烧 60%」一眼可见）。**给任务拨预算不给 agent 拨预算**；燃烧顺序背出口诀；三方对账先信服务商账单；idempotency key = task+agent+counter。

**Q4（容错·Day 151）：一个 agent 开始说假话/投毒怎么办？**
先分类再治理：crash→心跳+进展探针+checkpoint；omission→超时+重试+幂等；Byzantine→**高影响声明≥2 个独立来源交叉验证+签名消息（f<n 的税比 f<n/3 便宜）+append-only 哈希链+写权限最小化**。诚实答：**单靠一个节点日志分不出幻觉/注入/作恶——按最坏处理，先止血（隔离降权）再归因**。

**Q5（评测·Day 152）：怎么证明 50 个比 3 个强？怎么防版本升级后变差？**
先立评测协议再谈数字：pass^k 限定协调机制生效的 trial 子集、报 seed 方差不报单点、挂钟×token×通过率三维同报（噪声地板：n=100 两 seed 下 ±18pp 都可能纯噪声）。回归防线：行为维度回归集+子指标分列+数据集 hash 版本化+「读 cutoff 不然读小说」。**敢在报告里写「这个维度变差了」是评测成熟度的分水岭**。

**Q6（收口·综合）：上线第一天 P0——交付物里发现了恶意依赖，agent 互相甩锅，你怎么排查？**
六天弹药全上：①**溯源**（Day 149）：trace-id 贯穿日志+哈希链验证日志没被 tamper——先确认证据可信 ②**画像**（Day 151）：跨 run 行为关联，谁最早引入该依赖、谁审查过却没拦（**合法行为里的敌意模式=S-1 的 6% 蒸馏同款**）③**归因**（Day 152）：时间线对齐→因果链>排除法→定性四分类（有意/系统性/偶发/涌现）④**处置**（Day 151）：kill switch 演练过的链路止血→隔离涉事 agent ⑤**修复**（Day 153）：入册——恶意依赖特征进投毒样本库，review agent 的漏检行为进回归集，**下一次注入演练清单加一行**。

### 高频速答六连（收官版）

- **Q1 用一句话总结 Week 23？** 「协议管说话、账本管花钱、容错管使坏、评测管证明——而记忆化管的是别让修过的东西再坏回去。」
- **Q2 MCP 和 A2A 什么关系？** 「orthogonal 两层：MCP 连 agent 和工具，A2A 连 agent 和 agent；『都要』是常态——对外接活靠 A2A，干活的手还是 MCP。采购必问 spec 版本号，版本没对齐的『支持』约等于不支持。」
- **Q3 多 agent 一定比单 agent 强吗？** 「先反问评测协议：n 多少、seed 几个、pass^k 限没限定协调生效子集。挂钟提速是真的（SwarmChat：+1/3 token 换 5 小时），准确率 delta 在噪声地板下声称显著=不专业。」
- **Q4 黑板和队列能不能只用一个？** 「不能。队列=命令通道（消费即销毁），黑板=状态通道（随时读最新）。只用队列=快照必然漂移；只用黑板=事实混进待办。」
- **Q5 f<n/3 能不能绕过？** 「两个口子：签名消息（Lamport）不可伪造→坏节点只能污染自己的票→放宽到 f<n，代价是签名基础设施，能验签就别付 3f+1 的税；受控执行环境（TEE/只读文件系统）把任意偏离降级成 crash，回到重启就能治的世界。」
- **Q6 怎么让系统持续变好而不是偶尔变好？** 「今天这题：把每次改进写成严格递增路径上的一步（修完的 bug 入 memo），用最小覆盖集保证不回退，用 Kahn 波次把改进串成可并行的回归流水线——**变好不是一次冲刺，是一条不允许出现环的路径**。」

### 金句

> **多智能体工程收官的一句话：设计决定系统能不能跑，记忆化决定它会不会变好。K3.1 Pro 用 36 处力臂修正换来 11.2 秒的连续行走，靠的不是某一次神力——是每一步都严格好于上一步，且修过的错误永不再犯。系统的演进不是把格子全部点亮（那是 BFS 的广度），而是找到那条最长的、严格递增的爬坡路径：每一步都比上一步高，一旦绕回低处（环），之前的修正就全部作废。所以 memo 表不是优化技巧，是工程纪律——它是回归测试的最小覆盖集，是「变好」这件事的持久化层。当面试官问「怎么让多 agent 系统持续可靠地变好」，他真正在问的是：你的改进有没有严格递增的形状、修过的问题入册了吗、你的系统里有没有环——以及，上一次回归，是哪条路径断了。**
