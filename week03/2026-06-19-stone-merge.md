## 📝 题目描述

有 `n` 堆石子排成一排，第 `i` 堆石子的重量为 `stones[i]`。每次可以将**相邻**的两堆石子合并，合并的代价为这两堆石子的重量之和。求将所有石子合并为一堆的**最小总代价**。

**示例**:
```
输入: stones = [3, 2, 4, 1]
输出: 20

解释:
- 合并 [3,2] → [5, 4, 1], 代价 5
- 合并 [4,1] → [5, 5], 代价 5
- 合并 [5,5] → [10], 代价 10
总代价 = 5 + 5 + 10 = 20
```

---

## 💡 核心思路

石子合并是**区间DP**的经典模板题，和最长回文子序列形成完美互补：

| 题目 | 状态定义 | 转移方向 |
|------|----------|----------|
| 最长回文子序列 | `dp[i][j]` = 子串`s[i:j]`的最长回文子序列长度 | 两端向内缩 |
| **石子合并** | `dp[i][j]` = 合并区间`[i,j]`的最小代价 | **枚举中间分割点** |

### 状态定义

```
dp[i][j] = 将第 i 堆到第 j 堆石子合并为一堆的最小代价
```

### 状态转移

```
dp[i][j] = min(dp[i][k] + dp[k+1][j] + sum(i,j))  其中 k ∈ [i, j-1]
                    ↑           ↑           ↑
                 左半区间     右半区间     最后一次合并的代价
```

### 为什么枚举分割点？

> 因为最后一步一定是把某个中间位置 `k` 左右两边已经合并好的大石子堆再合并。无论之前怎么合并，最后一步一定是两堆变一堆。所以我们枚举这个"最后一步的分割点"。

### 关键观察：最后一次合并代价

```
sum(i,j) = prefix[j+1] - prefix[i]  // 区间[i,j]的石子总和（前缀和优化）
```

> 不管内部怎么合并，`[i,j]` 所有石子的总重量是固定的，最后一次合并就是把左右两个大堆合起来，代价就是这个总和。

---

## 🖥️ 代码实现

```python
def minStoneMerge(stones):
    n = len(stones)
    if n <= 1:
        return 0
    
    # 前缀和: prefix[i] = stones[0] + ... + stones[i-1]
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + stones[i]
    
    # dp[i][j] = 合并[i,j]的最小代价
    # 初始化: 单堆不需要合并，代价为0；其他先设无穷大
    dp = [[0] * n for _ in range(n)]
    
    # 区间长度从小到大枚举（len=2 到 n）
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = float('inf')
            
            # 枚举分割点 k: [i,k] 和 [k+1,j]
            for k in range(i, j):
                left_cost = dp[i][k]           # 合并左半区间的代价
                right_cost = dp[k + 1][j]      # 合并右半区间的代价
                merge_cost = prefix[j + 1] - prefix[i]  # 最后一次合并代价
                dp[i][j] = min(dp[i][j], left_cost + right_cost + merge_cost)
    
    return dp[0][n - 1]


# 验证
stones = [3, 2, 4, 1]
print(minStoneMerge(stones))  # 输出: 20
```

## ⏱️ 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(n³) | 区间长度 O(n) × 起点 O(n) × 分割点 O(n) |
| **空间** | O(n²) | dp 二维数组 |
| **优化** | 时间可优化至 O(n²) | Garsia-Wachs 算法（了解即可，面试不要求） |

> 面试时写 O(n³) 的区间DP解法已经足够。如果被追问优化，可以提到：当石子是环形排列时，需要破环成链（长度×2），难度升级为 ⭐⭐⭐⭐。

## 🎯 面试技巧

### 1. 如何向面试官解释"为什么枚举分割点"

❌ 不要这样说：
> "这是一个区间DP，所以枚举分割点。"

✅ 要这样说：
> "无论怎么合并，最后一步一定是把两堆已经合并好的石子再合并成一堆。所以我枚举最后一步的分割点 `k`，左边 `[i,k]` 已经合成一堆，右边 `[k+1,j]` 也已经合成一堆，最后把这两堆合起来的代价就是整个区间的总和。"

### 2. 画图辅助解释

```
stones = [3, 2, 4, 1]

最后一步可能是这样分：
┌─────────┬─────────┐
│ [3,2,4] │   [1]   │  k=2, 代价=10+1=11
└─────────┴─────────┘

或者这样：
┌───────┬───────────┐
│ [3,2] │   [4,1]   │  k=1, 代价=5+5=10  ← 最优
└───────┴───────────┘

或者这样：
┌───┬───────────────┐
│[3]│   [2,4,1]     │  k=0, 代价=3+7=10
└───┴───────────────┘
```

> 边画边说，面试官会觉得你思路特别清晰。

### 3. 手写代码时的小技巧

- **先写前缀和**，再写DP —— 面试官看到前缀和就知道你考虑到了区间求和的优化
- **枚举顺序**：外层长度、内层起点 —— 这是区间DP的标准写法，面试官一看就懂
- **初始化注意**：`dp[i][i] = 0` 天然满足，因为单堆不用合

### 4. 边界情况

```python
# 面试时主动提一下边界，加分
if n <= 1:
    return 0  # 0堆或1堆，不需要合并
```

### 5. 扩展追问预备

如果面试官问"如果是环形排列呢？"：
> "可以把数组复制一份接在后面，然后枚举长度为 n 的区间求最小值。这样时间复杂度还是 O(n³)，但空间变成 O((2n)²)。"

## 🔗 举一反三

| 题目 | 核心变化 | 难度 |
|------|----------|------|
| **矩阵链乘法** | `dp[i][j] = min(dp[i][k] + dp[k][j] + cost)` | ⭐⭐⭐ |
| **括号匹配/移除** | 类似框架，求最少添加/删除 | ⭐⭐⭐ |
| **树形DP: 打家劫舍III** | 从区间转移到树上 | ⭐⭐⭐ |
| **Burst Balloons** | 逆向思考：最后爆破的气球 | ⭐⭐⭐⭐ |

> 石子合并、矩阵链乘法、Burst Balloons 被称为"区间DP三大板斧"，框架几乎一样，都是枚举分割点。
