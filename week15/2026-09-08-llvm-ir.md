## 1. 今日算法题

### 基本计算器 III

**题目来源**：LeetCode 772（Hard）

**题目描述**：
实现一个基本的计算器来计算简单的表达式字符串。

表达式字符串只包含非负整数、`+`、`-`、`*`、`/` 运算符、`(` `)` 括号以及空格。整数除法需要向零截断。

你可以假设给定的表达式总是有效的，并且**所有中间结果和最终结果都在 32 位有符号整数范围内**。

**进阶**：表达式中还可能包含变量（小写字母）和赋值操作（`a=1+2` 形式）。

---

**示例**：

```
输入: "1 + 1"
输出: 2

输入: " 6-4 / 2 "
输出: 4

输入: "2*(5+5*2)/3+(6/2+8)"
输出: 21

输入: "(2+6*3+5-(3*14/7+2)*5)+3"
输出: -12

输入: "0"
输出: 0
```

### 解题思路

这道题是 **Day 95 递归下降解析器的直接实战升级**。如果说 Day 95 是在教你"怎么写解析器"，今天这道题就是"用解析器解决真问题"。

**核心思路：递归下降解析（Recursive Descent Parsing）**

我们延续 Day 95 的语法规则，但加入乘除法和变量支持：

```
expr   → term { ('+' | '-') term }
term   → factor { ('*' | '/') factor }
factor → number | '(' expr ')' | variable
```

每一层对应一个函数，调用栈天然处理优先级和括号嵌套：
- `expr()` 处理加减（最低优先级）
- `term()` 处理乘除（中等优先级）
- `factor()` 处理数字、括号、变量（最高优先级）

**从 AST 到 LLVM IR 的桥梁**：

这道题的手写解析器过程，本质上就是在模拟编译器前端的工作流程：

```
源代码字符串 → 词法分析（tokenizer）→ 语法分析（recursive descent）→ AST → LLVM IR 生成
     ↑                                                        ↓
   本题输入                                              本题输出（int 结果）
```

在真实编译器中，解析完成后会遍历 AST 生成 LLVM IR。今天我们先聚焦"把解析器写对"，面试技巧部分再深入 LLVM IR 的生成细节。

### 代码实现（Python）

```python
class Solution:
    def calculate(self, s: str) -> int:
        """
        基本计算器 III：递归下降解析
        支持 + - * / ( ) 和空格，整数除法向零截断
        """
        self.s = s
        self.n = len(s)
        self.i = 0  # 当前解析位置
        
        def parse_expr() -> int:
            """expr → term { ('+' | '-') term }"""
            result = parse_term()
            while self.i < self.n and self.s[self.i] in '+-':
                op = self.s[self.i]
                self.i += 1
                right = parse_term()
                if op == '+':
                    result += right
                else:
                    result -= right
            return result
        
        def parse_term() -> int:
            """term → factor { ('*' | '/') factor }"""
            result = parse_factor()
            while self.i < self.n and self.s[self.i] in '*/':
                op = self.s[self.i]
                self.i += 1
                right = parse_factor()
                if op == '*':
                    result *= right
                else:
                    # 向零截断的整数除法
                    result = int(result / right)
            return result
        
        def parse_factor() -> int:
            """factor → number | '(' expr ')'"""
            # 跳过空格
            while self.i < self.n and self.s[self.i] == ' ':
                self.i += 1
            
            if self.i >= self.n:
                return 0
            
            ch = self.s[self.i]
            
            if ch == '(':
                # 括号：递归解析内部表达式
                self.i += 1  # 跳过 '('
                result = parse_expr()
                self.i += 1  # 跳过 ')'
                return result
            
            # 解析数字
            num = 0
            while self.i < self.n and self.s[self.i].isdigit():
                num = num * 10 + int(self.s[self.i])
                self.i += 1
            return num
        
        return parse_expr()
```

### 代码实现（C — 更贴近编译器实现）

```c
#include <stdio.h>
#include <ctype.h>

const char *p;  // 全局解析指针

int expr(void);
int term(void);
int factor(void);

// 跳过空白字符
void skip_space(void) {
    while (*p == ' ') p++;
}

// expr → term { ('+' | '-') term }
int expr(void) {
    skip_space();
    int result = term();
    skip_space();
    while (*p == '+' || *p == '-') {
        char op = *p++;
        int right = term();
        if (op == '+') result += right;
        else result -= right;
        skip_space();
    }
    return result;
}

// term → factor { ('*' | '/') factor }
int term(void) {
    skip_space();
    int result = factor();
    skip_space();
    while (*p == '*' || *p == '/') {
        char op = *p++;
        int right = factor();
        if (op == '*') result *= right;
        else result = result / right;  // C 的整数除法本身就是向零截断
        skip_space();
    }
    return result;
}

// factor → number | '(' expr ')'
int factor(void) {
    skip_space();
    if (*p == '(') {
        p++;  // 跳过 '('
        int result = expr();
        p++;  // 跳过 ')'
        return result;
    }
    // 解析数字
    int num = 0;
    while (isdigit(*p)) {
        num = num * 10 + (*p - '0');
        p++;
    }
    return num;
}

int calculate(const char *s) {
    p = s;
    return expr();
}

int main(void) {
    printf("%d\n", calculate("1 + 1"));                       // 2
    printf("%d\n", calculate(" 6-4 / 2 "));                  // 4
    printf("%d\n", calculate("2*(5+5*2)/3+(6/2+8)"));       // 21
    printf("%d\n", calculate("(2+6*3+5-(3*14/7+2)*5)+3"));  // -12
    return 0;
}
```

编译运行：
```bash
gcc calculator3.c -o calc3 && ./calc3
```

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | O(n) | 每个字符只被扫描一次，递归调用只是移动指针 |
| **空间** | O(n) | 递归栈深度最坏情况等于括号嵌套层数（如 `"(((1)))"`） |

**注意**：这里的 O(n) 时间并不是显然的——因为递归会回溯，但每个字符只会被 `factor()` 中的数字解析或 `expr()`/`term()` 中的运算符检查访问一次。

### 🔥 面试官连环问

> **Q1：如果加入变量支持（如 `a=1+2`），怎么扩展？**
>
> 答：增加一层 `assignment` 规则：`assign → var '=' expr | expr`，同时维护一个符号表（`HashMap<String, Integer>`）。变量解析时先查符号表，找不到报错。这也是 LLVM IR 中 `alloca` + `store`/`load` 的雏形。

> **Q2：怎么把这个解析器改成生成 AST，而不是直接求值？**
>
> 答：把每个 `parse_*()` 函数的返回值从 `int` 改成 `ASTNode*`。`ASTNode` 包含节点类型（BinaryOp/Number/Variable）和子节点。最后返回根节点，再写一个 `eval(ASTNode*)` 做后序遍历求值。这是编译器前端的标配做法。

> **Q3：从 AST 到 LLVM IR 的关键步骤是什么？**
>
> 答：三步走：①**指令选择**（AST → 中间表示，如三地址码）；②**SSA 转换**（每个变量只赋值一次，用 φ 函数合并控制流）；③**代码生成**（遍历 SSA 形式的 IR，输出 LLVM IR 汇编）。LLVM 的 `IRBuilder` 就是做这个事的 API。

> **Q4：递归下降的缺点是什么？什么情况下不能用？**
>
> 答：最大的问题是**左递归**（如 `expr → expr + term`），需要手动改写成循环形式。另一个问题是**回溯效率低**（不过本题是无回溯的 LL(1) 文法，不存在这个问题）。对于复杂语言（如 C++ 的模板），递归下降手写会很痛苦，通常用自动生成工具（Yacc/Bison/ANTLR）。

## 2. 面试技巧

### LLVM IR 与中间代码优化 — 面试速查

#### 2.1 什么是 LLVM IR？

LLVM IR（Intermediate Representation）是 LLVM 编译器基础设施的核心——一种**强类型、SSA 形式、低级别但机器无关**的中间表示。

```
源代码 (C/C++/Rust/Swift)
    ↓
前端 (Clang) → AST → LLVM IR
    ↓
优化器 (Opt Passes) → 优化的 LLVM IR
    ↓
后端 (CodeGen) → 目标机器码 (x86/ARM/RISC-V)
```

**为什么需要 IR？**
- **解耦**：N 种前端语言 × M 种目标架构 = N+M 个组件，而不是 N×M
- **优化复用**：同一套优化 Pass 对所有语言生效
- **可移植**：IR 是文本格式，可以跨平台传递、分析、调试

#### 2.2 SSA 形式（Static Single Assignment）

SSA 是 LLVM IR 的核心特性：**每个变量只被赋值一次**。

```llvm
; 非 SSA（普通三地址码）
a = 1
a = a + 2   ; a 被赋值两次！
b = a * 3

; SSA 形式
a1 = 1
a2 = add a1, 2   ; 新变量 a2
b1 = mul a2, 3   ; 每个变量只定义一次
```

**SSA 的好处**：
- **简化数据流分析**：每个变量的定义点是唯一的，不用做到达定义分析
- **优化更激进**：常量传播、死代码删除、公共子表达式消除在 SSA 上实现更简单
- **直接映射寄存器分配**：LLVM 后端用图着色算法做寄存器分配，SSA 是前提

**φ（Phi）函数**：处理控制流合并点

```llvm
; if-else 合并
if.true:
  x1 = 1
  br label %merge
if.false:
  x2 = 2
  br label %merge
merge:
  x3 = phi i32 [ x1, %if.true ], [ x2, %if.false ]  ; 根据从哪跳过来选值
```

**面试速答模板**：
> "SSA 要求每个变量只被赋值一次。通过引入带版本号的变量（如 `x1`, `x2`）和 φ 函数处理控制流合并，大幅简化了数据流分析和优化算法的实现。LLVM 的几乎所有优化 Pass 都基于 SSA。"

#### 2.3 基本块（Basic Block）与控制流图（CFG）

**基本块**：一段连续的指令序列，只能从第一条指令进入，从最后一条指令离开。

```llvm
define i32 @foo(i32 %a) {
entry:
  %cmp = icmp sgt i32 %a, 0        ; 比较
  br i1 %cmp, label %if.then, label %if.else   ; 唯一出口：分支

if.then:                           ; 基本块开始
  %add = add i32 %a, 1
  br label %return                  ; 基本块结束：无条件跳转

if.else:                           ; 基本块开始
  %sub = sub i32 0, %a
  br label %return                  ; 基本块结束

return:                            ; 合并基本块
  %retval = phi i32 [ %add, %if.then ], [ %sub, %if.else ]
  ret i32 %retval
}
```

**CFG**：用基本块作为节点、跳转关系作为边构成的有向图。

**面试常考点**：
- 基本块的划分算法（找 leader 指令）
- CFG 在优化中的作用：死代码消除（不可达块删除）、循环优化（识别回边）

#### 2.4 LLVM IR 常见优化 Pass

| Pass | 作用 | 面试关键词 |
|------|------|-----------|
| **mem2reg** | 将栈上 `alloca` 提升为 SSA 寄存器 | 关键 Pass，SSA 构造 |
| **constprop** | 常量传播 | 编译期计算 |
| **dce** | 死代码消除 | 无用代码删除 |
| **inline** | 函数内联 | 消除调用开销，权衡代码膨胀 |
| **loop-unroll** | 循环展开 | 减少分支预测失败，增大数据局部性 |
| **gvn** | 全局值编号 | 公共子表达式消除（CSE） |
| **sroa** | 聚合体标量替换 | struct → 独立变量，利于寄存器分配 |
| **instcombine** | 指令组合 | `a*2 → a<<1` 等窥孔优化 |

**面试速答 — 优化器 Pipeline**：
> "LLVM 优化器是 Pass-based 架构，每个 Pass 做一件事。常见 Pipeline 包括：SSA 构造（mem2reg）→ 常量传播/死代码消除 → 循环优化（展开/不变量外提）→ 指令选择 → 寄存器分配。Pass 可以按需组合，`-O0` 几乎不跑，`-O3` 跑全套。"

#### 2.5 从 AST 到 LLVM IR：代码生成实战

以 `a + b * c` 为例，看看 AST 怎么变成 LLVM IR：

```
      +
     / \
    a   *
       / \
      b   c

AST (抽象语法树)
```

```llvm
; 生成的 LLVM IR
%t1 = mul i32 %b, %c      ; 先算乘法（优先级高）
%t2 = add i32 %a, %t1     ; 再算加法
```

**代码生成关键步骤**：

1. **符号表管理**：变量名 → LLVM `Value*`（SSA 值）
2. **递归遍历 AST**：后序遍历（先子节点，再父节点）
3. **指令创建**：用 `IRBuilder` 创建 `add`/`mul` 等指令
4. **类型系统**：确保操作数类型一致（i32/float 等）

```cpp
// LLVM API 伪代码
Value *Codegen(ASTNode *node) {
    if (node->type == BINARY_OP) {
        Value *L = Codegen(node->left);   // 递归左子树
        Value *R = Codegen(node->right);  // 递归右子树
        if (node->op == '+') 
            return Builder.CreateAdd(L, R, "addtmp");
        if (node->op == '*')
            return Builder.CreateMul(L, R, "multmp");
    }
    // ...
}
```

#### 2.6 深度学习编译器：TVM / MLIR / XLA

| 编译器 | 背景 | 核心思想 | 面试关键词 |
|--------|------|---------|-----------|
| **TVM** | 陈天奇，Apache | 计算图优化 + 算子自动调度（AutoTVM） | Relay IR、TVM Tensor Expression、调度空间搜索 |
| **MLIR** | Google/LLVM 社区 | 多层级 IR，方言（Dialect）机制 | 可扩展、Tensor/Vector/Affine/SCF Dialect、逐步降低 |
| **XLA** | Google TensorFlow | JIT/AOT 编译 TensorFlow 图 | HLO（High Level Optimizer）、算子融合、常量折叠 |

**为什么 AI 需要专用编译器？**

```
传统编译器（LLVM）：
  for (i) for (j) C[i][j] = A[i][j] + B[i][j]
  → 很难自动向量化、并行化

AI 编译器（TVM/XLA）：
  算子级别已知语义（conv/matmul/relu）
  → 自动融合（conv+relu→conv_relu）、自动分块、自动并行
```

**面试速答 — TVM vs MLIR**：
> "TVM 是端到端的深度学习编译器，从模型到机器码。核心是 Relay（图级别优化）+ TE（张量表达式）+ AutoTVM（自动调度搜索）。MLIR 更像一个编译器框架，用 Dialect 机制支持多层级 IR，从高层 ML 算子逐步 lower 到 LLVM IR。MLIR 更灵活，TVM 更专注。"

#### 2.7 高频面试题速记

| 问题 | 一句话速答 |
|------|-----------|
| LLVM IR 为什么用 SSA？ | 简化数据流分析，每个变量定义点唯一，优化算法实现更简单 |
| φ 函数的作用？ | 在控制流合并点（如 if-else 的 join 块）选择不同前驱块的值 |
| mem2reg 做了什么？ | 将栈分配的局部变量（`alloca`）提升为 SSA 虚拟寄存器 |
| 编译器优化 `-O2` 和 `-O3` 的区别？ | O2 是平衡点，O3 开启激进优化（循环展开、向量化），可能增加代码体积 |
| TVM 的 AutoTVM 原理？ | 定义算子的调度空间，用机器学习（XGBoost）搜索最优分块/展开/并行策略 |
| MLIR 的 Dialect 是什么？ | 可扩展的 IR 方言系统，不同层级（Tensor/Affine/LLVM IR）用不同 Dialect，逐步 lower |
| XLA 的算子融合怎么做？ | 识别相邻算子（如 conv+relu）合并为单一 kernel，减少内存搬运 |
| JIT vs AOT 编译的区别？ | JIT 运行时编译（如 Java HotSpot、XLA JIT），AOT 提前编译（如 Go、Rust、XLA AOT） |
| 为什么 AI 编译器比传统编译器更需要自动优化？ | 张量算子维度大、计算模式规则，手动调优不现实，自动搜索收益高 |

### 面试现场 — 模拟问答

> **面试官**："你在项目里用过 LLVM 吗？说说 LLVM IR 的 SSA 形式有什么好处。"
>
> **你**："我在做编译器课程项目时接触过 LLVM。SSA 的核心好处是**每个变量只被赋值一次**，这让数据流分析变得特别简单。比如做常量传播，只要看变量的唯一定义点是不是常量就行，不用做复杂的到达定义分析。LLVM 的 mem2reg Pass 就是把栈上的 alloca 变量转成 SSA 寄存器，后续优化 Pass 都依赖这个前提。"
>
> **面试官**："那如果代码里有 `if-else`，两边给同一个变量赋不同值，SSA 怎么处理？"
>
> **你**："用 φ（Phi）函数。在控制流合并的基本块里，φ 会根据程序从哪个前驱块跳转过来选择对应的值。比如 `if.true` 块定义了 `x1`，`if.false` 定义了 `x2`，在合并块里写 `x3 = phi [x1, %if.true], [x2, %if.false]`。这样 SSA 的'单次赋值'性质就不破了。"
>
> **面试官**："TVM 和 MLIR 都是 AI 编译器，有什么区别？"
>
> **你**："TVM 是**端到端的解决方案**，从模型（ONNX/PyTorch）到机器码，核心是 Relay 做图优化、TE 定义算子、AutoTVM 自动搜索调度。MLIR 更像**编译器基础设施**，用 Dialect 机制定义多层 IR，可以表达从高层 ML 算子到底层 LLVM IR 的任意中间层。MLIR 更灵活通用，TVM 更专注深度学习的端到端编译。"
