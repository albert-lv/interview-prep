## 今日算法题：逆波兰表达式求值

### 题目描述（LeetCode 150）

给你一个字符串数组 `tokens`，表示一个根据**逆波兰表示法**（Reverse Polish Notation, RPN）表示的算术表达式。

请你计算该表达式的值，返回一个表示表达式值的整数。

**注意：**
- 有效的算符为 `'+'`、`'-'`、`'*'` 和 `'/'`
- 每个操作数可以是整数，也可以是另一个表达式
- 两个整数之间的除法总是**向零截断**
- 表达式中不含括号
- 答案及所有中间计算结果可以用 **32 位整数** 表示

**示例 1：**
```
输入: tokens = ["2","1","+","3","*"]
输出: 9
解释: ((2 + 1) * 3) = 9
```

**示例 2：**
```
输入: tokens = ["4","13","5","/","+"]
输出: 6
解释: (4 + (13 / 5)) = 4 + 2 = 6
```

**示例 3：**
```
输入: tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
输出: 22
解释: ((10 * (6 / ((9 + 3) * -11))) + 17) + 5
```

### 思路：栈

逆波兰表达式（后缀表达式）的核心优势：**不需要括号，运算符优先级天然正确**。

计算规则很简单：
1. 遇到**数字** → 压入栈
2. 遇到**运算符** → 弹出栈顶两个元素，运算后将结果压回栈
3. 最后栈中只剩一个元素，就是答案

**为什么要先弹出右操作数？**

```
对于 "13","5","/"：
先弹出 5（右操作数），再弹出 13（左操作数）
计算 13 / 5 = 2
```

如果顺序错了，会变成 5 / 13，结果完全不同！

### 代码实现

**Python：**
```python
def evalRPN(tokens: list[str]) -> int:
    stack = []
    
    for token in tokens:
        if token in {"+", "-", "*", "/"}:
            # 先弹出的是右操作数！
            b = stack.pop()
            a = stack.pop()
            
            if token == "+":
                stack.append(a + b)
            elif token == "-":
                stack.append(a - b)
            elif token == "*":
                stack.append(a * b)
            else:  # "/"
                # Python 的 // 是向负无穷截断，题目要求向零截断
                stack.append(int(a / b))
        else:
            stack.append(int(token))
    
    return stack[-1]
```

**Go：**
```go
func evalRPN(tokens []string) int {
    stack := make([]int, 0, len(tokens))
    
    for _, token := range tokens {
        switch token {
        case "+", "-", "*", "/":
            n := len(stack)
            b := stack[n-1]
            a := stack[n-2]
            stack = stack[:n-2]
            
            var res int
            switch token {
            case "+":
                res = a + b
            case "-":
                res = a - b
            case "*":
                res = a * b
            case "/":
                res = a / b  // Go 的整数除法天然向零截断 ✅
            }
            stack = append(stack, res)
        default:
            num, _ := strconv.Atoi(token)
            stack = append(stack, num)
        }
    }
    
    return stack[0]
}
```

**C++：**
```cpp
class Solution {
public:
    int evalRPN(vector<string>& tokens) {
        stack<int> st;
        
        for (const string& token : tokens) {
            if (token == "+" || token == "-" || token == "*" || token == "/") {
                int b = st.top(); st.pop();
                int a = st.top(); st.pop();
                
                if (token == "+") st.push(a + b);
                else if (token == "-") st.push(a - b);
                else if (token == "*") st.push(a * b);
                else st.push(a / b);  // C++ 整数除法向零截断 ✅
            } else {
                st.push(stoi(token));
            }
        }
        
        return st.top();
    }
};
```

### 复杂度分析

| 指标 | 复杂度 | 说明 |
|---|---|---|
| **时间** | O(n) | 遍历一次 tokens |
| **空间** | O(n) | 栈的深度，最坏情况全是数字 |

### 🎤 面试官追问

**Q1: 中缀表达式怎么转成逆波兰表达式？**
> 用**调度场算法**（Shunting Yard Algorithm）：
> 1. 数字直接输出
> 2. 运算符与栈顶比较优先级，高则压栈，低或相等则弹出栈顶输出
> 3. 左括号压栈，右括号弹出到左括号为止
> 4. 最后弹出栈中剩余运算符

**Q2: 如果运算符有优先级且支持括号呢？**
> 上面的调度场算法已经处理。核心是用栈保存"还没找到右操作数的运算符"。

**Q3: 如果支持一元运算符（如负号）？**
> 区分方法：
> - 在 token 层面区分：`-3` 作为一个 token 是数字，`3 - 5` 的 `-` 是运算符
> - 或者引入特殊标记区分一元/二元运算符

**Q4: 为什么编译器内部常用后缀表达式？**
> 因为后缀表达式**无歧义、无括号、求值简单（只需一个栈）**，非常适合机器执行。

## 面试技巧：编译原理基础与编译器前端

### 1. 编译器整体架构

```
源代码
   ↓
┌─────────────────┐
│   编译器前端     │  ← 机器无关
│  · 词法分析      │     Token 序列
│  · 语法分析      │     AST
│  · 语义分析      │     带类型的 AST
│  · 中间代码生成  │     IR（三地址码/SSA）
└─────────────────┘
   ↓
┌─────────────────┐
│   编译器后端     │  ← 机器相关
│  · 中间代码优化  │     常量传播/死代码消除/循环优化
│  · 目标代码生成  │     指令选择/寄存器分配
│  · 目标代码优化  │     窥孔优化
└─────────────────┘
   ↓
目标代码
```

### 2. 词法分析（Lexical Analysis）

**任务**：将字符流切分成 Token 序列。

```c
// 源代码
int main() { return 42; }

// Token 序列
INT    "int"
IDENT  "main"
LPAREN "("
RPAREN ")"
LBRACE "{"
RETURN "return"
NUM    "42"
SEMI   ";"
RBRACE "}"
```

**核心工具：正则表达式 + 有限自动机（FA）**

| 自动机类型 | 确定性 | 表达能力 |
|---|---|---|
| DFA（确定有限自动机） | 确定 | 识别正则语言 |
| NFA（非确定有限自动机） | 非确定 | 识别正则语言 |

> 🔑 **面试金句**：词法分析器通常用 DFA 实现，因为 DFA 匹配效率是 O(n)，每个字符只需查一次状态转移表。

### 3. 语法分析（Syntax Analysis）

**任务**：根据文法规则将 Token 序列构建成抽象语法树（AST）。

**文法分类（乔姆斯基体系）**：

| 类型 | 名称 | 能力 | 典型用途 |
|---|---|---|---|
| Type-0 | 无限制文法 | 图灵完备 | 不可判定 |
| Type-1 | 上下文有关文法 | 线性有界 | 极少使用 |
| Type-2 | **上下文无关文法（CFG）** | 下推自动机 | **编程语言语法** ✅ |
| Type-3 | 正则文法 | 有限自动机 | 词法分析 |

**主流解析算法**：

| 算法 | 方向 | 复杂度 | 特点 |
|---|---|---|---|
| LL(1) | 自顶向下 | O(n) | 递归下降， hand-written 首选 |
| LR(1) | 自底向上 | O(n) | 自动生成（Yacc/Bison） |
| LALR(1) | 自底向上 | O(n) | LR 的简化，Bison 默认 |
| Recursive Descent | 自顶向下 | O(n) | 手写友好，现代编译器主流 |

> 🔑 **面试金句**：现代编译器（如 GCC、Clang、Rustc）的语法分析器大多是**递归下降 + Pratt 解析**（Top-Down Operator Precedence），因为手写可控、错误信息友好。

### 4. 语义分析（Semantic Analysis）

**任务**：检查 AST 的"上下文相关"规则（语法分析处理不了的部分）。

**典型检查**：
- **类型检查**：`int x = "hello";` ❌ 类型不匹配
- **作用域检查**：使用未定义的变量
- **控制流检查**：`return` 之后还有代码？是否每个分支都有返回值？

### 5. 中间表示（IR）

编译器前端的输出、后端的输入。常用形式：

| IR 类型 | 示例 | 特点 |
|---|---|---|
| AST | 抽象语法树 | 高层，保留源代码结构 |
| 三地址码 | `t1 = a + b` | 类似汇编但无限寄存器 |
| SSA | Static Single Assignment | 每个变量只赋值一次，优化友好 |
| LLVM IR | `@main() { ... }` | 工业标准，可移植 |

> 🔑 **面试金句**：LLVM IR 是编译器界的"通用货币"，前端（Clang/Swift/Rust）生成 LLVM IR，后端统一优化和生成机器码。

### 6. 高频面试连环问

**Q1: 编译型和解释型语言的区别？**
> | 编译型 | 解释型 |
> |---|---|
> | 先全部编译再执行 | 边解释边执行 |
> | C/C++/Rust/Go | Python/JS/Ruby |
> | 执行快，启动慢 | 启动快，执行慢 |
> | 编译期发现错误 | 运行期才发现错误 |
>
> 中间态：Java（编译到字节码 + JIT）、JS（解释 + JIT 编译热点代码）

**Q2: 词法分析和语法分析为什么要分成两个阶段？**
> 1. **关注点分离**：词法分析处理"拼写"，语法分析处理"结构"
> 2. **简化设计**：语法分析器不需要处理空白符、注释等琐事
> 3. **性能**：词法分析可以缓存和预读，提高效率
> 4. **错误定位**：词法错误（非法字符）和语法错误（括号不匹配）分开报告

**Q3: 什么是左递归？为什么 LL 解析器处理不了？**
> ```
> expr → expr + term   // 左递归！
> expr → term
> ```
> LL(1) 是**自顶向下**递归下降，遇到左递归会无限递归：`expr → expr → expr → ...`
>
> **解决方法**：
> - 改写文法消除左递归（`expr → term expr'`）
> - 改用 LR 解析器（自底向上，天然处理左递归）

**Q4: JIT 编译是什么？和 AOT 有什么区别？**
> | | JIT（Just-In-Time） | AOT（Ahead-Of-Time） |
> |---|---|---|
> | 时机 | 运行时将字节码编译成机器码 | 运行前编译成机器码 |
> | 代表 | Java HotSpot、V8 | C/C++、Go、Rust |
> | 优势 | 可收集运行时信息优化（内联、去虚调用） | 启动快、无编译开销、可静态分析 |
> | 劣势 | 启动慢、运行时耗CPU | 无法利用运行时信息 |

**Q5: LLVM 是什么？为什么它这么重要？**
> LLVM（Low Level Virtual Machine）是一套**模块化的编译器基础设施**：
> - **前端**：Clang（C/C++）、Rustc、Swift → 生成 LLVM IR
> - **优化层**：一系列 Pass（常量传播、循环展开、死代码消除）
> - **后端**：生成 x86/ARM/RISC-V 机器码
>
> 价值：**写一个新语言只需要写前端，自动获得世界级优化和后端支持。**

**Q6: 编译原理知识在 AI 工程中有哪些应用？**
> 1. **深度学习编译器**：TVM、MLIR、XLA 都用编译器技术优化模型推理
> 2. **算子融合**：类似编译器的循环融合，将多个算子合并减少访存
> 3. **量化与图优化**：常量传播、死代码消除等经典编译优化直接复用
> 4. **自定义算子**：用 TVM/MLIR 写 DSL 描述算子，自动生成高效代码
> 5. **模型部署**：ONNX 作为 IR，各框架前端转换，后端针对硬件优化

## 📚 今日速记卡

**逆波兰表达式求值**：
```
数字入栈，运算符出栈两个数运算后再入栈
注意：先弹出的是右操作数！
时间 O(n)，空间 O(n)
```

**编译器三阶段**：
```
词法分析 → Token
语法分析 → AST
语义分析 → 带类型/作用域的 AST
```

**CFG vs 正则文法**：
```
正则文法  → 有限自动机  → 词法分析
CFG       → 下推自动机  → 语法分析
```

**LL vs LR**：
```
LL：自顶向下，递归下降，手写友好
LR：自底向上，自动生成，处理左递归
```
